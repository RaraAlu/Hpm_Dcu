# CAN3 硬件重发六十秒实板验证

2026-11-22。**T6 的 500 Hz、60 秒项目通过：30,000/30,000 笔全零 MIT 均在下一拍给出有效反馈。** 本轮只跑一次，未开始 30 分钟测试。

## 实测配置

生产 Release，Profile rev 6，仅 CAN3 接 HRA55H-100（`0x02`），动力隔离、保留通信供电。使用生产 784/1072 B PDO 单 LRW、DC Sync0 500 Hz、相位 +375 µs、350 µs 事务截止；未发使能、模式切换或 `0x17`，无应用补发。镜像 SHA-256 为 `5128ac4432d48ddd243e756924911b047677b746cf759dce099cb7ef422581d6`；[烧录与保留区审计](../../artifacts/target/20261122T021158.110262Z/)通过。

暖机前读回 `CCCR=0x700`（DAR=0，硬件重发开启）、`NBTP=0x26003A13`、`DBTP=0x00800A33`、`TDCR=0x00000D0C`（TDCO/TDCF=13/12），确认与[上次 CAN3 TDCO 对照](2026-11-20-生产全零MIT六十秒首轮实板验证.md#can3-tdco-单变量对照)相比位时序不变。启动前无待发、提交或首错记录，RK 在 PREOP 校验 Profile rev 6、槽位和 CAN ID。

## 结果与首错

| 项目 | 实测 |
| --- | --- |
| 暖机与计分 | 64 拍连续零输出暖机通过。30,000 笔全零 MIT，30,000 笔 N+1 有效，漏拍、错配、未确认均为 0；最后用零输出 LRW 读回。 |
| EtherCAT | 30,001 个计分 LRW 均为单帧、OP、WKC=3；有效反馈年龄均为 1 ms，无电机或网关故障。HPM 计数 30,000 次提交、30,000 次成功 TX、RX 溢出 0。 |
| 首错锁存 | CAN3 IRQ 捕获 `IR=0x10010000`、`PSR=0x001D341F` 和 `ECR=0x00010008`，仍为数据相位 Bit1Error（DLEC=4、TEC=8）。唯一令牌 `0x6388`（第 25,480 笔），slot 7：`TXBRP=0x80`、`TXBTO=0x7F`、`TXBCF=0`，首错后仍在途。 |
| 首错后恢复 | 第 25,480 笔约在计分 50.956 s，对应 PDO 25934；下一帧 25935 读到序号 25934 和新发布，有效位 `0x37`、无故障。说明至少这笔已记录的发送错误被硬件重发恢复，且仍满足 N+1；不能据此给出精确重发次数。 |
| 时序 | 30,000 个标称 2 ms 周期，RK 从首次发送到最终读回为 59.998379 s；RK 发送间隔相对 2 ms 最大绝对偏差 0.610 µs，不是 Sync0 边沿抖动。HPM 发布起始最大迟延 61 µs、发布执行最大 277 µs，距本地 +1750 µs 截止保守余量不少于 262 µs；这不是逐拍实测的最小余量。 |
| 收尾 | RK Idle/Inactive、HPM PREOP、CAN3 无待发；重发版镜像与首错快照留板。 |

结论：这一轮证明硬件重发能在当前 500 Hz 生产窗口内恢复至少一次 Bit1Error，不能证明底层位错误已消除，也不能外推到 30 分钟或多设备。原始 [RK 逐拍 CSV](../../artifacts/target/t6-production-can3-retry-20261122-FZ0RU7/rk-t6.csv)和 [HPM 收尾读回](../../artifacts/target/t6-production-can3-retry-20261122-FZ0RU7/hpm-after-t6.log)保留。
