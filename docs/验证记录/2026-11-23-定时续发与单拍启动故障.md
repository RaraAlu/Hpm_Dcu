# 定时续发与单拍启动故障

生产 ENCOS MIT 的同路续发改为 MCAN TX EOF 加 GPTMR 单次比较，不新增线程。SM2 锁存、首发触发条件、同路 100 µs 最小间隔、反馈和 SM3 截止均未修改。

## 实板结果

RK 构建目录启动同一 `DriverModule`，Profile 与 RK 调度文件逐字节一致。PREOP 中回读 SM2 的 9 个映射和 101 个字段、SM3 的 9 个映射和 122 个字段，逐项与本次生成的 PDO 契约一致：216 B / 256 B。

| 阶段 | 观测 |
| --- | --- |
| 空载 | 68 个样本的 SM2 比 Sync0 早 211～317 µs；五个已登记轴控制 TX 均未增加。 |
| 单拍启动 | 驱动在启动阶段报 `HPM slave left OP`，尚未软件武装。四个目标轴 TX 增量均为 0，CAN3 对照轴也为 0。没有 MIT 命令进入首拍时标。 |
| HPM 快照 | epoch 31、普通 PDO 序号 2046。以该拍 Sync0 为零，SM2 就绪 −250 µs，worker 本次进入 +244 µs，普通 SM3 发布截止 +1750 µs，故障处理 +1807 µs。故障位 `0x04` 为 `PDO_PIPELINE_TX_LATE`；没有 `CAN_FEEDBACK_MISSING`。 |
| 未验证项 | 本次无四帧 TX EOF、无 N+1 本拍反馈、无节拍抖动样本。未重试，未跑 60 秒。收尾 HPM 运行于 PREOP，RK Idle。 |

快照同时保留了 `published_epoch=31` 和故障位。这不能证明 ESC 真写晚了 57 µs：+1807 是处理故障的时间，不是写入时间。空载走 `PDO_InputMapping()` 后单独登记发布的路径；区别“ESC 写晚”与“写完后尚未登记时 watchdog 判晚”，需观测普通 PDO 的写入、登记与 watchdog 首次置位时标。这次抓取没有这三个时标。

宿主回归 432 项，427 通过、5 项缺 Unicorn 跳过；普通及带时标五轴 Release 均构建通过。底层用生产 MCAN 传输代码和寄存器替身验证无 RX、无 worker 的四帧续发、双总线、计数回绕、取消、换拍、丢 EOF 与过期。不以离线结果代替硬件验收。

首次复位前备份与复位后的启动日志不同，保护入口在写镜像前中止。独立回读证实 SII 未变；日志从 351 按扇区轮转到 352，另一扇区未动。之后按标准受保护入口备份并校验镜像及保留区，未回写旧日志。上板 ELF SHA-256：`d73d48bbef0a10a08d7aaad2d31adf840cf07b08fc392a4d1ec41c6af7631e0f`。
