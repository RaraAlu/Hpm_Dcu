| 项目 | 观测 |

| 计分 | 计划 30,000 条。RK 串行发送 2,531 笔带命令的 PDO，2,529 笔在对应 N+1 拍成功，1 笔明确失败，1 笔和失败读回同帧发送但未在 HPM 执行；其余 27,469 笔未发 PDO。 |

| HPM CAN | 共提交 2,530 笔，2,529 笔报告成功 TX，软件 RX 溢出为 0。停发后首份快照 `ECR=0x00010008`（TEC=8、REC=0、错误日志计数 1），`PSR=0x001c340f`（DLEC=4，Bit1Error；发送隐性位而监测到显性位）。 |
| N+1：2986 | 单 LRW、OP、WKC=3，`AcceptedCycleSeq=2985`、发布序号前进、`BoardStatus=0x23`、`ValidFlags=0`。HPM 无 PDO 周期故障位。此 LRW 携带的后续命令未触发 CAN；RK 未再排有效命令。 |
| 收尾 | 只有零输出收尾，RK Idle/Inactive、HPM PREOP；没有重新进 OP。 |

全部 2,531 个计分窗口 LRW 的单帧/OP/WKC 检查通过。成功反馈年龄均为 1 ms；RK 发送间隔相对 2 ms 的最大绝对偏差为 0.547 µs（不是 Sync0 边沿抖动）。成功样本从 N 的发送调用到 N+1 收取完成为 2.553–2.555 ms；证明下一帧带回，不等于 RK 端到端小于 2 ms。

HPM 正常生产构建未开启逐帧相位追踪。周期统计给出的发布开始最大迟延 33 µs、发布执行最大 220 µs，保守相加得到距 HPM 本地 +1750 µs 截止不少于 347 µs（+1150 µs 构建窗口开启）；这不是实测的最小 SM3 到 RK 读帧余量，也不是首错拍的 CAN 段时序。

**结论**：首错是已确认的 CAN FD 数据相位错误，不是 EtherCAT 漏帧或已证实的 SM3 超期；错误的物理原因尚未定位。下一步优先查 CAN 数据相位与物理链路，不放宽 N+1 判据或取消首错停发。

## 停发后位时序复核

仅在 RK Idle、HPM PREOP 读回 MCAN1，未复位、未写配置、未发帧；`TXBRP=0`，累计提交/成功 TX 仍为 2,530/2,529。原始读回见同一证据目录的 `can1-timing-readback.log`。

- 本次生产镜像 `NBTP=0x26003A13`、`DBTP=0x00800A33`、`TDCR=0x00000C0C`，和[上一轮独立诊断首错](../../artifacts/target/cih408-mit-once-dc-20261119/CAN首次故障快照.md)一致。按 80 MHz 解码为 1/5 Mbit/s，常规采样点均 75%；没看到位率或 TDC 配置漂移。
- TDC 已启用，`TDCO=TDCF=12`；按本板 SDK 寄存器定义，只有 `TDCF > TDCO` 才开启早沿过滤，因此当前没有开启该过滤。首错快照的 `TDCV=28 mtq` 是次采样点位置（350 ns），不是往返延迟；由寄存器值减去 offset 得 16 mtq（200 ns），仅为控制器快照的推算，不是实测波形。
- 失败帧的滚动计数为 `0xe1`。按生产编码规则和逐拍 CSV 对齐，先前 PDO 序号 681、937、1193、1449、1705、1961、2217、2473、2729 的同计数全零命令均在 N+1 成功，排除了该计数值每次必现的故障。不能排除某些位形更容易触发偶发错误。

优先现场确认总线两端终端和线束；如有条件，用差分波形对照 TXD/RXD 在数据段的实际边沿，区分反射、对端主动错误帧与次采样点偏差。没有波形时，从一项物理变量的对照开始（如已知正确端接的短线），不要同时改线束、TDC 和速率。当前寄存器快照还不足以改 TDC。

## 生产驱动首错取证

补齐生产驱动的片内证据，不改变速率、TDC、禁止重传或应用停发判据。每个 CAN 通道每次启动锁存首次观察到的协议错误，记录 HPM 微秒时标、来源、`IR/PSR/ECR`、位时序、FIFO 与 TX 状态，以及每个 TX 槽当时由软件持有的令牌。快照不是电气错误边沿的捕获；同一时刻有多个令牌时，不能仅凭快照认定哪个槽在线上出错。

- 取证早于 MCAN 中断清除、TX 事件回收或主动取消。常规状态轮询也保留读清之前读到的错误码，不能等事后再读 `PSR` 还原首错。
- 快照在 RAM 中，后续错误不覆盖，普通 PDO 停止或退出 OP 不清除。复测停止后、复位前，使用当次 ELF 定位 `s_first_fault[1]`，停核读出。当前 Release 每项 128 字节，`valid=1` 才是完整快照；不要沿用旧 ELF 的 RAM 地址。
- 该版上线前已通过 Debug/Release 构建和镜像保护检查，宿主覆盖中断清除、轮询读清、TX 令牌回收和取消路径。实板取证见下节；此变更不针对 Bit1Error 根因。
