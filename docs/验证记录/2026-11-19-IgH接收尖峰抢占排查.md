# IgH 接收尖峰抢占排查

沿用 [IgH 接收分段计时](2026-11-19-IgH接收分段计时.md) 的原路径，CPU 4、SCHED_FIFO 80、锁内存，周期 1 ms，不提前唤醒、不后移 DC 时间。保持板上固件、Profile 和 PDO 布局，不接 CAN。IgH 使用原生 `ec_stmmac`，从原有 `ecrt_master_receive()` 路径轮询驱动，不调整中断亲和性。

运行内核 `6.1.141 PREEMPT_RT` 未启用 `CONFIG_FTRACE`、`CONFIG_PERF_EVENTS`、`CONFIG_KPROBES` 或 `CONFIG_IRQ_TIME_ACCOUNTING`，无 tracefs，不能获得每个接收调用内的 IRQ 事件或驱动函数用时。先在探针以 `getrusage(RUSAGE_THREAD)` 在每个被计时的接收前记录切换计数，仅当 `ecrt_master_receive()` 耗时达到 8 µs，才在读取回显后再次记录。两次快照均在被计时的调用之外；计数差为零可以排除该窗口内的线程切换，不能排除进入 IRQ 后直接返回同一线程。

`/proc/interrupts` 和 `/proc/softirqs` 只在整轮前后读取，不在实时循环里采集或打印。它们只能说明 CPU 4 上的整轮活动，不用于给单次尖峰归因。

| 指标 | 60 秒实测 |
| --- | --- |
| 回显完整性 | 60000/60000，漏拍、重复、乱序、异常 AL/WKC 均为 0，每条均在第 3 拍读回 |
| `ecrt_master_receive()` | 中位 5.250 µs，P99.9 7.875 µs，最大 9.916 µs |
| 接收耗时 ≥ 8 µs | 50 次全部覆盖；自愿和非自愿线程切换均为 0 |
| 全回环完成间隔 | P99.9 绝对偏差 6.828 µs，最大 12.369 µs，3958/59999 个间隔超过 ±1 µs |

最慢的接收出现在 `sent=30969`、`ack=30966`，耗时 9.916 µs，无线程切换。新增检测在接收调用之前的区段中位数增加约 0.583 µs，接收调用自身的中位耗时未变。CPU 4 有计时器和 IPI 活动，诊断窗口内 `arch_timer` 增加 76815、IRQ work IPI 增加 795；这些没有逐拍时间戳。整轮未重现此前 37 µs 级完成间隔极值。

因此可排除本轮捕获的 50 个接收慢样本由其他线程切入或本线程阻塞切出造成；不能区分硬 IRQ、同步网卡轮询、IgH 内核收包处理等在线程内发生的耗时。进一步归因需要在同一时钟下将 CPU 4 的 IRQ 进入/退出与 `ec_device_poll` / 驱动轮询窗口对齐。本轮没有换内核、重载驱动或烧录。最后从站回到 PREOP，IgH 为 Idle，Profile 前后读回一致。

