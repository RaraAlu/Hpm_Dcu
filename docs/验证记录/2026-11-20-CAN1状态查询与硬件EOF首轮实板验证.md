# CAN1 状态查询与硬件 EOF 首轮实板验证

2026-11-20，用户确认 HPM 台架的 CAN1 接 HRA55H-100（节点 `0x02`），保留电机通信供电、隔离动力。仅运行当前生产 Release 和 Profile 第 2 版，RK 主站保持 Idle，不进入 OP，不发使能或 MIT。镜像 SHA-256 为 `5981caeadf68f26f81415879803e9aac307dcd0892aaf0aed56edd534990109f`。

| 检查 | 实测 |
| --- | --- |
| 受保护下载 | 复位前备份路径在写入前阻止了日志变化；独立回读证实 SII 不变，日志只从 181 正常追加到 182。随后标准保护流程重新备份，在镜像写入前后验证两保留区，并校验 ELF。运行后 SII 仍逐字节相同；以写前日志为基准只追加 184、185 两条合法记录。 |
| MCAN1 初始化 | 活动掩码 `0x2`，MCAN1 `CCCR=0x740`（FD、BRS、DAR、TSU），`TSCFG=0x1`（TSU 开启、EOF 捕获、内部时基、32 位），`TSCC=0x2`。 |
| 状态请求与 TX EOF | 约 5 秒窗口内提交 50 笔 `0x002#17`。Message RAM 中最近 8 个 TX 槽均为该命令；`TXBTO=0xff`，对应软件槽保有有效 TX EOF。`ECR=0`。 |
| RX 与关联 | 同一窗口内 RX FIFO 空，CAN1 软件 RX 队列读写索引均为 0，无软件丢帧。没有观察到 `0x80` 或可核对的 RX EOF，未命中接收断点。不能判因，也不能报收发关联通过。 |
| 收尾 | RK 主站仍为 Idle/Inactive，HPM 状态为 PREOP；进度 SDO 未在读取时限内返回，不据此报 READY。终检后 HPM 保持暂停，未写回任何保留区。 |

原始证据位于 `artifacts/target/20261120T092045.042839Z/`，含 `openocd.log`、`readonly-can1.log`、`can1-detail.log`、MCAN 队列与 Message RAM、写前和运行后保留区。首次阻止写入与复位后独立回读位于 `artifacts/target/20261120T091940.520093Z/`。

**结论**：生产镜像的 CAN1 初始化和 TX EOF 捕获已实板确认；先查明该接线与供电条件下节点不回 `0x17` 的原因，复验 RX 之前不进入运动试验。

## 同供电条件下的独立只读对照

使用独立 RAM 探针直查 MCAN1，不经过 EtherCAT 或生产网关，FD+BRS 1/5 Mbit/s，关闭自动重传。三次各只提交一帧，均完成发送，`ECR=0`。未更改电机供电、状态或配置，未烧录 Flash。

| 查询 | 观察结果 |
| --- | --- |
| ID 查询 `0x000`，8 字节全零 | 收到 `0x000` 的 `80 02`，确认节点 `0x02` 在线。 |
| 状态 `0x002#17` | 发送完成后未收到任何 CAN 回包，也没有格式不匹配的回包。 |
| 版本 `0x402#01` | 收到 `0x402` 的 `81 37 03 1E 06`，确认实际版本 `37.03.1E.06`。 |

结论：CAN1 双向通信和身份查询正常，而独立路径也复现了状态查询无回包。现象不依赖生产网关的 EOF 筛选或 EtherCAT；仍不能从这组结果判定该版本在当前供电条件下的状态查询前提。不能用 ID 或版本应答代替状态反馈或放行运动。HPM 回到 Flash 复位暂停，RK 主站保持 Idle。

原始证据：`artifacts/target/bjcx-can1-readonly-check-20261120-ZsUk27/`。

## 动力隔离下的单笔 mode 2 尝试

另获单次使能、MIT 和收尾失能授权。动力保持隔离，主站 Idle；使用独立 RAM 探针，不进 OP、不刷 Flash。MCAN1 FD+BRS 1/5 Mbit/s，DAR 和 TSU EOF 均开启。

- 对节点 `0x02` 单发 `10 01`，发送完成且捕获 TX EOF，无 CAN 错误。软件读到 1 帧，但未获得可用的 RX EOF，保护门槛未通过，**未发送 MIT**。
- 随后单发 `10 00`，发送完成且捕获 TX EOF，无 CAN 错误。软件同样读到 1 帧，但未能按硬件 EOF 关联。
- 复位暂停后独立回读 MCAN Message RAM，两个标准 FD+BRS RX 元素的 ID 都是 `0x02`，载荷依次为 `90 01`、`90 00`。两帧 RX 头按当前 SDK 布局解析均没有捕获标志。它们是原始应答证据，不当作通过 EOF 门槛或物理失能验收。

**结论**：收到使能和失能的原始应答，但缺可核对的 RX EOF，未尝试 MIT，不能判定能否进入 mode 2。HPM 已恢复到 Flash 复位暂停，未重试。证据：`artifacts/target/bjcx-can1-mode2-once-20261120-lcHO24/`。

## RX EOF 缺失的只读对照

动力继续隔离，主站保持 Idle。独立 RAM 探针在 CAN1 单发三个对照版本查询，每轮只发一笔 `0x402#01`，都收到 `81 37 03 1E 06`，CAN 错误计数为 0。

| 标准帧过滤器 | 原始 RX 字 1 | TSU 有效槽 | EOF 结果 |
| --- | --- | --- | --- |
| 精确匹配，`sync_message=0` | `0x00350000` | 无 | TX 有，RX 无 |
| 精确匹配，`sync_message=1` | `0x00350011` | 槽 1 | TX/RX 均有效，RX 晚 10058 ticks |
| 全标准 ID 匹配，`sync_message=1` | `0x00350011` | 槽 1 | 同生产修正配置，RX 晚 10058 ticks |

根因是原全局接收路径并未给标准帧请求 TSU 时间戳，不是这两条应答没有进 FIFO，也不需要变更 SDK 解析。生产代码已让单发通道的标准帧通过带 `sync_message=1` 的过滤器，保持 FIFO0 路由及原 EOF 门槛。宿主回归和 Debug/Release 镜像检查通过；实板验证的是独立探针，不代表修正后的生产镜像已下载，也不代表 `0x17` 无回包或 mode 2 已解决。未发送使能、MIT 或失能，未烧录 Flash，结束后 HPM 复位暂停。

证据：`artifacts/target/bjcx-can1-rx-eof-ab-20261120-Huz2st/`。

## 只验单笔 MIT 和有效回包

按用户确认的判据，只用独立 RAM 探针在 CAN1 向 `0x02` 单发一笔全零 MIT（`0x11` 加 15 字节零），不发使能、`0x17` 或重试。动力保持隔离，主站 Idle。

**通过**：1 次提交、1 次发送完成、1 帧同 ID 标准 FD+BRS 回复，原始 DLC 10（16 字节），载荷 `80 20 00 41 46 37 20 80 00 00 00 00 00 4D 4D 60`。TX EOF 为 421984、RX EOF 为 435401，相差 13417 TSU ticks，CAN 错误计数为 0。模式和动作不作为本轮判据。

这只确认独立 CAN 往返，不代表生产 PDO 或 N+1 验收。未接回动力、未刷 Flash，结束后 HPM 复位暂停。证据：`artifacts/target/bjcx-can1-mit-reply-20261120-TrXRoo/`。
