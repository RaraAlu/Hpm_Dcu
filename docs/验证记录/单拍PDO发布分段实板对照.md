# 单拍 PDO 发布分段实板对照

沿用 [单拍 PDO 时序预算](单拍PDO时序预算与写入优化.md)。同一块 HPM 和同一独立 IgH 探针，CPU6、FIFO 80、锁内存、1 kHz。Sync0/SM3 发起/主站收集标称相位仍为 +120/+885/+975 µs，600 µs 构建预算和相对 Sync0 +750 µs 的发布截止未动。没有接 CAN、下发 Profile、调整 PDO 布局或切换生产 DriverModule。两个诊断镜像使用同一套计时，先试四字展开，再试原单字循环；每版取得 8 条 HPM 发布轨迹，严格验收各只有 1 条。

| 1072 字节 TxPDO 写入计时 | 原单字循环 | 四字展开 |
| --- | ---: | ---: |
| SSC 映射调用至返回，最小 / 中位 / 最大 | 148 / 148 / 152 µs | 143 / 149 / 151 µs |
| 沿用旧诊断口径：打包结束至 ESC 写完，中位 / 最大 | 152 / 156 µs | 153 / 160 µs |

中位数均未改善，两组样本范围重叠。这轮没有测到可重复的节省，不能由循环指令减少换算省下的微秒，也不能据小样本判定性能退化。

发布前的等待从现有 +150 µs 发布开门点起算。旧镜像只有 182 µs 的最大值，无法追溯该条的组成。带新计时的两组各取最慢一条，按同一拍拆分如下：

| 分段（HPM 本地壁钟时间） | 原单字循环最慢一拍 | 四字展开最慢一拍 |
| --- | ---: | ---: |
| 开门到开始发布 | 214 µs | 204 µs |
| 落在上述区间内的解码 + 命令处理 | 38 + 123 µs | 38 + 115 µs |
| 到命令完成前的其余等待/开销 | 49 µs | 47 µs |
| 命令完成到开始发布 | 4 µs | 4 µs |

在两组最慢拍，发布前延迟主要位于命令路径，不是命令完成后才调度慢。时间戳量的是调用段的壁钟时间，可能包含抢占，不等同于纯 CPU 执行时间；其余时间也包含 SSC 服务与调用开销，不能全归为 RTOS 唤醒。连续发帧时，下一帧 SM2 事件在锁存所用 Sync0 前约 16–19 µs 到达，下一帧槽提交在该 Sync0 后约 122–125 µs；这是与任务接手延迟重叠的已观测区间，不表示已经拆清 IRQ 内的每一项。

两版首条严格命令均失败：四字版 4858 在 +994.901 µs 收到 4857，原版 4857 在 +994.534 µs 收到 4856；WKC 双向均为 1、AL 均为 OP。四字版 4858 的 RxPDO 约 +242 µs 就绪，错过约 +121 µs 的首个 Sync0；在约 +1121 µs 锁存，随后发布约 +1434 µs。此次不据预热样本宣称单拍通过。

原始记录分别在 `artifacts/target/pdo-tx-stages-20261119/`、`artifacts/target/pdo-tx-linear-20261119/`。烧录前后验证 SII 一致，启动日志顺序追加 81 至 84。主站已退回 Idle，从站退 PREOP 后由 J-Link 暂停，板上保留原单字循环的对照镜像。
