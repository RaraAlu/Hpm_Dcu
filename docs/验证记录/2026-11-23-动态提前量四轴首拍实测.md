# 动态提前量四轴首拍实测

按修订 10 的五轴台架 Profile，由 RK 构建目录的启动脚本运行生产 `driver_module`。只对 CAN2 的四台 7216 请求全零 MIT，未改变同路 TX EOF 后至少 100 µs 的配置。Python 只提交命令、检查生产线程结果和读回计数。顺序为空载、首拍，首拍成功才进入 60 秒。

## 结果

- 空载时发现 RK 在关闭 IgH 后记录的校准统计已清零；调整为关闭前取值，重新构建 RK 生产包。两次空载四轴 TX 增量均为 0，没有为此重刷 HPM。
- 空载复核：RK 完成 1 个校准窗口，唤醒提前量由 150 µs 调至 75 µs。HPM 记录 68 次 SM2 就绪，相对 Sync0 提前 204 至 318 µs。
- 首拍：`sent=1 matched=0 missed=0`。这里 `missed` 是 RK 调度跳拍数，不是 N+1 反馈漏拍数。N+1 四轴完整反馈漏了 1 拍。CAN2 的 ID 1、2、3、4 发送计数各从 0 变为 1，CAN3 仍为 0。
- 首拍生产会话也完成了 1 个校准窗口，唤醒提前量为 75 µs。该会话关联了 1 次准备迟到，最小余量 −9.264 µs；这是会话统计，不能归因到故障命令的 SM2。
- 没有重发、没有启动 60 秒段。测后 HPM 为 PREOP，RK 主站 Idle；从空载到结束，HPM boot ID 为 1468878815232，拓扑代数为 0。

## 首拍时间线

HPM 保留 RAM 中，命令序号 1187、epoch 67。以这拍的 Sync0 为零点，以下均为 HPM 时钟：

| 事件 | 相对时间 |
| --- | ---: |
| SM2 完整就绪 | −252 µs |
| 周期工作开始 | +46 µs |
| 命令处理完成（不是最后一帧 CAN TX EOF） | +507 µs |
| 四轴反馈匹配截止 | +1300 µs |
| 记录反馈缺失故障，缺失掩码 `0x10`，仅 ID 4 | +1307 µs |
| 原定 SM3 提交截止；实际未开始打包 | +1600 µs |

流水线最后成功发布的是 epoch 66；67 的反馈收齐、打包和 ESC 提交时标均为零，故障位为 `CAN_FEEDBACK_MISSING`。这定位到 ID 4 的本拍反馈未在截止前通过匹配，而不是首拍 SM2 未到、ID 4 未提交或 SM3 大包写慢。本镜像的故障现场没有保留可用于区分 ID 4 未回、晚回、晚处理或校验不通过的独立 RX EOF 记录。仅发出一拍，也不能测 MIT 相邻节拍抖动。

## J-Link 故障后补读

未重发 MIT。先用系统总线读取流水线，再在 PREOP 短暂停核，通过 CPU 的 program buffer 读取一致快照并立即恢复。接收环在可缓存 SRAM，系统总线读出的混杂旧样本不用于本拍定时。CPU 侧发布记录与保留的故障序号 1187、epoch 67 相符；周期网关保留的截止时刻为 330763845 µs，即该拍 Sync0 +1300 µs。

| CAN2 ID | 周期命令 TX EOF（控制器 tick） | 距上一帧 TX EOF |
| --- | ---: | ---: |
| 1 | 1728066476 | 不适用 |
| 2 | 1728126831 | 301.775 µs |
| 3 | 1728167064 | 201.165 µs |
| 4 | 1728211656 | 222.960 µs |

四个 EOF 有效位均为 1。控制器的 100 µs 间隔配置对应 20000 tick；从第一帧帧尾到第四帧帧尾为 725.900 µs。这是帧尾到帧尾，不是总线空闲时间，也不是 Sync0 到第四帧的时间。代码按 worker **处理反馈时刻**检查截止，不是仅按硬件 RX EOF 判定；若帧已到但尚未处理，也可能报缺。

CPU 一致快照中的 32 个 RX 槽已全是故障后的位置、速度和电流查询应答（报文以 `a0 01/02/03` 开头），不再是故障拍的 MIT 反馈。不能据此判定 ID 4 未回、晚回或解码失败。下轮最小观测点是保留 ID 4 的 RX EOF、出队时间和匹配拒绝原因；不能用当前 PREOP 查询应答代替。恢复后 boot ID 不变，四个命令计数仍各为 1，RK 主站空闲。

## 带时标的单拍复现

台架保持动力隔离。使用同一五轴生产配置，只启用首拍 RAM 记录，新增 CAN2 ID 4 的硬件时钟对照、出队时刻和匹配判定。RK 生产包未替换，未使用测试线程；采样期间没有停核或断点。首次刷写事务在擦写前因复位追加启动日志而终止，随后按标准事务复位后备份并校验镜像、EEPROM 和启动日志。上板镜像 SHA-256 为 `e8f20434cad28ae4835b21976b08270924d64c04202af6af697661da2bc104f4`。

空载四轴 TX 均为 0，SM2 提前 211 至 317 µs 就绪，共 68 个样本。随后只发一拍：命令 1266，epoch 68，四轴 TX 各加 1，CAN3 不变。RK 的 N+1 收到的仍是 1265，四轴新反馈掩码为 0。没有进入 60 秒测试。

以本拍 Sync0 为零点。CAN EOF 来自同一控制器，用 ID 4 中断内对 ATB 的两侧 GPTMR 读数换算：ATB 为 163996358 tick，采样在 +1282 至 +1286 µs 的两个整数微秒读数之间，保守计入 1 µs 量化；每 200 tick 为 1 µs。

| 事件 | 时间（µs） |
| --- | ---: |
| SM2 完整就绪；周期 worker 开始 | −251；+69 |
| ID 1 / 2 / 3 / 4 命令硬件 TX EOF | +591～596 / +811～816 / +1023～1028 / +1211～1216（近似） |
| ID 4 回包硬件 RX EOF | +1272～1277；距该轴 TX EOF 60.700 |
| CAN RX 中断记录 ID 4，有效 EOF、DLC 8、首字节 0x20 | +1291 |
| 接收截止；watchdog 本次检查采时；记录首次故障位 | +1300；+1306；+1310 |
| 周期 worker 处理 `CAN_FEEDBACK_MISSING`，缺失掩码 0x10 | +1339 |
| 同一 RX EOF tick 的 ID 4 帧出队（已退出本拍匹配路径） | +2034 |

结论：**该回包线上的帧尾比截止早约 23～28 µs，但到截止时尚未出队。** 本拍 ID 1～3 的周期匹配均成功。ID 4 根本没有进入周期匹配判定，不是该判定拒绝了帧内容；普通路径在故障后消费这帧不能补回本拍。定时中断先查软件缺失掩码、后通知 worker，worker 在待发布路径也先查故障、后处理 CAN。SM3 未开始打包。这是带时标复现拍的实证，不能将这拍的绝对耗时当作未插桩固件的基准，也不能据此断言载荷中所有字段已通过解码。

本次未修改生产超时策略、CAN 间隔或 SM3 截止。测后 HPM 为 PREOP，RK Idle，板上保留时标固件。
