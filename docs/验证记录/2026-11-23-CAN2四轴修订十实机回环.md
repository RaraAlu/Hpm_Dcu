# CAN2 四轴修订十实机回环

结论：生产路径全零 MIT 单拍通过。两轮 500 Hz 长测均在第一个 N+1 核对时退出，均未跑满 60 秒。**控制帧已发出；问题不是第 3、4 轴没发，也不是反馈数值超限。**

| 测试 | 命令拍 → 读回拍 | 每轴硬件 TX 完成计数 | N+1 回显 / 发布号 | 结果 |
| --- | --- | --- | --- | --- |
| 单拍 | 273 → 274 | 0 → 1 | 273 / 46331 | 四轴逐拍 TX、新反馈均为 1 |
| 首轮长测 | 329 → 330 | 1 → 3 | 329 / 164740 | 四轴逐拍证据均为 -1 |
| PREOP 重登后的长测 | 303 → 304 | 3 → 5 | 303 / 684178 | 四轴逐拍证据仍均为 -1 |

- 长测的读回 LRW 同时携带下一拍命令，所以每轮实际有 **2 个命令 PDO、每轴 2 次硬件 TX 完成**，不是只发了 1 拍。每轮各有 29,998 个计划命令 PDO 未发。最后随读回携带的命令没有独立计分的 N+1 窗口。三段合计 CAN2 各轴 5 次，CAN3 ID 2 始终为 0。
- 单拍四轴有效 TX EOF 的相邻差为 272.775、212.175、196.960 µs。读回间隔门限 20,000 tick（200 tick/µs）；按本次标准 ID、8 B FD+BRS、1/5 Mbit/s 的成功帧上界 80 µs，EOF 至下一成功帧 SOF 下界分别为 **192.775、132.175、116.960 µs**。这是首拍硬件时标推得的下界，不是 SOF 直接采样，也不是长测全程测量。
- 两轮长测的首个 N+1 均是 330 B 单帧 LRW、OP、WKC=3，`AcceptedCycleSeq` 等于所期待的命令序号，`PublishSeq` 比上一幅 SM3 增 1。四轴均为模式 4、状态 `0x81f`、有效位 `0x3f`，电机和桥接故障为 0。两次的四轴反馈年龄依次为 `1/1/0/0` 和 `0/0/0/0` ms。不是旧 SM3，但这些字段单独不能证明逐轴 CAN 回包归属于该命令。
- 直接判停原因是 RK 未取得四个槽的有效旁带请求掩码：在 LRW 和序号均正确时，`can_tx_complete` 和 `n1_fresh` 都为 `-1`，含义是未知，不是 0。受测探针没有保存当拍 `0x6400` 全部 48 字节，无法再区分 `T1R2` 或 `E01` 标识未识别，还是请求掩码未包含目标槽；也不能用整轮 TX 计数替代逐拍收包证据。
- 首轮长测前单拍已退 OP。第二轮单独在 PREOP 显式复位旁带、提交同一修订的 41 B 档 1 请求、重写并核对原 assignment；请求状态回读为 Requested。未改映射内容、配额、发送权、固件或限值。**Requested 不是 OP 当拍已经 Active 的证据**。退 OP 后旁带状态 5 符合现有会话逻辑，不能倒推计分帧时的状态。
- 三次运行在已输出计分结果后，探针立即退活并读 SDO 时均报 I/O 错误。上表的硬件计数取自主站释放后、同一 boot ID / 拓扑代数下的独立 SDO 回读。这个错误不在周期路径上，不是长测判停原因。

**环境与收尾：** HPM 五轴台架 Profile 1/rev 10，SM2 216 B、SM3 256 B；RK 管理核对非重叠域 472 B，测试探针使用 256 B 重叠域。两路零透传配额均未开放，未启动或替换 DriverModule。末态 HPM PREOP、AL 状态码 0、RK 主站 Idle / inactive，boot ID `0x0000014400000000`，拓扑代数 0。
