# CAN2 四轴紧凑布局：单拍通过，六十秒在首个反馈窗口停止

使用板上已有的五轴生产 Release，未刷写、未重启、未修改 Profile、未启动 DriverModule。RK 管理工具只读核对 boot ID `0x0000013f00000000`、拓扑代数 1、通道掩码 `0x0c`、轴掩码 `0x0023c000`。SM2/SM3 为 216/256 B；管理工具登记非重叠域为 472 B。周期探针另建 256 B 重叠域，单 LRW 的收发偏移均为零；实际计分帧为 330 B、OP、WKC=3。

[RK 生产 PDO 探针](../../tests/host/ethercat_data/production_mit_endurance_probe.cpp)在 RK 上按同一固件导出的头文件编译，绑定隔离核 CPU6，使用普通调度、锁内存、2 ms 周期、Sync0 相移 +375 µs。两段均在确认连续零输出暖机、就绪和 ARM 后，只向 CAN2 ID 1、2、3、4 发位置、速度、Kp、Kd、前馈全零的 MIT；CAN3 的 ID 2 保留映射，不下发控制。

## 单拍

| RK 帧 | 当帧命令 | AcceptedCycleSeq | PublishSeq | 四轴反馈年龄（ms，按 ID 顺序） |
| --- | --- | ---: | ---: | --- |
| 273 | 四轴各一次 | 272 | 2297504 | 142、141、140、140（之前的查询值） |
| 274 | 撤掉命令，只收结果 | **273** | **2297505** | **1、0、0、0** |

274 拍四轴均为模式 4，状态 `0x81f`、有效位 `0x3f`，电机和网关故障为零。控制帧完成计数分别从 0 变成 1，CAN3 保持 0。

CAN2 回读的间隔门限为 20,000 tick（100 µs）。在退 OP 后，从核内只读取得四轴有效的硬件 TX EOF：`fd089526, fd094809, fd0a05dc, fd0a9b82`，约 200 tick/µs，相邻 EOF 差为 228.975、242.975、191.550 µs。对本次标准 11 位 ID、8 B、FD+BRS、1/5 Mbit/s 成功帧，保守上界取 48 个仲裁速率位和 160 个数据速率位（包括填充），即 80 µs。扣去后一帧的上界，三段 EOF 到下一成功帧 SOF 的下界分别为 148.975、162.975、111.550 µs。这不是 TXBAR 或 SOF 的直接采样。

## 长测首错

计划 30,000 拍，每拍四轴。304 帧发送第一组命令；305 帧既携带下一组命令，又读上一组结果。305 的 LRW 按时完成，WKC=3，但期待回显 304，实际仍为 303；两帧的 PublishSeq 都是 2808769。RK 立即停发：命令 PDO 2 个，已验证 0，首个窗口失败 1 个，随读回携带的下条命令未获确认；剩余 29,998 个命令 PDO 未发。没有重试。

- CAN2 四轴控制发送完成计数在长测中各从 1 增至 2，都有该组的有效 TX EOF；并非第 3、4 台没有发出。整个两段测试 CAN3 控制完成数始终为 0。
- HPM 同一本地 epoch 69 的故障位为 `0x20`（本拍 CAN 反馈缺失），上一发布 epoch 为 68。缺设备掩码 `0x8` 是 Profile 设备序号 3，对应 **CAN2 ID 3、物理轴槽 16**。另外三台不在缺失掩码中。故障处理为 Sync0 后 +1642 µs，本拍截止为 +1600 µs；无 `TX_LATE` 位。
- CAN2 未锁存 MCAN 协议错误。现有证据能确定 ID 3 的反馈没有在截止前被认作本拍有效数据；不能区分物理未回、到达太晚或帧未通过匹配。未补发诊断拍、未清除电机故障。

核内快照仅在周期输出退出后短暂停核读取，已恢复运行；运行时未挂断点。最后只请求 PREOP 并独立复核：HPM `PREOP +`，AL 状态码 0，RK `Idle / Active: no`，boot ID、拓扑代数和映射长度未变。

原始证据位于 [本次实板目录](../../artifacts/target/can2-five-profile-mit.g3VJjTWE/)：`单拍.csv`、`长测首错.csv`、三份逐轴计数、`首拍核内时标.log`、`长测首错核内快照.log`、`收尾状态.log`。总有效接收计数还包括状态查询，不作为 MIT 回包数。
