# 生产网关就绪首轮实板验证

结论：**实板启动日志首装及本地 READY 已验证；一次确认与掉线回归未执行。** MCU 工作任务停止被定时唤醒后，IgH 虽发现物理从站，但无法完成 SII 识别和 PREOP SDO 读取。

| 阶段 | 证据与结果 |
| --- | --- |
| 保留区备份 | 写入前先暂停，备份并对照 Flash 验证 SII 64 KiB、启动日志 8 KiB。探测物理 Flash 为 1 MiB、4 KiB 扇区；日志全空且用户确认此前从未发号。 |
| 首装日志 | 只向 `0x80090000` 写入 16 字节记录，无擦除。写后直接比较仍读到 `0xFF`；未补写，复位暂停后完整 8 KiB 读回 SHA-256 与计划一致，SII 校验不变。 |
| 烧录生产镜像 | `hpm-debug` 镜像预计擦除区间 `[0x80000000, 0x8006a000)`，不碰保留区。烧录事务在复位前再次备份，镜像和两保留区校验成功。 |
| 本地 READY | 生产固件启动后，J-Link 暂停读取就绪核心，状态为 `READY (2)`、会话为 0、Boot ID 为 `0x0000000200000000`。最终完整日志读到 epoch 0、1、2；SII 再校验与烧录前备份一致。生产 Profile 的 `devices: []` 只核验本地 CAN 通道。 |
| EtherCAT / IgH | 链路 UP，发现 1 个物理从站；扫描和重扫后身份仍全 0、AL 为 INIT，`0x2002` 只读上传报 I/O 错误。没有进 OP，没有下发确认帧或业务 PDO。 |
| 结束状态 | 生产 Debug 镜像留在板上，HPM 保持暂停，IgH 未激活；未接电机或 CAN 业务节点。 |

## 卡点

暂停读取显示 CPU 在 FreeRTOS Idle，任务及 ISR 临界嵌套计数均为 0，但 PLIC M-mode 阈值仍为 3。GPTMR2 中断已使能且状态和 PLIC pending 均置位，优先级为 1，被该阈值屏蔽。网关任务时钟在两次快照间保持约 9 ms，不足以持续处理 SSC 和 SII 请求。

本地 SDK 的 `ulTaskGenericNotifyTake()` 允许阻塞时在临界段内切换任务；HPM FreeRTOS 上下文恢复保存并恢复临界嵌套计数，但未同步 PLIC 屏蔽阈值。这是优先排查的路径；本轮未改写 PLIC 寄存器、BSP 或 SDK 来绕过故障。后续先复测工作任务持续唤醒、从站身份和 PREOP SDO，再测一次确认、OP 退出和旧会话拒绝。

RK3588 已编译[无动作主站探针](../../tests/host/ethercat_data/production_ready_probe.cpp)，复用 DriverModule 的 IgH 周期辅助，不运行旧逐项 SDO 配置。它尚未通过线上运行验证。
