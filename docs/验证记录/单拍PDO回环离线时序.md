# 单拍 PDO 回环离线时序

验收口径：第 N 拍发出序号 N，到了第 N+1 拍边界，主站必须已经从有效 TxPDO 中读到同一个序号。旧序号、错误序号、AL 不在 OP、任一方向 WKC 不完整、超过 1 ms 截止的反馈都判失败；后续补到不改判。这是单笔回环延迟要求，不等同于每 1 ms 更新一次旧数据。

## 旧路径的 3 ms

旧 IgH 探针每拍先收上一轮报文，再把 SM2 写、SM3 读一起排队发送。SM3 读请求不会等待同拍的 HPM Sync0 或应用处理。以 60 秒基线中稳定的 3 拍序号差反推，请求 N 在 N 拍发出，含对应回显的 SM3 读取直到 N+2 拍才被送出，主站 N+3 拍处理该返回。原 CSV 没有与主站共时基的 Sync0、PDI 和实际 TxPDO 写入时间戳，不能把 N 到 N+2 的时间精确分配给 MCU 各段。

离线代码审查还发现独立的一拍延迟风险：`motor_control_output()` 只暂存已锁存的命令，`motor_control_process()` 处理后才更新接受序号。若 worker 第一次调度已到 TxPDO 发布窗，旧代码会先做 `publish_due()`，有可能将上拍序号作为本拍已发布。新代码按 Sync0 epoch 记录暂存与消费，只允许准备过本拍命令的反馈在原窗口内发布；如果命令仍被网关周期门暂缓，继续等，但不得延后截止。没有收到任何首帧前保留既有状态发布行为。

## 新探针的名义时间表

使用标准 IgH 域接口从原 SM2、SM3 注册两个独立方向的域，验收保持原宽度及既有接受序号字段，并分别检查 WKC。用户态不访问 ESC 固定地址，不改 ESI、SyncManager 的 PDO 赋值、对象字典或 Profile。RxPDO 仍经 SSC/PDI 收入、Sync0 锁存；TxPDO 仍经 SSC 写入 ESC。DC 起点和主站绝对时拍使用同一 `CLOCK_MONOTONIC` 网格，由 `ecrt_slave_config_dc()` 配置 Sync0 相位。

| 相对第 N 拍 | 操作 |
| --- | --- |
| 0 µs | 更新 DC 应用时间，只排队发送 SM2 写入 N；每周期同步 DC 一次。 |
| 120 µs | 名义 Sync0。RxPDO 必须已经就绪，HPM 消费当前 epoch 的命令。 |
| 270–870 µs | HPM 原发布窗：相对 Sync0 为 +150 到 +750 µs，仍使用 600 µs 预算及 250 µs 提前量。 |
| 885 µs | `receive → process` 检查写回包，再只排队并发送 SM3 读。 |
| 975–1000 µs | 只轮询已经发出的读请求，`receive → process` 后核对 OP、双向 WKC 和序号 N。到 N+1 边界仍无有效反馈立即失败，不用旧帧或延迟重读补账。 |

该时间表是待实板验证的候选值，并非已证实的线侧时序。100 Mb/s、784/1072 字节单数据报的名义串行化约为 66.6/89.6 µs，未把额外报文、网卡与 PDI 运行时间或调度尾部当成已知上界。如果实际相位或线侧回程余量不足，本探针会判失败，不会放宽 HPM 截止。新模式为 `--one-cycle 1`，仅接受 1 ms 计时模式；不替换生产 DriverModule，也不会退回旧的同拍读写模式。

离线验证：历史 CSV 按下一拍匹配复算；主站排程模型覆盖正确序号、旧/未来序号、WKC 和 AL 否决、恰好边界与超时；HPM 真实周期代码的主机回归覆盖 worker 晚于发布窗口起点、命令被暂缓以及仍然在原截止处触发 `TX_LATE`。本机编译并链接 IgH userspace 探针，只运行未打开设备的参数校验。HPM Release 构建及镜像保护检查通过。未上板、未接 CAN。
