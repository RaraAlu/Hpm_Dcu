# CAN2 多轴发送：上游源码对照

目标是一条 CAN2 总线发四个 ENCOS ID：上一条命令的 TX EOF 之后至少 100 µs 才允许续发，下一轴不等上一轴的 RX。以下是源码对照，不是台架实测。

| 参考代码 | 可以借鉴 | 与本项目的差别 |
| --- | --- | --- |
| HPM SDK v1.12.1 [CAN FD 批量发送](https://github.com/hpmicro/hpm_sdk/blob/v1.12.1/samples/drivers/mcan/src/mcan_txrx_demo.c#L117-L136) | 一个 MCAN 实例逐帧改标准 ID，从 0 发到 2047；设置 FD 和 BRS，调用 `mcan_transmit_blocking`，循环不等 RX。 | 每帧 64 字节；没有帧尾后 100 µs 的定时。 |
| HPM SDK v1.12.1 [异步 TX Queue](https://github.com/hpmicro/hpm_sdk/blob/v1.12.1/samples/drivers/mcan/src/mcan_txqueue_demo.c#L66-L111) | 一次提交一帧，队满时重试，最后才等所有回环帧；收包不阻塞逐帧提交。 | 经典 CAN 内部回环，待发帧按 CAN 优先级选取，不是按时隙发。不能预填四帧就期待线上的间隔。 |
| HPM SDK v1.12.1 [TX Event FIFO](https://github.com/hpmicro/hpm_sdk/blob/v1.12.1/samples/drivers/mcan/src/mcan_tx_event_demo.c#L83-L105) 和 [TSU 时间戳](https://github.com/hpmicro/hpm_sdk/blob/v1.12.1/samples/drivers/mcan/src/mcan_timestamp_demo.c#L90-L149) | 前者用 marker 把发送事件对应到提交的帧；后者启用时间戳捕获并从 TX 事件读值。`capture_on_sof=false` 选择 [EOF 而非 SOF](https://github.com/hpmicro/hpm_sdk/blob/v1.12.1/drivers/inc/hpm_mcan_drv.h#L990-L995)。 | 两个例程都用内部回环，且等待 RX；不可直接照搬其等待循环。 |
| mjbots moteus [C++ 多轴循环](https://github.com/mjbots/moteus/blob/main/lib/cpp/examples/multiple_cycle.cc#L75-L116) | 每轴组一个 `CanFdFrame`，一次 `BlockingCycle` 提交整批，按回复的源 ID 归轴。 | 示例会保留缺回复轴的旧值用于显示；这不是本拍新反馈，也没有 ENCOS 的帧间时序保证。 |

针对本台架，可借鉴的是逐轴组帧、TX 事件关联和硬件 EOF 捕获。提交成功不是完成；收到 TX 中断的 CPU 时刻也不是硬件 EOF。下一条命令由前一条有效 TX EOF 加 100 µs 放行，反馈另按当前周期归轴。上述示例没有同时实现这两条规则，也不能证明四轴在 N+1 全部读到本拍新反馈。
