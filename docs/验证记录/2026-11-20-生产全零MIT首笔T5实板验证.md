# 生产全零 MIT 首笔 T5 实板验证

2026-11-20，HPM Release + RK3588。**1 kHz 首笔只通过 CAN1 收发；500 Hz 生产复测通过单笔 N+1。** 两次各自仅获准测试一笔全零 MIT，不重试、不使能、不读 `0x17`、不切 mode 2；CAN1 只接 HRA55H-100（`0x02`），保留通信供电，动力隔离。

## 配置与证据

- [生产 Profile](../../firmware/app/profile/cfg/生产CAN配置.yaml) rev 3，`neutral_mit_only`，FD+BRS 1/5 Mbit/s，DAR，固定 PDO 784/1072 B。生产 Release 的发布提前量为 250 µs，构建预算 600 µs；周期 1 kHz，DC Sync0。RK 用独立 IgH 夹具注入，下发相位为 +375 µs（仅为本次试验参数，不是生产窗口的结论）。
- 下载审计：`artifacts/target/20261120T102153.358061Z/`，镜像 SHA-256 `1aec762ec710d5675559716ca5690d157cb745ee2d5e7e80b8b27d5efd4dd9`，按受保护流程备份与校验保留区。
- RK 与 HPM 原始证据：`artifacts/target/t5-production-neutral-mit-20261120-XaKWj8/`，含 `rk_t5.cpp`、`rk-t5.log`、`post-t5-hpm-registers.log`、`can1-msg-ram.bin` 和 `can1-sw-rx.bin`。RK 夹具可执行文件 SHA-256 `e189a000e0cc100eca64206d761e46a61fe1f2d621e0c3ea10542062931e9221`。

## 实测

| 环节 | 结果 |
| --- | --- |
| 零使能暖机 | 连续 64 拍满足 OP、单帧、WKC=3、上拍命令序号匹配、无新轴反馈；第 613 帧独立 ARM。仅证明短基线可用，不代表发布窗口余量已验收。 |
| N 帧 | 序号 614，单帧、WKC=3。HPM CAN1 只提交一次，发送标准 ID `0x02`、DLC 10（16 B），`11` 后跟 15 个零；TXBTO bit 0 置位，TX EOF `0x5f5d78d1`。 |
| 电机回复 | 标准 ID `0x02`、FD+BRS、DLC 10，`80 20 00 41 46 3C C0 80 00 00 00 00 00 4D 4D 60`。HPM 软件接收队列记录有效 RX EOF `0x5f5daecb`，比 TX EOF 晚 13,818 个同源 TSU tick；MCAN1 ECR 为 0。 |
| N+1 帧 | 序号 615，仍是单帧、WKC=3，但 `AcceptedCycleSeq=613`、`PublishEpoch` 未变、`ValidFlags=0`，没有第 614 帧的新反馈。RK 收取完成时间（本机单调时钟）为 `195514101019048 ns`。 |
| 故障与收尾 | HPM 周期诊断 `faults=0x4`（`PDO_PIPELINE_TX_LATE`）。运行结束后 RK master 已退回 Idle/Inactive，HPM 为 SAFEOP E。未重发 MIT。 |

这次证明了生产 PDO 能触发预期的 CAN 发送，且电机回包进入 HPM。未采集该拍的提交、锁存、取包、打包和 SM3 写入分段时间，不能仅凭 EOF 和全程最大值判断哪一步耗尽了发布余量。RK 和 HPM 时间也未做同拍跨时钟对齐，不直接相减。下一步先量该生产配置的发布余量，并定位 N 拍从锁存到 SM3 的耗时，不能靠放宽超时或拿 WKC 代替反馈。T6 暂不开始。

## 超期诊断准备

上一轮[空载相位实测](单帧LRW的同步相位窗口实测.md)的 +351～+397.42 µs 窗口用的是 399 µs 发布提前量；当前 Release 的 250 µs 把固件硬截止从 Sync0 +601 µs 移到 +750 µs。若仅替换截止、沿用旧样本与同样余量，Tx 允许的相位上界会降至 +248.42 µs，低于旧 Rx 下界 +351 µs。这个推算只说明 +375 µs **不能由旧窗口保证**，不是当前镜像的相位实测，也不能证明失败一定由相位导致。

诊断构建仅开启已有的 `CONFIG_PDO_PHASE_TRACE`，不改 CAN 事务、PDO 或发布截止。停机后从 RAM 取三组记录：

- `pdo_phase_trace`：按 PDO 序号找锁存和处理完成，区分仍在等回包、已开始打包、已开始写 ESC、写完但没在截止内发布。失败拍也保留分段时间，`published_us` 仍只代表成功提交；`fault_epoch` 是任务观测故障时的 epoch，Sync0 已翻拍时可能不是失败拍。
- `neutral_mit_phase_trace` 与 `s_rx[1]`：提交、任务观察到 TX 完成、ISR 入队、应用判定及事务结果，同用 HPM 微秒计时。TX/RX EOF 只在同一个 MCAN 的 TSU 时钟上作差；即使事务先超时，接收环仍能用于查这笔帧的入队时刻。
- RK 逐拍记录：命令序号、N+1 的回显与有效位、帧时间。算跨端余量时，用相邻成功样本的 ESC DC 配对数据，不直接减 RK 单调时钟与 HPM 本地微秒时钟。

宿主用例已验证等待期间不发布、截止不延长，以及失败记录能区分打包超期和 ESC 写入超期。普通 Release 重新构建后 SHA-256 与本轮实板镜像一致；诊断构建的结果不计为生产 T5 通过。

## 诊断镜像零输出暖机

现场仅授权暖机。配置仍为 1 kHz DC Sync0、+375 µs、784/1072 B；RK 只跑 `--dry-run`，未发 ARM 或 MIT。下载审计在 `artifacts/target/20261120T103125.065727Z/`，镜像 SHA-256 `e360e7224bd75ec29457c5a41a6f940b268024f4d779fddd4739661f18c148c6`；原始记录在 `artifacts/target/t5-phase-zero-warm-20261120-xuRvAK/`。

| 指标 | 观测 |
| --- | --- |
| RK 门槛 | 连续 64 拍 OP、单帧、WKC=3、上拍序号匹配；最后序号 611 读到 610，轴有效位 0。 |
| HPM 分段样本 | 65 拍，序号 547–611 均在本轮成功发布；SM2 提交到 Sync0 余量 105–121 µs，Sync0 到命令处理完成 175–288 µs。 |
| SM3 发布成本 | 打包至 ESC 写完 193–221 µs，其中 ESC 写段 149–163 µs；发布完成在 Sync0 后 382–511 µs。 |
| 跨端单点配对 | 第 610 拍在 Sync0 后 402 µs 发布；用同拍 ESC DC 读数对齐，距第 611 帧 FRMW 为约 261 µs。该次 FRMW 实际相当于前一 Sync0 后约 663 µs，比固件 +750 µs 截止早约 87 µs；这是一对实测，不是全程最差界限。 |
| 收尾 | HPM 无周期故障，所有 CAN 提交序号为 0。RK Idle/Inactive，HPM PREOP；板上保留诊断镜像。 |

当前 `ecat-can` 是一个业务任务，不是两个抢锁的任务。零输出结果支持明确安排任务内的三个执行阶段：EtherCAT 消费锁存命令、CAN 有界执行并更新反馈、EtherCAT 发布。CAN 应在回包后或在 SM3 保留窗口开始时交回执行权（以实测的最早下一帧读取时刻和发布成本定边界），不应一直等到 CAN 自己的超时。交接后到达的回包不能补报为该拍新反馈；PDI、Sync0 和 MCAN 的捕获中断不参与任务层的互斥。这里只证明空载发布和有必要预留发布窗口，未测真实 MIT 在该窗口内是否能闭合。

## 500 Hz 零输出暖机

本次测试改为 500 Hz：RK 发送、IgH 发送间隔、DC Sync0 均为 2 ms，保持 +375 µs 相位和 784/1072 B 布局。不改生产 Profile、不刷板，沿用上述诊断镜像；RK 仅运行 `--dry-run`。独立夹具源码和原始日志在 `artifacts/target/t5-500hz-20261120-Wuh8KA/`，不覆盖 1 kHz 证据。

- RK 连续 64 拍单帧、OP、WKC=3，均回显前一拍序号；最后第 457 帧读到第 456 帧。HPM 确认配置周期 2,000,000 ns，64 个相邻 Sync0 的固件时间戳间隔为 1,996–2,004 µs（不是硬件边沿抖动）。
- HPM 留下 65 拍（393–457）同序号发布记录；SM2 提交余量 112–121 µs，SM3 在 Sync0 后 1,343–1,391 µs 发布。仅有的一对 RK/HPM 对齐样本中，第 456 拍发布距第 457 帧 FRMW 约 282 µs。
- CAN 提交计数为 0。退出后下一周期（epoch 66）记录 `RX_MISSING`，在最后一个已发布周期 65 之后；最终 RK Idle/Inactive，HPM PREOP。此次没有发 MIT，不计 T5 通过。

## 500 Hz 生产单笔复测

按授权从诊断镜像切回原生产 Release，SHA-256 与 1 kHz 首笔相同；受保护下载与回读审计在 `artifacts/target/20261120T110417.081227Z/`。使用上一节的 500 Hz 夹具和 +375 µs 相位，在 64 拍零输出暖机合格后单次运行 `--t5-once`。原始日志与 CAN1 RAM 在 `artifacts/target/t5-production-500hz-20261120-HEWZU5/`。

| 环节 | 结果 |
| --- | --- |
| N：1338 | 单帧、WKC=3、OP；读到旧一拍序号 1337，无新反馈。HPM CAN1 确认只提交并发送一笔标准 ID `0x02`、FD+BRS、16 B 的全零 MIT（`11` 加 15 个零）。 |
| 设备回包 | 同 ID、FD+BRS、16 B，`80 20 00 41 46 3C C0 80 00 00 00 00 00 4D 4D 60`。TX EOF `0x7a343ad5`，RX EOF `0x7a347009`，同源差 13,620 tick；CAN ECR 为 0。 |
| N+1：1339 | 单帧、WKC=3、OP；`AcceptedCycleSeq=1338`，发布序号从 10167 增至 10168，新鲜位有效，`ValidFlags=0x37`、`FeedbackAgeMs=1`。RK 收取完成本机时标为 `197975132575856 ns`；夹具返回 `T5_N_PLUS_1_PASS=1`。 |
| 收尾 | HPM 确认周期 2,000,000 ns，周期故障位为 0；RK 已退出至 Idle/Inactive，HPM PREOP；未重发。 |

本次证明生产 Release 在该 500 Hz 配置下一笔真实 N+1。该构建未开启分段计时，缺该拍的 CAN 提交与 SM3 写入完成的精确时标，不从零输出暖机外推实载余量，也不转记为 1 kHz 或长测通过。当次烧录的 rev 3 每个 PDO 会话仅允许一笔全零 MIT；[rev 4 连续路径](2026-11-20-生产全零MIT六十秒离线验证.md)另行验证。
