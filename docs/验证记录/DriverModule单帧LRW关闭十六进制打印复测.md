# DriverModule 单帧 LRW：关闭十六进制打印复测

2026-11-19，RK3588 / HPM。仅关闭[上轮重叠映射实板测试](DriverModule单帧LRW重叠映射实测.md)中 DriverModule 自动开启的 IgH 网卡逐帧十六进制打印，保留物理收发帧/字节计数、WKC、OP 采样和所有原有停止条件。**32 拍门槛未通过，第 31 拍退出，未开 60 秒组，也没有补拍或重跑。**

## 计分结果

| 观测项 | 结果 |
| --- | --- |
| 实际计分序号 | 2756 至 2786，共 31 拍 |
| 物理帧 | 每拍发 1、收 1，总计发 31、收 31；每拍收发字节数相等 |
| IgH 域 WKC | 序号 2756 至 2785 为 3/3；2786 为 1/3 |
| 运行状态 | 故障拍主站缓存的 AL 状态仍为 OP；IgH 日志在运行/释放期间有同步错误 0x001A。预热不计入上述 31 拍 |
| 输出日志 | 内核收发十六进制打印 0 条；本次不是原始帧抓包 |
| 运行条件 | 仅 DriverModule；CPU6 单核、FIFO 80、锁内存；1 kHz、RK 跟随 HPM；零轴、零使能、不接 CAN |

活动域仍为从逻辑地址 0 重叠的 SM2 784 B / SM3 1072 B，IgH 报告一个 1072 B LRW，预期 WKC 为 3。本轮用相同物理网卡计数、域状态逐拍核对；线上 LRW 头尾已在上轮实帧核实。本次没有新增一次发送或回显条件。两次实板结果都不足以说明关闭打印会增加或减少故障概率，但证明不打印也能复现。

## MCU 时间线

| 序号 2785 的事件 | HPM 时钟（µs） | 距本拍 Sync0 |
| --- | ---: | ---: |
| SM2 事件 | 47842694 | 提前 127 µs |
| ESC 开始读 | 47842704 | 提前 117 µs |
| ESC 读完 | 47842817 | 提前 4 µs |
| Sync0 中断记录 | 47842821 | 0 |
| RxPDO 提交函数完成记录 | 47842826 | 晚 5 µs |

时间在同一 MCU 时钟上相减。故障点 `epoch=46` 的 Sync0 仍见 `stage_busy=1` 且无可取的新槽，锁存的是 `RX_MISSING`，不是 `TX_LATE`。2785 的 EtherCAT WKC 此时仍是 3；随后 2786 有物理返回帧，WKC 只有 1，没有相应 MCU RxPDO 提交记录。该拍不纳入提交余量，不按零余量补值。

以故障点的序号、epoch、stage 起止时间为锚，只匹配实际记录的同拍 Sync0，不拿下一拍成功取槽的时刻充当本拍余量。30 个可配对样本的**提交完成记录余量**（Sync0 中断时间减提交完成时间）最小 −10 µs，中位 −5 µs，最大 −5 µs。在这 30 个样本中，27 个序号实际到下一拍才被取走，1 个在目标拍被取走，2 个未见成功锁存。**提交完成打点在原子发布 ready 之后**：负的完成余量不等于每拍都没成功发布。对 2785，还另有 MCU 的缺槽故障证据。

## 代码核对

RK 以帧首参考时刻控制发帧相位（目标 37 µs），配置 Sync0 相位为 +255 µs。两者并不测量 HPM 应用槽何时可见。30 个对齐样本中，SM2 事件到目标边沿有 123～127 µs，而事件到提交完成打点用去 132～133 µs；其中 10 个样本连 ESC 读取结束都已越过目标边沿，不能只归咎于提交后的调试打点。

HPM 的 [原子发布](../../firmware/app/cycle/pdo_pipeline.c#L88) 与 Sync0 取槽有明确先后，多个完整写入会由最新槽替换之前待取的槽。使用原项目的 `pdo_pipeline.c` 进行[最小离线回放](../../artifacts/target/pdo-lrw-nohex-20261119-NiIOTYV3/ready_order_replay.c)，按计分末段观测到的先后关系，目标序号 2783 / 2784 / 2785 实际取到 2782 / 2784 / 空，故障位为 1。仅将这三次原子发布放到各自目标边沿前，取得 2783 / 2784 / 2785，故障位为 0。该对照复现的是事件顺序，不是声称已测得原子指令的耗时或验证了新的相位值。现有 PDO 槽的 13 个离线测试通过；本次未改发帧相位、MCU 取槽规则或故障保护。
