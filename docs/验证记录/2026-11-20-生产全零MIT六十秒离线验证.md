# 生产全零 MIT 六十秒离线验证

2026-11-20，**离线通过，未烧录、未启动 T6 台架**。HPM 使用生产 Release、实际生产 Profile 和原固定布局；没有另一套单发运行模式，也没有 RAM 诊断 PDO、Raw CAN 旁路、使能帧或 mode 2 门槛。

## 生产链路

- [生产 Profile](../../firmware/app/profile/cfg/生产CAN配置.yaml) rev 4：仅 CAN1 的 HRA55H-100（`0x02`），FD+BRS 1/5 Mbit/s，500 Hz DC Sync0，首轮上限 30,000 条。HPM 校验实际 Sync0 周期为 2 ms，不能只把 PDO 通道提示改为 2 ms。CAN 的 `single_shot` 指每条帧禁止硬件自动重传，不是单发运行模式。
- OP 的普通零输出 PDO 建立基线，独立 ARM PDO 后才允许首条全零 MIT。之后每个连续、新序号 PDO 最多触发一条；前一笔只有收到 TX 完成、同 MCAN 严格后继的 RX EOF 和完整有效的 `0x80` 才放行下一笔。五个控制量恒为零，仅协议尾字节滚动计数（模 256）。
- CAN 等待窗口最长 350 µs，并且不能侵占 SM3 发布窗口。若时间不够则不提交；到交接点仍在等待则关闭本轮，发布故障而非新反馈。提交异常、重复或跳号、无有效回包、TX/RX 证据错误、报警、失步或退出 OP 均不继续发；到上限或停止后重连也不自动再开一轮。
- `0x80` 不回显请求计数。关联仍要求独占该 CAN 通道、无同节点主动上报和无其他查询，不能把时间戳先后当成唯一身份凭据。

## 沿用单帧样本

[RK 夹具](../../tests/host/ethercat_data/production_mit_endurance_probe.cpp)按[大 PDO 单帧回环样本](../../artifacts/target/cih408-mit-once-dc-20261119/大PDO单帧回环实板记录.md)的办法编写：SM2 784 B、SM3 1072 B 重叠，物理发送计数 1、OP、WKC=3；跟随 HPM DC、+375 µs，64 拍无输出暖机后逐拍核对 N→N+1。本次使用普通生产 PDO 中的 `AcceptedCycleSeq`、新鲜位、有效字段和故障位，不使用旧诊断 `BACK/PRDY` 标记。CSV 在退出后写出，保留首错一拍；最后用零输出 PDO 读回最后一笔，不补发。

同一 LRW 读 N 的反馈时已携带 N+1 的输出，主站检出异常时该帧可能已上链；主站不再排后续有效命令。HPM 的本地故障与在途保护独立拦截，CSV 中的“已送 PDO”不等于“CAN 线上已发”。
