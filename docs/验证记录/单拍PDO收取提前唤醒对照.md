# 单拍 PDO：提前 50 µs 唤醒收取的对照

2026-11-19。独立 RK 探针在同一份二进制、同一次 HPM 启动上对照两个运行选项：`--collect-wait legacy` 仍等待到 +975 µs；`--collect-wait early` 用相同的等待函数睡到 +925 µs，只读 RK 单调时钟等到 +975 µs 再调用 IgH 接收。未使用绝对等待组作基线。CPU6、FIFO 80、锁内存、1 kHz、RK 跟随 HPM；SM2 0 µs 发、SM3 +870 µs 发、Sync0 +255 µs、MCU 构建保护 600 µs 不变。

## 逐拍验收

两组先分别跑 32 拍；探针及独立 CSV 核对均全过之后，才分别跑连续 60 秒。最小截止余量取每拍已冻结的 N+1 截止减去最终反馈确认时刻，不用首次 WKC 或提前唤醒的时间冒充完成时间。

两轮的 60,000 拍均首轮收齐、WKC 1/1、采到 OP、同帧参考有效且回显与本拍序号一致。提前组最长晚醒 9.169 µs（相对 +925 µs），没有一拍醒过 +975 µs，也没有一拍提前收取。提前组最紧的命令 48910 在 +975.247 µs 开始收取，收取至最终确认用 7.291 µs。最小余量比同轮基线多 **5.740 µs**，不是 IgH 收包本身快了这么多。

代价是提前组醒来到首次接收的墙钟间隔中位数 48.124 µs，这段用来忙等，不是网卡处理时间，也不是实测 CPU 占用率。这 60 秒验证了单拍回显，未覆盖既往 29:40 附近的长尾，亦没有达到完整回环间隔全程 ±1 µs。

## 离线与台架

- [调度与验收](../../tests/host/ethercat_data/one_cycle_pdo.hpp)分别记录实际醒来、首轮接收起点和原本的最终确认；在计时构建中，首收早于 +975 µs 即不能通过。晚醒已过 +975 µs 则立即走正常收取，不重发，不平移截止。
- [离线注入](../../tests/host/ethercat_data/test_one_cycle_pdo.cpp)覆盖唤醒延迟 0、23.167、40、50、60、80 µs；晚醒 40 µs 时仍在 +975 µs 才实际接收，晚醒 80 µs 时 +1005 µs 才收，即使回显正确仍判超期。也覆盖准时醒但忙等中被延迟 30 µs、首收提前 1 ns 等反例。相关主机测试 20 项通过。
- 计分时临时移开可迁移无关线程，预检没有设备 IRQ 指向 CPU6。用已有 HPM 镜像，核对镜像及两个 Flash 保留区后正常复位，没有烧录；四轮启动编号均为 116。各组只读 Profile 前后一致，不接 CAN，不改 MCU、PDO 布局或生产 DriverModule。结束时 IgH Idle、从站 PREOP、HPM 暂停，临时亲和性已恢复；SII 回读一致，启动编号日志保留。
