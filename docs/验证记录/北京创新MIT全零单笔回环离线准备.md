# 北京创新 MIT 全零单笔回环离线准备

目标：RK 触发一笔，HPM 只发一帧 MIT，直接收电机反馈，写入 SM3，下一帧 LRW 读回。当前只完成主机离线演练；没有连接设备、写入板卡、改生产 Profile 或接入生产 PDO。

## 协议和轮式项目证据

- 本机厂家资料《CAN 协议说明 CiH408 V1.6》§2、§4.2、§5.1：标准 CAN FD，仲裁/数据 1/5 Mbit/s，控制帧 CAN ID 为关节 ID。MIT 是 `0x11`、16 B（MCAN 原始 DLC 为 10）。依次为操作码、Kp/Kd 各一个大端 `uint16`（物理值乘 10）、目标位置/速度各一个大端 binary32、前馈一个大端 `int16`、滚动计数一个字节。轮式 `application/motor/protocol/protocol.c` 的 `cih_mix()` 与此一致，并开启 BRS。
- 五个物理量都取正零，且首笔计数为 0 时，载荷是 `11 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00`。最后一个字节是会话计数，不是控制量；若已有会话，应使用其下一计数而不是强制清零。
- 默认反馈格式下，`0x11` 直接回同 ID 的 `0x80` / 16 B，不再发 `0x17`。轮式项目 `debug/2026-11-09-cih408-mit-mode-confirmation/README.md` 记录了 `0x11` TX EOF 到 `0x80` RX EOF 为 67 µs，中间无查询。那条是已使能后的保持帧，不是全零试验，反馈仍为 mode 1。收到反馈只证明通信；报告进入 MIT 还需 mode 2，报警独立核对。

## 离线演练

```sh
python3 -m unittest discover -s tests/host -p 'test_bjcx_mit_once.py' -v
```

主机夹具模拟 RK 产生带非零序号的诊断 RxPDO、HPM 单次发帧、真实历史反馈字节回放、SM3 写完和 RK 校验。只接受匹配物理通道、TX 令牌、后于 TX EOF 的同 ID 标准 FD+BRS 反馈；RK 只收 WKC 3、OP、对应序号的新结果。错误路由/格式、重复命令、取消、拒绝提交、出 OP 和超期都有回归。夹具的 32/48 B 是隔离的诊断数据，不是生产 PDO 契约；601 µs 是用于演练的片上截止，不是本轮实测。

## 接板前边界

- 不自动使能、不切换反馈格式、不重试。全零 MIT 不是失能或停机。模式与使能前提须按实机手册确认；本次离线结果不说明未使能时该电机会如何处理 `0x11`。
- 默认 `0x80` 不携带请求序号。实际接入需单节点、独占诊断通道，无周期查询和主动上报；发前清陈旧 RX，按同一 MCAN 时基的 TX/RX EOF 匹配，并关闭 MCAN 自动重传。不能用软件先读到哪个队列替代硬件时序。
- 实板还需把诊断事务接到 RK/HPM 和 MCAN，超期撤销未完成 TX，核对真正的 SM3 写完和下一帧读回。生产 bjcx 目前仍只读，不应借 Raw PDO 绕过，也未将离线夹具编入任何镜像。
