# 500 Hz 三路 CAN FD 十三轴单拍反馈验收

**结果：未通过。** 2026-11-29（北京时间），RK 生产 `DriverModule` 向 CAN1/2/3 上的 3+5+5 台电机发布一次全零 MIT。13 个目标的 CAN TX 完成计数均从 0 增至 1，但第 N+1 帧没有本拍新反馈。首错即停，未重发，未转长测。

## 测试对象

- HPM 源码基线 `82dfba8ea9e3` 加本次三项修改：新锁存的 SM2 命令不受后台 50 µs 节流；只有已发射、未收割终态的同 ID 反馈槽才阻挡 RX 队头；首发失败在原内核临界区内回滚。未清空 RX 队列，未增加每轮 TX 收割数，未改变总线顺序、全局中断掩码或状态轮询。
- `python3 scripts/dcu.py build --preset hpm-release` 构建、镜像检查通过；逐轴采样为工程默认的 `CONFIG_CAN_BATCH_SAMPLE=ON`。现场确认动力隔离后经受保护入口烧录，固件及 SII、启动编号日志保留区均经回读校验。烧录快照和构建 ELF 的 SHA-256 均为 `924ae009b5842e5083494c42569b60dffb60c46ce4fbd6d67752abb2c312423a`。
- 本次 HPM 和 RK 使用相同的 WG3 YAML，实际为 Profile **1/rev 13**，PDO 周期 2000 µs、Sync0 相位 +375 µs。两端的布局 JSON、两个生成头、ESI 和 SII 共 5 个文件逐字节一致。进入 OP 前，通过 CoE 读回 Profile ID、修订号、布局摘要及完整双向映射：SM2 为 19 个 PDO、161 项、388 B；SM3 为 19 个 PDO、216 项、492 B。均与本次生成物一致。

## 单拍结果

RK 只发布一条命令，`batches=1`。第 N 帧命令序号为 1132；第 N+1 帧读到的受理序号仍为 1131，`requested=0x03e7c380`、`fresh=0x0`、`n_plus_one=0`。测试前后启动标识与拓扑代次不变。逐轴 TX 计数证明这 13 条命令实际发出，不证明 SM3 发布成功。

以下时间均相对**这一拍的 Sync0**，单位 µs。“写入”指 HPM 解码后写入该轴的 PDO 输入缓冲，不是写完 ESC SM3。严格截止为 +1600 µs。

| 总线 | 首槽提交 | 最晚 RX EOF | 最晚写入 | 截止前写入 |
| --- | ---: | ---: | ---: | ---: |
| CAN1（腰） | 385 | 807 | 2400 | 0/3 |
| CAN2（左臂） | 395 | 1221 | 2615 | 0/5 |
| CAN3（右臂） | 403 | 1188 | 1515 | 5/5 |

13 台电机的同路 RX EOF 均晚于各自 TX EOF，且都早于截止。CAN2 ID 1 的反馈在 +560 µs 已进入软件队列，直到 +2021 µs 才开始出队。HPM 锁存 `PDO_PIPELINE_CAN_FEEDBACK_MISSING`（`0x20`），缺失设备掩码 `0x000000ff` 对应 CAN1 的 3 台和 CAN2 的 5 台；严格 SM3 发布计数为 0。CAN3 的 5 份反馈虽及时写入，也不能作为部分有效帧交给主站。这一拍证实超期发生在 HPM 收到回包之后；不能据此判定具体抢占源或最坏时延。
