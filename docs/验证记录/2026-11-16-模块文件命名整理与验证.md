# 模块文件命名整理与验证

日期：2026-11-16。承接[应用层职责拆分](2026-11-16-应用层职责拆分与事务修复记录.md)，按实际职责整理项目自有文件名。**仅改名、引用、头文件保护宏、源码说明和测试/文档；不调整业务逻辑、任务划分、同步时序、函数符号或线上协议。未操作目标板、主站，未自动提交。**

## 生产文件对照

本轮共改名 18 个生产文件，目录不变：

| 目录 | 原名 | 当前名 | 命名依据 |
| --- | --- | --- | --- |
| `app/motor/` | `motor_control.cpp/.h` | `motor_application.cpp/.h` | 产品业务编排，不是底层电流环；与既有 `motor_application.hpp` 共用词干 |
| `app/motor/` | `bus_scheduler.cpp/.hpp` | `can_bus_scheduler.cpp/.hpp` | 说明是 CAN 总线预算和发送选择，不是 RTOS 任务调度 |
| `app/motor/` | `parameter_transactions.cpp/.hpp` | `encos_parameter_transactions.cpp/.hpp` | 明确仍为 ENCOS 参数、查询和维护兼容路径，不冒充通用参数模型 |
| `app/motor/cfg/` | `motor_control.hpp` | `motor_policy.hpp` | 工程时序、预算与容量策略，与业务接口名区分 |
| `app/cycle/` | `cycle_runtime.c/.h` | `ethercat_cycle.c/.h` | EtherCAT 同步、截止与 SSC 周期编排，不再创建 RTOS 任务 |
| `app/cycle/cfg/` | `runtime_config.h` | `ethercat_cycle_policy.h` | 当前为延后 SSC Tick 上限，避免与任务资源配置混淆 |
| `app/runtime/` | `app_runtime.c/.h` | `ethercat_can_task.c/.h` | 实际拥有 EtherCAT/CAN 唯一业务任务、通知和致命错误处理 |
| `app/runtime/cfg/` | `rtos_config.h` | `ethercat_can_task_config.h` | 只配置该任务的栈、优先级及水位检查，不冒充整个内核配置 |
| `bsp/dcu_hpm5e31/` | `cycle_hardware.c/.h` | `cycle_timers.c/.h` | 实际只管理微秒时钟和唤醒定时器，不笼统涵盖全部周期硬件 |
| `bsp/dcu_hpm5e31/cfg/` | `cycle_board.h` | `cycle_timer_map.h` | 明确 GPTMR 通道、时钟和 IRQ 的板级资源映射 |
| `comm/canfd/` | `tx_guard.c` | `can_tx_gate.c` | CAN 发送禁止门控，不是互斥锁或通用保护器 |
| `comm/ethercat/` | `digital_io.c` | `ethercat_callbacks.c` | 当前实现产品 APPL 回调，不再是数字量示例 |

上述目录均相对 `firmware/`。`motor_application.h` 是 C 入口，`.hpp` 是同一实现的 C++ 业务操作接口，`.cpp` 是实现；没有增加另一份状态或逐函数转发实现。`motor_control_*` 等已有函数名及 C++ 命名空间保留，不要求文件改名时同步破坏现有调用契约。

## 保留的名称

`digital_io.h` 保留：SSC 的 `coeappl.c`、`ecatappl.c`、`ecatslv.c` 三处直接包含它。仅为改名修改第三方，或新建一个旧名转发头，都没有本轮必要性。因此只更名实际回调实现，不增加兼容副本。

`digital_ioObjects.h`、`gatewayObjects.h`、`eeprom.h` 等生成物、SSC/SDK 文件及 `DEVICE_NAME` 不改。`pdo_pipeline`、`motor_pdo_codec`、`motor_pdo_layout`、`motor_dictionary`、`motor_driver_binding` 已能说明职责，不为统一前缀机械改名。文档继续使用中文文件名。

## 构建与资源

改名前分别清理 Debug/Release 的旧构建产物，再通过统一 CLI 重新配置和完整构建，避免 SDK 的 `ar crD` 留下旧归档成员。不把仅增量编译成功当作重命名完成的证据。

```bash
# 此两条在移动旧源码前执行。
cmake --build --preset hpm-debug --target clean
cmake --build --preset hpm-release --target clean
# 改名及更新清单后执行。
python3 scripts/dcu.py build --preset hpm-debug
python3 scripts/dcu.py build --preset hpm-release
PYTHONPATH=/tmp/dcu-rtos-audit-deps python3 scripts/dcu.py test
PYTHONPATH=/tmp/dcu-rtos-audit-deps ctest --preset hpm-debug
python3 scripts/dcu.py test
DCU_HOST_SANITIZE=1 ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  python3 -m unittest discover -s tests/host -p test_motor_application.py -v
git diff --check
```

可选测试依赖的安装见[环境准备](../当前说明/环境依赖与外部资源准备.md)。改名后两种配置仍为 94 个生产编译单元，其中 11 个 C++，镜像保护通过。

| 配置 | FLASH 链接占用 | ILM | DLM | AXI SRAM | AHB SRAM | 擦除范围，右端不含 |
| --- | --- | --- | --- | --- | --- | --- |
| Debug | 330784 B | 18888 B | 35232 B | 129840 B | 10240 B | `0x80000000..0x80060000` |
| Release | 298984 B | 22344 B | 35232 B | 129840 B | 10240 B | `0x80000000..0x80058000` |

相对改名前，Debug FLASH 不变，Release 增加 8 B，RAM 占用不变。源码路径会进入 `__FILE__` 和调试信息，不能把文件改名等同于 ELF 逐字节不变。镜像检查的 `hardware_geometry_verified=false`，没有重新探测实物。

本轮不新增硬件验收结论：旧字典兼容耦合、1 us 锁存抖动、任务最坏耗时、反馈年龄及物理停止的边界均同[职责拆分记录](2026-11-16-应用层职责拆分与事务修复记录.md)。持续命名约定见[目录职责说明](../当前说明/目录层级与维护职责.md)。
