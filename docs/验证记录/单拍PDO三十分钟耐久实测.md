## 停止原因

按命令序号对齐主站 CSV、同帧 FRMW、HPM 接收及发布环形日志和首次缺拍快照。故障拍为命令 **1364947**，不是后一拍才出现的 WKC 下降。

| 时间点 | 故障前 32 拍中位数 | 故障拍 |
| --- | ---: | ---: |
| RK 发 SM2 调用相对本拍起点 | +5.741 µs | **+62.831 µs** |
| SM2 帧首距 HPM 下一 Sync0 的提前量 | 217.858 µs | 160.578 µs |
| HPM 开始 ESC 读取时距 Sync0 | 139 µs | **82 µs** |
| HPM ESC 读取耗时 | 113 µs | **119 µs** |
| RxPDO 槽提交完成打点相对 Sync0 | −22 µs | **+41 µs** |
| RK 发 SM3 调用相对 +870 µs | +0.152 µs | +0.190 µs |

1. 命令 1364947 的 SM2 成功写到从站（WKC 1），但 ESC 读取结束已经晚于 Sync0 **37 µs**。首次缺拍快照记录槽仍在写；最后正常发布的 epoch 为 1364508，紧接的 epoch 1364509 置位 `RX_MISSING`，没有 `TX_LATE`。本拍 SM3 仍读到 1364946。
2. 下一拍 1364948，SM2 WKC 0、SM3 WKC 1、读回 0。IgH 在探针停用前记录写域变为 0/1；主站 AL 缓存仍是 OP。停用后 IgH 才打印 `SAFEOP + ERROR`，未在计分窗口单独打印 AL 码 `0x001A`。这次 HPM 的缺拍在停用**之前**，不能当作正常收尾产生的缺拍。
3. 本轮能定位到 **SM2 晚进入发送调用，消耗了 RxPDO 在 Sync0 前的准备余量**。故障拍的 SM2 调用比前 32 拍中位数晚 57.090 µs，同帧帧首的提前量也减少 57.280 µs。现在没有 SM2 唤醒返回、组帧、排队的独立时间戳，不能把全部差值归给 Linux 唤醒。7 拍反馈观察超时是另一类现象，不应归因到这次 `RX_MISSING`。
