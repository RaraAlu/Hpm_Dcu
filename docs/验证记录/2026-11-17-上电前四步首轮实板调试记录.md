## 中断与 CAN 配置

EtherCAT 初始化后，PLIC 使能字为 `0x00004800, 0xe0000000, 0x00000001, 0x00000000`。ESC/PDI、Sync0、Sync1、ESC Reset 的优先级分别为 4、5、3、2；GPTMR0 为 3，板级 GPTMR3 为 1，与当前配置一致。

CAN 初始化后，PLIC 第二个使能字变为 `0xe003c000`，四路 CAN 优先级均为 2。以上是寄存器配置检查，不代表所有中断已经实际触发。

`CCCR=0x300` 对应已离开 INIT、FD/BRS 配置启用；按软件预设 80 MHz 时钟解释，时序值对应仲裁段 1 Mbit/s、数据段 5 Mbit/s，不是线速实测。FIFO 配置对应 RX FIFO0 16 项、TX FIFO 8 项，数据槽 8 字节。Message RAM 基址为 `0xf0200000`，每路 2560 字节，共 10240 字节；各路起始偏移按 `0xa00` 分隔，所查 FIFO 地址互不重叠。

本轮未批量读取可能带有读副作用的状态寄存器，也没有执行 GDB 目标函数调用，不能将“初始化返回成功”扩展为“总线上没有任何错误”。

## 发现与限制

1. 当前 `board_can_transceiver_phy_set()` 是空实现，只丢弃 `ptr` 和 `enable` 参数。因此不能沿用“函数已调用，所以收发器已使能”的判断。可能由硬件常使能，也可能需要补接控制；本轮未查原理图或测引脚，不能直接判定为代码缺陷。首次物理收发前必须核对板级连接。
2. 探针报告 4.850 V，但本轮没有独立测量 VTref，也没有测量 CAN/PHY 电气波形。基础调试成功不等于电气条件验收。
3. 没有执行重复性复验、无探针冷启动、RTOS 调度、EtherCAT 主站状态切换、DC Sync0/PDO、CAN 对端收发、实时负载或电机停止测试。
4. 使用的是命令行 GDB 与项目受保护 OpenOCD 服务，没有验收 VS Code GUI、HPM 插件默认入口、SVD 或 RTOS 视图。
