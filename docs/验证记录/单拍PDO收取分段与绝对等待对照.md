# 单拍 PDO：收取分段与绝对等待对照

2026-11-19。1 kHz 空载、CPU6、FIFO 80、锁内存、RK 跟随 HPM。两组使用同一份 RK 探针二进制与同一 HPM 镜像。A 保留原 `sleep_until`；B **仅在 +975 µs 的 SM3 收取**使用 `clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME)`，遇 EINTR 重试原绝对时刻。两组 SM2 仍在 0 µs 发、SM3 在 +870 µs 发，准备提前量均为 50 µs，Sync0 +255 µs，构建保护仍为 600 µs。没有改 MCU、Profile、PDO 布局或生产 DriverModule，CAN 未参与。

## 实板结果

两组先分别通过 32/32，再分别执行连续 60,000 拍。没有补测、拼接或启动 30 分钟测试。表内时间单位均为 µs。

| 1 kHz、60 秒 | A：原等待 | B：绝对等待 |
| --- | ---: | ---: |
| N+1 按时通过 / 实测 | 60,000 / 60,000 | 59,999 / 60,000 |
| 正确序号、WKC 1/1、采到 OP / 首轮即收齐 | 60,000 / 60,000 | 60,000 / 60,000 |
| 等待返回相对 +975 的偏差：P50 / P99.9 / 最大 | 1.901 / 6.438 / 17.295 | 1.609 / 5.504 / 23.167 |
| IgH receive：P50 / P99.9 / 最大 | 4.083 / 4.667 / 6.708 | 3.792 / 4.667 / 5.542 |
| 域处理：P99.9 / 最大 | 0.584 / 0.875 | 0.584 / 0.875 |
| WKC 查询 / OP 核对：各自的最大 | 0.875 / 0.875 | 0.584 / 0.875 |
| 醒后至最终确认：P50 / P99.9 / 最大 | 5.541 / 6.125 / 7.875 | 5.250 / 5.834 / 7.583 |
| 最小 N+1 余量 | +2.413 | **−3.741** |

**本次失败在等待返回段。** B 的命令 35004 已在 +873.623 进入等待，SM3 发送并不迟（+870.123）。目标 +975，RK 到 +998.167 才从等待返回，晚 **23.167**。这时到已冻结的下一拍起点 +999.967 只剩 **1.800**；此前 32 个正常拍中位数，完成醒后处理就需要 **5.250**。

该拍首轮 receive 用 4.083，域处理用 0.583，WKC 查询用 0.292；到 +1003.125 确认 WKC 和回显 35004 匹配，到 +1003.708 才核完 OP。醒后合计 5.541，不是处理尖峰，最终超期 **3.741**。下一拍的 SM2 因此在 +6.075 才调用发送，但该拍自身仍按时通过。A 的最差拍 3784 也主要晚在等待返回（17.295），醒后处理 5.250，仍剩 2.413。

绝对等待在这次样本中的中位数和 P99.9 较低，但没有保证按时返回，不能据此替换生产等待策略。此处观测的是用户态线程返回时刻，不是内核定时器触发或物理帧到达时刻；也不能用这 60 秒倒推[历史 29:40 的尖峰](单拍PDO主站SM2与SM3提前准备三十分钟实测.md)。

## 打点与验证

- [单拍收取](../../tests/host/ethercat_data/one_cycle_pdo.hpp)：记录等待入口及返回、首轮 receive 起止、域处理和 WKC 查询结束；若重试，分别累计三段时间并记次数。不重排或重发数据报。在 AL 查询之前从稳定的输入镜像检查序号，仅在两个 WKC 正确、输入域 COMPLETE 时记匹配时间。所有 OP 核对和原本的最终读回完成后才取验收时间，仍使用冻结的 N+1 截止。没有用提前打点把迟到算通过。未观察到有效事件用 0 表示；两个相同的非零时间戳不表示物理耗时为零。
- [离线故障注入](../../tests/host/ethercat_data/test_one_cycle_pdo.cpp)：分别注入 40 µs 晚醒、receive 延迟、域处理延迟，三者落在对应分段，按原截止都失败，下一拍均迟发 26 µs（模型值）。另覆盖首轮 WKC 不完整后重试、无 WKC、错序号、非 OP、回显虽早但 OP 核对逾期。相关两组主机测试共 19 项通过。
- 核对原镜像及 SII 和启动日志后，直接恢复旧停核现场时只读 SDO 未响应；预检在 OP / 计分前退出，[日志单独保留](../../artifacts/target/pdo-collect-ab-20261119-6UkBLZ/preflight-resume-sdo-failed.log)。正常复位同一镜像后，四次计分的启动编号均为 114。各组前后只读 Profile 一致；结束时 IgH Idle、从站 PREOP、HPM 恢复暂停。SII 回读一致，旧启动编号保留；未烧录、未初始化或擦除日志。
