# 五轴周期布局热重载实板验证

授权范围为停稳、动力隔离的五轴台架，保留 CAN2 的四台 ENCOS 和 CAN3 的一台 HRA55H-100。在 RK 空闲、HPM 为 PREOP 时安装生产 Release 固件；随后不复位 HPM，在 PREOP 提交一次完整的五轴拓扑。没有进 OP，没有发送使能、MIT 或运动指令，也没有运行周期验收。

| 核对项 | 首次读取 | 提交后独立进程重读 |
| --- | --- | --- |
| HPM boot ID | `0x0000013f00000000` | `0x0000013f00000000` |
| 拓扑代数 | 0 | 1 |
| 通道 / 物理轴掩码 | `0x0c` / `0x0023c000` | 相同 |
| SM2 / SM3 映射长度 | 216 / 256 B | 216 / 256 B |
| RK 已登记的 IgH 域 | 472 B | 472 B |

RK 从 HPM 回读两方向的 assignment 及每个 PDO 字段，再用新建的 domain 独立登记偏移。HPM 的路由对象 `30E0/30F0/3100/3110/3150:01` 分别读到 `1/2/3/4/2`，对应 CAN2 槽 14 至 17 和 CAN3 槽 21。这是 DCU 已应用的配置，不代表五台电机的实时应答或 N+1 反馈。最终 HPM `PREOP +`，IgH `Phase: Idle, Active: no`。

固件预设为 `hpm-release-five-axis`，镜像 SHA-256 为 `99be6a3dd4fcc1c94d85263f7b9ae85e4e2c1d0a31b0f4b90babad46c61fc4a9`。第一次刷写在擦除前因复位追加启动日志而被保护检查中止；保留原备份，按标准复位后备份流程写入并通过镜像、保留 EEPROM 和启动日志校验。审计目录为 `artifacts/target/20261123T072942.737186Z`、`artifacts/target/20261123T073122.204584Z`。

RK 的管理程序和五轴 YAML 已安装在 `~/.local/share/dcu/cyclic-profile/48b232794e62-five-axis/`。从该目录以 `python3 apply_cyclic_profile.py --catalogue 五轴台架配置.yaml --profile 五轴台架配置.yaml --client ./select` 只读复核通过。没有替换或启动独立 DriverModule 服务。

离线用相同五轴目录移除 CAN2 ID 2，得到 192 / 224 B，ID 3 的对象索引未移位，撤掉的轴不再收到查询；恢复后回到 216 / 256 B。另测只保留 CAN2，得到 184 / 216 B。相同长度但轴号错误、未退休的 CAN TX、旧代数、旧命令及不相符的 Profile 均有拒绝或清除覆盖。实板未为验证而移除任何轴。
