# 生产线程四轴单拍收发相位对照

**结果：CAN2 的四帧全零 MIT 均已发送，四轴结果出现在 N+2，不在 N+1。** 此次 N+1 经过从站时，相对于本拍锁存所用 Sync0 的时间比旧成功样本早约 708 µs。RK 晚些时候调用 receive，并不会重新读取从站 SM3。

## 两次时间线

下表以各自命令帧之后的首个 Sync0 为零点，单位 µs。帧到达取本次交换的 DC 参考钟 FRMW 时标，不是直接采到的 SM3 访存或 Sync0 引脚边沿；RK API 时标另列，不跨时钟直接相减。

| DC 事件 | 旧探针成功样本 | 本次生产线程 |
|---|---:|---:|
| 命令帧 N 到站 | 272，−338.055 | 314，−1037.496 |
| Sync0 网格 | 0 | 0 |
| N+1 到站，读 SM3 | 273，+1662.025，回显 272，四轴新 | 315，+954.101，回显 313，四轴均非本拍新反馈 |
| N+2 到站，读 SM3 | 未计分 | 316，+3007.018，回显 314，四轴均新 |

本次 314/315/316 读回的发布号依次为 5581307、5581308、5581309，WKC 均为 3，各占一个主站发送帧。315 读的不是与 314 完全相同的 SM3，而是**更新了发布号、命令回显仍落后一拍**的 SM3。315、316 只带停止输出，没有第二拍 MIT。

按 RK 单调时钟，各自以命令帧进入 send 为零点：旧路径 N+1 发/收为 +1999.915/+2553.486 µs；生产线程 N+1 发/收为 +1991.243/+3987.444 µs。旧路径在同一周期回收发出的帧；生产线程在下一次 tick 开头回收上一帧。**决定 SM3 内容的是帧经过从站的时刻，不是 RK 的 domain_process 返回时刻。**

## 相位依据

- 旧样本：读取[已通过的原始 CSV](../../artifacts/target/can2-pdo-only.PUxGpSBo/once.csv)。命令帧的 DC 网格低位 537295878，加当次配置的 375000 ns，得到 Sync0 参照 537670878；两帧 FRMW 分别为 537332823、539332903。原探针对到站相位有闭环跟随。
- 新样本：生产线程在 OP 启动期通过两笔只读请求取 ESC 系统时间和 DC 定时寄存器；在命令窗口不再排入寄存器读请求。0x0990 回读 99942070690288 ns，0x09a0 回读 2000000 ns；用 0x0910 的 64 位时标解开 FRMW 低 32 位回卷，本拍对应的 Sync0 网格时刻为 99942208690288 ns。生产配置 Sync0 shift 为 0，使用原 472 B 非重叠域，SM2/SM3 偏移 0/216。未修改同步算法。
- 对照[固件发布期限](../../firmware/app/cycle/pdo_pipeline.c)：此配置下四轴本拍反馈收齐即可发布，最迟提交时间为 Sync0 +1600 µs。成功样本的 N+1 在该期限之后约 62 µs；生产样本反而在该期限之前约 646 µs 经过从站。故当前 RK 相位没有给 HPM 留出约定的完整处理窗口。本次没有 MCU 内部 SM3 写入时标，不能把这 708 µs 解释成 CAN 或固件变慢了 708 µs。

## 采集边界

历史[312 故障日志](../../artifacts/target/can2-driver-phase-20261123/原312.log)只有期望 312、回显 311，没有对应的逐帧 DC 时标。314 是同一现象的新样本，不是给历史 312 补造时间戳。

本次从原 build 启动脚本加载临时采集版生产模块。仅替换私有包内的传输对象以记录时标，沿用原 DriverTick、IgH 调用顺序、调度、映射和打包；未覆盖部署包或改 HPM。生产线程在内存记录，释放主站后落盘，没有独立周期线程。只申请一拍，不跑长测。四轴 TX 完成计数均为 546→547，CAN3 仍为 0；boot ID 0x14400000000、拓扑代数 0 未变。最终 PREOP，主站 Idle/inactive。
