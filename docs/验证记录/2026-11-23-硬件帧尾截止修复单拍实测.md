# 硬件帧尾截止修复单拍实测

修复 HPM 生产接收路径，沿用[上一拍的时标](2026-11-23-动态提前量四轴首拍实测.md)进行对照。保留 Profile、RK 生产包、同路 TX EOF 后 100 µs 最小间隔、反馈帧尾 +1300 µs 和 SM3 +1600 µs 截止。CAN 中断入队后可唤醒原有 worker；在反馈截止后只处理已到帧，不补发未发送的轴，不把软件缺失掩码直接当成硬件到达判据。

空载 67 个 SM2 样本均在 Sync0 前就绪（214～315 µs），所有轴 TX 增量为 0。随后由 RK 构建目录的 `driver_module` 发 CAN2 ID 1～4 各一条全零 MIT，未使用测试线程。主站退出后才用 J-Link 读取一致快照。

## 单拍结果

命令 1468，HPM epoch 63。以本拍 Sync0 为零点：

| 项目 | 现场结果 |
| --- | --- |
| SM2 就绪 / 周期 worker 开始 | −248 / +7 µs |
| ID 1 / 2 / 3 / 4 TX 请求时标 | +484 / +724 / +1008 / +1270 µs |
| ID 4 硬件 TX EOF | +1308.65～1313.65 µs |
| ID 4 硬件 RX EOF | +1370.565～1375.565 µs，距 TX EOF 61.915 µs |
| ID 4 出队 / 周期校验 | +1418 / +1422 µs；拒绝原因 7，即 `DCU_FIRST_RX_CUTOFF` |
| 结果 | ID 1～3 匹配，ID 4 晚到；故障掩码 0x10，无本拍 SM3 提交 |
| N+1 | 实际回显 1467，预期 1468；1 拍发送、0 拍完整匹配、RK 调度跳拍 0 |

硬件时标用 CAN ATB 和两侧 GPTMR 读数换算，包含 1 µs 取整边界。上一拍是按时到达却未及时出队；这一次不是同样的故障：**第 4 条命令的帧尾本身就已经晚于反馈截止，其回包实际迟了约 71～76 µs。** 与下条请求记录对齐，三个“上一 TX EOF 到下一 TX 请求后时标”的间隔约为 195～200、239～244、216～221 µs；这些不是总线分析仪测得的空闲间隔。优先排查首发前 484 µs 和三个帧间超过 100 µs 门限之后的调度等待。带时标单拍不是抖动或最坏耗时保证。

CAN2 TX 增量各 1，CAN3 为 0；未重试、未跑 60 秒。最终 HPM PREOP、RK Idle。上板带时标 ELF SHA-256：`d2b1b5e416fc8079029190261d720c53e7286e474b417d1a8824f14aded44c97`。
