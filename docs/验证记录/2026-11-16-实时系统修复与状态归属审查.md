## 已修复问题

### 优先级屏蔽状态未随上下文恢复

实际构建启用了 `USE_SYSCALL_INTERRUPT_PRIORITY=1`。HPM 移植的临界区会修改 CSR `mie` 和 PLIC threshold，但原上下文只保存临界区嵌套计数等状态，未保存这两个硬件屏蔽值。`ulTaskNotifyTake()` 在临界区内通过 ecall 阻塞，切到 Idle 后可能继承屏蔽；创建静态任务后的屏蔽值也可能进入首次任务启动。这不是仅凭编译能排除的问题。

修复位于配套移植的 [HPM 上下文扩展](../../third_party/hpm_sdk/middleware/FreeRTOS/Source/portable/GCC/RISC-V/chip_specific_extensions/HPMicro/freertos_risc_v_chip_specific_extensions.h)与[上下文汇编](../../third_party/hpm_sdk/middleware/FreeRTOS/Source/portable/GCC/RISC-V/portASM.S)：

- 为任务和嵌套 ISR 保存、恢复 `mie` 与 PLIC threshold，额外使用 16 B，保持栈对齐。
- 新任务初始化为正常内核 IRQ 使能和 threshold 0；恢复被打断的临界区时则保留原屏蔽值，不能一律清零。
- 没有整体升级 SDK，没有用通用 RISC-V 端口替换 HPM 专用启动和中断实现。

实际 SDK 构建设置了 `CONFIG_DISABLE_GLOBAL_IRQ_ON_STARTUP=1`；不把“启动前全局中断已打开”列为本工程已确认缺陷。

### 故障门控与 CAN 最终提交之间有竞态

原发送路径先检查 TX 禁止位，再进入“填写 FIFO 并提交”的 SDK 函数。故障定时器可能在两者之间设置禁止位并取消排队，随后任务恢复执行又提交新请求。只屏蔽该路 CAN IRQ 并不能屏蔽故障定时器。

[发送适配](../../firmware/comm/canfd/ethercat_canfd_gateway.c)现在先暂存帧，在短内核临界区内完成“重查门控、写完成标签、提交 TX 请求”。整帧复制不在该临界区内；Sync0/PDI 的优先级高于内核屏蔽边界，仍可抢占。交错结果只有两种：故障先发生则不提交，提交先发生则由随后故障取消排队。已经上总线的帧不保证可撤回。

该拆分对应当前 HPM5E31 的 SDK 路径。若未来启用 `CAN_SOC_TX_RX_BUFFER_ACCESS_WORKAROUND=1`，编译明确拒绝，须先补齐该芯片的勘误流程，不能静默绕过。

电机对象访问的 `OD/STATE/DIAG/BASE` 函数式宏已替换为有类型的函数或 `constexpr`。公开 `mc_object()` 仍为未知对象返回空指针，CoE 访问仍返回原有 abort；内部固定对象访问依赖生成字典完整这一既有约束，并不是任意索引的安全查询器。

## 静态状态审查

静态分配不是本身的缺陷。本工程任务栈、三缓冲和每轴设备实例需要稳定生命周期及确定的容量；移到 8 KiB 任务栈或改成动态申请都会引入额外风险。真正需要修正的是可变状态散落、所有者不清和把 `volatile` 当同步手段。

| 对象 | 归属与并发规则 | Debug ELF 对象大小 |
| --- | --- | --- |
| `pipeline` | DLM 三缓冲；PDI 生产、Sync0 锁存、任务消费，32 位原子交接；配置重置仅在停止输出时 | 2460 B，段对齐后 2464 B |
| `worker_task` | TCB、句柄、对齐静态任务栈，创建后由内核使用 | 8288 B，其中栈 8192 B |
| `handoff` | ISR/任务共享事件、禁止位和 PDO 暂存序号；访问均使用原子操作 | 20 B |
| `runtime` | 业务任务私有的配置/运行标志及水位检查时间 | 8 B |
| 电机 `state` | 收拢为私有 `MotorControlState`；SDO、SSC 后台、电机调度同属 `ecat-can` 任务 | 10116 B |
| 每轴 ENCOS 驱动实例 | 产品绑定模块的私有静态数组，逐轴配置，不是 ISR 共享业务状态 | 4704 B |
| 周期诊断 | 面向调试观察的 `volatile` 对象，不用它作为同步协议或一致性快照 | 36 B |

上述大小来自当前 RV32 Debug ELF 的 `nm -S`，不是跨平台 `sizeof` 承诺。电机状态仍在 BSS；非零初值放到初始化函数，避免将整个约 10 KiB 对象变成 Flash 初始化数据。没有新增动态分配，也没有在任务栈上构造同等大小的临时状态。

移除任务私有标志的 `volatile`，保留必要硬件/诊断用途。未把单任务数据全部加锁；ISR 继续只经 PDO/CAN 交接进入业务。公共头注明调用上下文，删除未使用的 `motor_control_background()` 转发接口，将超时检查收为内部函数。运行中调用重新配置会明确拒绝，不重置活动流水线。

### 仍有的设计成本

`motor_control.cpp` 仍把会话/启动、PDO 打包、CAN 调度、参数事务和 CoE 访问放在一个较大的实现文件中。状态集中只解决归属和重复配置，**不等于这些职责已经解耦**。目前不把它改成大量小型透传类，也不重写安全状态机；后续拆分应围绕会话、调度和参数事务建立行为测试后分别推进。

100 us 响应保护、800 us/ms 预算以及 `frame_us()` 的公式仍是工程估计，不是实测总线占用。200–1000 Hz 是 PDO 同步范围，不等于四路全轴的实际命令和反馈都能在 1 ms 内完成。
