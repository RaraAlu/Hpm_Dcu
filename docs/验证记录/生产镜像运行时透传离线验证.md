## 离线结果

- `cmake --build --preset hpm-debug --target check-image`、`hpm-release` 同目标均通过。两者均取生产 CAN 配置，没有启用回环或网关测试预设。Release 的 `build/hpm-release/output/dcu.bin` SHA-256：`4f9f2b11869a19aa02680373c36267739a3094b42abf27d3b4836e83297a4f4d`。
- `python3 -m unittest discover -s tests/host`：405 项通过，0 失败、0 跳过；使用本机缓存的 Unicorn 2.1.4。指定头文件归属测试 7 项通过；协议生成只读一致性检查通过。
- 生产 YAML 不改动：CAN3（通道索引 3）、一台 HRA55H-100（ID 0x02）、默认配额全零。宿主从真实生产配置初始化，经 CoE、实际 mapping、网关和模拟 CAN 端口：未授权不收发；授权 1 后同窗第二帧被拒，64 B 下行和模拟外设返回的 64 B 上行逐字节相同，电机 ID 仍拒发。
- OP / SAFEOP 禁写，未退休槽禁写，越界和未启用通道拒绝；回切恢复 784/1072 B、原电机槽与角色。旧使能不建立会话，新基线后跳过 ARM 也不发，新的 ARM + 启动边沿才发出原 16 B MIT 命令。另用有就绪探测的电机配置覆盖两种纯透传档：取消在途探测、纯档不轮询、回切后重新取证。
- 不切档的两个独立宿主进程分别使用默认配额、非零运行时配额，驱动同一个生产电机周期；比较完整 784 B SM2、1072 B SM3 和 16 B MIT 发送载荷，完全一致。旧映射、ESI/SII 契约和原有电机回归亦通过。未测量目标 CPU 耗时。

## 必须上板确认

在 RK 已支持该档且由操作者确认停车后，验证实际 IgH 重配、ESC 的 SM 长度/站址、域偏移与 WKC，CAN3 外部 FD 对端的真实 64 B 请求/应答（不是本机回环），以及 2 ms 连续运行的丢帧、迟到、最坏抖动和故障恢复。还需在可控条件下确认总线撤销终态、切档期间无电机命令、回切不自启动。宿主结果不能证明现场停车、CAN 仲裁时序或物理往返。
