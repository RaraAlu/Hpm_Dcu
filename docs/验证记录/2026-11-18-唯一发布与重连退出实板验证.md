# 唯一发布与重连退出验证

在 OP 入口暂存 SSC 的 Sync0 自动 TxPDO 锁存设置并将其关闭，唯一的周期发布由应用任务在既定窗口调用 SSC 的 `PDO_InputMapping()`。SSC 的 Sync0 看门狗和 SM 顺序检查仍运行；退出 OP 后恢复 SSC 的自动锁存，SAFEOP 和初始发布走原路径。若打包结束时已过截止或切换到下一拍，不再开始一次 ESC 写入。

未改 CAN 收发、Profile、PDO/SDO 线布局、Sync0 相位、600 µs 准备预算或 250 µs 发布提前量。离线测试模拟 SSC 的自动锁存：修前断言在 OP 第一次 Sync0 已发生重复写入，修后窗口内只写一次；退出 OP 后恢复 SSC 写入。还验证打包完成时已经超期则不启动 ESC 写入。

新增首次缺帧锁存信息：当时的 Sync0 和周期、上一次 PDI 槽提交完成时间、PDI 通知应用后复制是否正在进行，以及任务处理故障前的 AL 状态。主站另外记录应用发送时间，并在故障后仍保持零使能流量时读取 AL 状态与状态码，避免把探针关闭后产生的二次故障当成首次故障。RK3588 和 MCU 的时间戳各是本机时钟，未校准成同一物理时基。

测试仅覆盖空载台架，探针优雅退出用 IgH 的 `ecrt_master_deactivate_slaves()` 并保持循环收发到 PREOP；断流对照在 OP 下故意停发四拍，保持主站会话不释放。

| 场景 | 实板结果 |
| --- | --- |
| 4 ms 正常退出和重连 | 连续 4 轮，每轮 1000 帧，WKC 为 2，应答最大滞后 3 拍。每次到 PREOP 的 AL 状态码为 0，读回周期故障位为 0。最后一轮打包到发布完成最长 169 µs。 |
| 1 ms 正常退出和重连 | 连续 3 轮，每轮 4000 帧，WKC 为 2，应答最大滞后 3 拍。每次到 PREOP 的 AL 状态码为 0，读回周期故障位为 0。最后一轮打包到发布完成最长 465 µs。 |
| 4 ms 突然断流 | OP 持续 200 帧后，停发 4 拍。释放前读到 AL 状态 `0x0014`、同步错误码 `0x001A`。MCU 捕捉到首个缺帧在第 211 拍，当时应用的 RxPDO 槽位复制未在进行，上一次槽提交距该 Sync0 为 7472 µs，任务在该 Sync0 后 25 µs 开始处理故障。 |
| 断流后的立即重连 | 同一次 MCU 启动内，Profile 保留，WKC 恢复为 2，但仍停在 SAFEOP（AL `0x0004`、状态码 0），未进入 OP；缺帧快照仍是断流时的旧记录，不是新的缺帧。 |

上述结果区分了正常退出与断流保护，不证明上轮每次 WKC 下降都由断流造成。后续应定位异常后的 SAFEOP→OP 为什么没有完成，并在生产主站接入同样的正常退出流程；未修改生产 DriverModule。

异常后经 PREOP 重新进入 OP 的修复结果见[断流后运行态恢复验证](2026-11-18-断流后运行态恢复验证.md)。
