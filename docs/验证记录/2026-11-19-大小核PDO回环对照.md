# 大小核 PDO 回环对照

在同一 RK3588、同一 HPM、同一 IgH 专口上，对比 CPU2（Cortex-A55）和 CPU4（Cortex-A76）。CPU0–3、CPU4–5 和 CPU6–7 是三组频率策略；本轮只测 CPU2 和 CPU4，不拿已隔离的 CPU6–7 混作大小核对照。两组均为 `performance`，试验前读取到的频率分别为 1.800 GHz 和 2.256 GHz，不调整频率或中断亲和性。

同一探针依次用 FIFO 80、单核绑定和锁内存跑 60 秒、1 kHz，按 HPM 接受序号确认每条零使能 PDO。保持原睡眠、DC 更新和收发顺序，开启相同的 IgH 接收分段计时，不开提前唤醒和线程切换快照。各自额外收 24 拍在途反馈，不计这 24 拍新发送的命令。不接 CAN，不改 Profile、PDO 布局或固件。

| 指标 | CPU2（A55） | CPU4（A76） |
| --- | ---: | ---: |
| 回显 / 发送 | 59709 / 60000 | 60000 / 60000 |
| 未观察到的回显 | 291 | 0 |
| `ecrt_master_receive()` 中位耗时 | 10.792 µs | 5.250 µs |
| 连续回显间隔 P99.9 绝对偏差 | 16.458 µs | 6.833 µs |
| 连续回显间隔最大绝对偏差 | 36.000 µs | 10.625 µs |
| 整轮（含回显缺口）最大完成间隔 | 2006.374 µs | 1010.625 µs |
| 最大唤醒迟到 | 33.798 µs | 8.997 µs |

CPU2 有 291 次读到重复的回显序号，所有 WKC 仍为 2；这说明主站没有观察到每个新反馈，不等同于确认网线丢包。缺口多数在前 6 秒，但之后也有，不能当成纯预热现象。小核最坏的连续回显间隔偏差为 +36.000 µs，其中接收调用贡献 +32.666 µs，唤醒相位贡献 +3.041 µs。

这次台架对照保留 CPU4；两边都不满足全程 ±1 µs。结论只覆盖当前板上的 CPU2 和 CPU4 配置，不代表所有小核。两轮都正常退出到 PREOP、IgH Idle，Profile 前后读回一致；没有更改生产绑核配置。
