# 断流后运行态恢复验证

## 根因和修复

旧镜像断流后外部 AL 已回到 PREOP，但实板回读 SSC 内部错误仍为 `SAFEOP / 0x001A`，且无 AL 转换在等待。SSC 的 `StartOutputHandler()` 会因该内部错误拒绝后续 OP；外部错误指示清掉并不等于内部错误消失。

周期模块只跟踪自己报给 SSC 的同步错误。已回到 PREOP/INIT，或主站在 SAFEOP 执行正常错误确认后，且 SSC 没有待完成的状态转换，才调用 SSC 的无错误接口释放本地锁存。不写 AL 寄存器、不替主站确认、不强制进入 OP、不解除断流后的业务门，也不放宽 600 µs 保护。其他错误保持原样；重连沿用原 Profile，仍需普通零使能 PDO 才建立新命令基线。

离线用例在修复前复现了 PREOP 内本地错误未清除；修复后通过，并覆盖 SAFEOP 未确认、转换待完成和非本模块错误不被清理。全量主机回归 346 项（341 通过、5 跳过），Debug 和 Release 构建通过。

## 实板结果

| 场景 | 结果 |
| --- | --- |
| 4 ms 断流、重连 | 连续 3 组。每次停发 4 拍仍触发 `SAFEOP+ERROR / 0x001A`，然后在同一 MCU 启动内重新进入 OP；每次重连后通过 1000 个普通零使能 PDO，WKC 为 2。 |
| 1 ms 断流、重连 | 1 组。同样触发 `SAFEOP+ERROR / 0x001A`，重连后通过 4000 个普通零使能 PDO，WKC 为 2，应答最大滞后 3 拍，发布段合计最长 466 µs。 |
| 保持策略和状态隔离 | 启动代次全程为 63、Profile ID/版本为 1/1。进 OP 后首次零使能前的应答始终为 0；最后读回 SSC 本地错误为 0、累计清除 4 次。 |

实板通过的是主站释放后经 PREOP 重新进入 OP 的路径；SAFEOP 原地错误确认仅离线覆盖。使用独立 IgH 探针，没有部署生产 DriverModule，电机动力隔离、CAN 无业务节点，未做物理拔线。结束后 IgH 为 Idle，从站在 PREOP，保留新版并由 J-Link 暂停。SII 回读一致，启动日志保留旧记录并递增到 63。
