# 单拍 PDO 时序预算与写入优化

复用 [32 位读取实测](单拍PDO字读实板对照.md) 的 8 条 HPM 轨迹和首条严格验收记录。主站一拍 1000 µs；第 N 拍发出命令，必须在第 N+1 拍边界前读回同一序号、双向 WKC 达标且从站仍在 OP。上轮严格验收的首条命令 4848 实际读回 4847，未通过。没有用旧反馈估算回环成功率。

| 事件 | 实测时间或现有约束 |
| --- | ---: |
| RxPDO 槽提交 | 相对第 N 拍起点 +242 至 +252 µs（估算，8 条） |
| Sync0 | 标称 +120 µs；实测相位约 +120 至 +121 µs |
| TxPDO 发布完成 | 相对实际锁存 Sync0 +318 至 +498 µs（HPM 本地，8 条） |
| TxPDO 发布截止 | 相对 Sync0 +750 µs，由周期减去 250 µs 提前量 |
| SM3 读请求 | 标称 +885 µs；实测调用 +894.282 µs |
| 主站读回 | +997.532 µs；从读请求调用到收回 103.250 µs，距验收边界仅 2.468 µs |

以 SM3 标称发出时刻作为保守的发布上界，而非未知的 ESC 实际取数时刻。只按这 8 条实测并假定移相后耗时不变，Sync0 候选区间为约 252–387 µs，不含端点，也没扣抖动余量。按固件允许的最晚发布时间，Sync0 既须晚于约 +252 µs，又须早于 +135 µs（885 − 750），无共同窗口，差约 117 µs。即使把读帧和返回开销都按零预算处理，Sync0 也必须早于 +250 µs 才能让固件允许的最晚发布落在 1 ms 内。本轮不改相位、不放宽 600 µs 构建预算或 +750 µs 截止。

诊断最大值并非同一拍：发布可开始后至实际进入发布路径最多 182 µs，其中可能包含命令处理和任务调度，不能全部归因于唤醒；ESC 写入最多 153 µs，是已经单独计时且耗时最长的执行操作，反馈打包最多 19 µs，SM2 读取最多 119 µs。本轮只优化 ESC 写入：每次预取四个对齐的源字，再按地址顺序逐个写入四个 32 位 ESC 字，不改读写宽度、末地址交接或不对齐回退路径。

对齐的 1072 字节 SSC 镜像，目标反汇编显示热循环从 268 次单字循环变成 67 次四字循环，循环体动态指令数由 1608 降为 737（不含循环首尾），但仍有同样的 268 次 MMIO 写。离线字节对照、旧序号及截止保护回归共 44 项通过，诊断固件构建和保留区检查通过。没有烧录；节省多少实际微秒、能否单拍通过，均尚未实测。不接 CAN，不改 Profile、PDO 布局或生产 DriverModule。
