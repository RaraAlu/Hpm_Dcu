# HPM EtherCAT/CANFD 板卡工程说明与功能验证

## 1. 工程用途

本工程由 HPMicro 官方 `ecat_io` EtherCAT 从站例程移植而来，目标硬件为采用 **HPM5E31、LQFP100** 的自研板卡。

工程当前的主要作用是验证：

- HPM5E31 LQFP100 的基础启动、时钟、调试串口和板级引脚配置；
- 两个 EtherCAT 物理端口及 EtherCAT Slave Controller（ESC）；
- Beckhoff SSC EtherCAT 从站协议栈的启动和状态切换；
- Flash 模拟 EtherCAT EEPROM；
- PA22 上的 `SYS_LED` 每 1000 ms 翻转一次；
- 四路 MCAN/CANFD 和对应收发指示灯的引脚定义。

> 当前工程还不是完整的 EtherCAT 转四路 CANFD 应用。四路 MCAN 已完成板级引脚和外设定义，但应用层尚未初始化 MCAN，也没有 CANFD 收发、协议解析或 EtherCAT/CANFD 数据转发代码。

## 2. 当前已经完成的移植

### 2.1 芯片和 SDK 工程

- 目标芯片：HPM5E31，LQFP100。
- 默认构建类型：`flash_xip`。
- 工程使用本地化 SDK：`hpm_sdk_localized_for_hpm5e00evk`。
- 目录名和构建板名仍保留 `hpm5e00evk`，这是为了兼容官方 SDK 本地化工程结构，并不表示实际硬件仍是官方 HPM5E00EVK。
- PinMux 工具配置文件：
  `hpm_sdk_localized_for_hpm5e00evk/boards/hpm5e00evk/tool_config.hpmpc`。

### 2.2 系统灯和调试串口

| 功能 | 引脚/配置 | 当前状态 |
| --- | --- | --- |
| SYS_LED | PA22，高电平点亮 | 启动后每 1000 ms 翻转一次 |
| 调试串口 TX | UART0_TX，PA00 | 已配置 |
| 调试串口 RX | UART0_RX，PA01 | 已配置 |
| 串口参数 | 115200、8 数据位、无校验、1 停止位 | 已配置 |
| JTAG | PA04～PA08 | 用于下载和调试 |

`SYS_LED` 每秒改变一次亮灭状态，因此完整的“亮一次 + 灭一次”周期约为 2 秒。

### 2.3 EtherCAT

- 启用了 EtherCAT Port 0 和 Port 1，Port 2 未启用；
- 已适配 ESC、NMII、MDC、MDIO、PHY 复位和 LINK 输入；
- 两个 PHY 共用 PB26 复位信号；
- LINK0、LINK1 分别使用 ESC 控制输入 7、8；
- 使用 Beckhoff SSC 从站协议栈；
- 使用片上 Flash 的 `0x80000` 偏移位置模拟 EtherCAT EEPROM；
- EEPROM 中产品码或修订号不匹配时，程序会根据工程内数据更新模拟 EEPROM。

当前 ESI 和 PDO 定义仍来自官方 `digital_io` 示例：

| 项目 | 值 |
| --- | --- |
| ESI 文件 | `SSC/ESI/ECAT_IO.xml` |
| 厂商名 | HPMicro |
| Vendor ID | `0x0048504D` |
| 设备名 | `digital_io` |
| Product Code | `0x00000001` |
| Revision | `0x00000001` |
| RxPDO | 0x1600，映射 0x7010:00 `OutputCounter`，32 位 |
| TxPDO | 0x1A00，映射 0x6000:00 `InputCounter`，32 位 |

自研板没有沿用官方开发板的拨码输入和输出灯，因此 `BOARD_ECAT_SUPPORT_DIGITAL_IO` 当前为 0：

- `InputCounter` 固定返回 0；
- 主站写入 `OutputCounter` 后不会驱动实际 GPIO；
- 仍可使用这两个 PDO 验证主站扫描、PDO 映射及进入 OP 状态，但不能用它们判断板载 I/O 是否正常。

### 2.4 四路 CANFD

| 通道 | TX | RX | TX 指示灯 | RX 指示灯 |
| --- | --- | --- | --- | --- |
| MCAN0 | PD00 | PD01 | PD02 | PC16 |
| MCAN1 | PD05 | PD04 | PD07 | PD06 |
| MCAN2 | PC08 | PC09 | PB29 | PB30 |
| MCAN3 | PC15 | PC14 | PC12 | PC11 |

CAN 收发指示灯均为低电平点亮。板级代码已经提供 `board_init_can_led_pins()`，但当前应用没有调用它；MCAN 外设也没有被应用初始化，所以刷入当前固件后 CAN 总线上不会主动出现报文，CAN 指示灯也不会随通信闪烁。

## 3. 编译和下载

### 3.1 使用 HPMicro VS Code 扩展

1. 用 VS Code 打开 `HPM_ethercat_canfd_encos_V1.0` 目录。
2. 在 HPMicro 工程工具中选择本工程，构建类型选择 `flash_xip`，配置选择 Debug。
3. 执行配置/生成工程，然后执行 Build。
4. 编译成功后，主要下载文件为：
   `hpm5e00evk_flash_xip_debug/output/demo.elf`。
5. 使用板卡 JTAG 接口连接调试器，通过 HPMicro 扩展或生成的 Segger Embedded Studio 工程下载并运行。

当前工程已经通过完整编译。若命令行环境与本机安装目录相同，也可在仓库根目录执行：

```powershell
& 'F:\HPMicro_develop\SDK\sdk_env_v1.12.1\tools\ninja\ninja.exe' -C '.\HPM_ethercat_canfd_encos_V1.0\hpm5e00evk_flash_xip_debug'
```

> 修改 `tool_config.hpmpc` 后，建议只重新生成 `pinmux.c` 和 `pinmux.h`。不要在尚未重新核对时钟树的情况下覆盖现有 `clock.c`、`clock.h`。

## 4. 推荐验证顺序

### 4.1 验证供电、下载和程序运行

1. 按硬件设计要求给板卡供电，下载 `demo.elf`。
2. 复位或重新上电。
3. 观察 PA22 对应的 `SYS_LED`。

通过标准：

- 固件能够正常下载并运行；
- `SYS_LED` 每 1 秒翻转一次；
- 调试器不会反复进入复位或异常中断。

如果 LED 不闪烁，依次检查 PA22 电平、LED 极性、焊接、供电和程序是否真正运行到 `main()`。

### 4.2 验证调试串口

1. 将 USB 转串口的 RX 接板卡 PA00（UART0_TX）。
2. TX 可接 PA01，地线必须共地。
3. 串口工具设置为 115200、8N1。
4. 板卡复位后观察输出。

正常启动时应看到：

```text
EtherCAT IO sample
```

如果随后出现：

```text
Init ESC peripheral and related devices(EEPROM/PHY) failed!
```

说明 CPU 和串口已经工作，但 ESC、PHY、MDIO、复位时序或 EEPROM 模拟初始化失败，应优先检查 EtherCAT 相关硬件和引脚。

### 4.3 验证 EtherCAT 物理链路

1. 将 EtherCAT 主站接到 Port 0。
2. 如需验证级联，将 Port 1 接到下一从站；只测单板时 Port 1 可以悬空。
3. 启动主站并观察网口 LINK/ACT 指示以及主站扫描结果。

通过标准：

- Port 0 插入主站网线后能够建立 Link；
- Port 1 接入下级设备后也能建立 Link；
- 主站能够扫描到本板，而不是显示丢帧或端口始终关闭。

若 Port 0 无 Link，优先检查 PHY 电源、25 MHz/参考时钟、PB26 复位、MDC/MDIO、网变和差分线。若只有一个端口异常，应重点对比该端口 NMII 信号和 LINK 输入极性。

### 4.4 验证 EtherCAT 从站协议

可使用 TwinCAT 或其他 EtherCAT 主站：

1. 把 `SSC/ESI/ECAT_IO.xml` 导入主站的 ESI 设备库。
2. 扫描 EtherCAT 网络，确认识别为 HPMicro `digital_io`。
3. 检查 Vendor ID、Product Code 和 Revision 是否与第 2.3 节一致。
4. 让从站依次进入 INIT、PREOP、SAFEOP、OP。
5. 查看 PDO，确认主站存在 32 位 `OutputCounter` 和 32 位 `InputCounter`。
6. 在 OP 状态周期写入不同的 `OutputCounter` 数值，并确认从站保持 OP、工作计数器正常且没有 AL 错误。

通过标准：

- 主站能稳定扫描到设备；
- 从站能够进入并保持 OP；
- PDO 映射与 ESI 一致；
- `InputCounter` 为 0 属于当前程序的预期行为；
- 写 `OutputCounter` 不引起实际输出变化也属于当前程序的预期行为。

首次运行或修改 ESI 身份信息后，模拟 EEPROM 可能需要更新。若主站读到旧的产品信息，可断电重启后重新扫描；仍不一致时再检查 Flash 模拟 EEPROM 区域及串口报错。

### 4.5 验证四路 CANFD

当前固件不能完成 CANFD 功能验收，因为没有 CAN 初始化和收发代码。不能把“CAN 引脚已配置”当成“CAN 通信已通过”。

后续加入 CAN 测试程序后，每个通道应分别执行：

1. 初始化对应 MCAN，设置仲裁段/数据段波特率和 CANFD 参数。
2. CANH、CANL 接 CANFD 分析仪或另一节点，并保证总线两端各有 120 Ω 终端电阻。
3. 周期发送标准帧、扩展帧和 CANFD+BRS 帧。
4. 检查分析仪能否正确接收，并从分析仪回发报文验证 MCU 接收。
5. 验证 TX/RX 指示灯是否随对应方向的报文闪烁。
6. 依次测试 MCAN0～MCAN3，避免只验证公共代码而漏掉单通道焊接或引脚问题。

每路至少满足以下条件才算通过：无 ACK/位错误、收发数据一致、连续运行无 Bus-Off、指示灯方向正确。

## 7. 下一步开发建议

下一阶段应先写一个独立的四路 CANFD 自发自收/分析仪测试程序，逐路确认硬件；全部通过后，再设计 EtherCAT PDO 或 CoE 对象与 CANFD 报文之间的数据结构和转发策略。这样能够先把硬件问题与网关协议问题分开定位。
