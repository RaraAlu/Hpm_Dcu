# 周期锁存与反馈发布契约

本页说明生产 DC Sync0 路径。可选的 SM2 事件模式不在同一会话同时运行；其事件基准见[单帧 LRW 与 SM2 事件模式](../验证记录/单帧LRW与SM2事件模式.md)。

| 时点 | 所有者 | 对数据的承诺 |
| --- | --- | --- |
| Sync0 之前 | PDI / SSC | 收齐 RxPDO 后原子发布待锁存槽。不发布半帧；任务正在读取的槽不可被写入者覆盖。 |
| Sync0 边沿 | 快速中断 | 锁存所属周期的完整槽，不解析设备命令、不发送 CAN、不调用 RTOS。边沿、锁存和应用执行不是同一时刻。 |
| 周期内 | 唯一业务任务 | 按顺序消费命令、处理 CAN 完成/接收事件并更新设备状态。接受序号不证明已发 CAN，更不证明设备已执行。 |
| 反馈窗口内 | 任务 / ESC | 构建完整 TxPDO，在截止前写完 SM3，供主站下一帧读取。只发布已解码反馈及真实有效位、年龄；本拍没有新反馈不能当作 N+1 成功。 |

主站配置 Sync0 周期，DC 路径支持范围 1–5 ms。当前[工程常量](../../firmware/cfg/cycle_config.h)为 50 µs 任务唤醒、600 µs 构建预算、默认 250 µs 发布提前量。实测镜像可以覆盖提前量，因此比较相位与余量必须标明构建配置。周期变更退出 OP 后重新配置；不在 OP 内热改或以放宽截止掩盖失败。

**严格电机反馈窗口与普通发布窗口不同。** 普通构建起点距 Sync0 为 `周期 − 发布提前量 − 构建预算`。要求本拍因果反馈的轴则按有效 TX EOF、同路更晚的有效 RX EOF、截止前到达及解码后的周期反馈计数增量匹配；全部必回轴匹配后才构建 SM3，截止提前量取配置值与 400 µs 的较大者。缺反馈和发布晚点分别记故障，不用旧数据补齐。

ENCOS 的预编码只发生在电机档。已处于 `Running` 的时间戳阻抗轴，只有同轴、同序号且命令字段全部匹配才复用预览帧；未命中时用本次校验编码所得帧。首次启动可能改发位置保持，仍按实际生效的启动命令选帧，不跳过限值和启动保护。编码成功、CAN 提交成功、TX 硬件完成和收到本拍反馈是四件不同的事。

`worker_max_us` 统计单次 `dcu_cycle_step()`，包括等待本拍反馈时的提前返回，不是整拍延迟。`CONFIG_CAN_BATCH_SAMPLE` 默认开启，控制逐轴时间戳采样，不控制真实 TX 完成计数或反馈匹配。代码路径变化不能代替实测耗时。

`SingleFd` 的 88/88 B 透传也可以用该 Sync0 锁存和发布窗口，不改变 `RawState`、PREOP 排空切换和通道所有权。RK 生产透传读取匹配的 `schedule_file`，用 2 ms 周期，确认 DC 相位锁定后才允许发 CAN。HPM 仍兼容显式选择 SM2 的老主站；RK 新路径不会在 DC 失败时回退到它。

透传收的是原始帧，不是轴反馈表。到窗口就发布已经收到的帧，不等电机回包，主站未读的 SM3 映像不被下一批覆盖；晚到帧参加之后的发布。空心跳不重发旧命令。`BatchSeq` 是发布序号，不是请求号。单请求、可区分回包时可测 N+k；不能据此声明通用透传保证逐轴 N+1。

[缓冲和锁存](../../firmware/app/cycle/pdo_pipeline.c)、[周期故障与发布](../../firmware/app/cycle/ethercat_cycle.c)和[RTOS 任务](../../firmware/app/runtime/ethercat_can_task.c)分别拥有状态。缺帧、覆盖、失步和发布晚点按周期故障处理；看门狗可先禁止新 TX，业务任务处理停止和 EtherCAT 状态。软件取消不能撤回已上总线的帧；任务停止或调试暂停不等于电机已经物理停止。

测量须区分 Sync0 硬件边沿间隔、从边沿到锁存的延迟及其抖动、Rx 提交余量、Tx 发布到下一帧的余量、RK 确认反馈的间隔。没有共同时间基准的两个时间戳不能直接相减。每个结果同时注明序号、周期、负载、采样位置和未执行拍；见[片内边沿捕获](../验证记录/2026-11-18-片内同步硬件捕获验证.md)和[单帧相位对照](../验证记录/单帧LRW的同步相位窗口实测.md)。
