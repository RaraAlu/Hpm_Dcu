# 配置文件归档规范

更新日期：2026-11-13。项目可迁移的配置文件放在其维护模块内的 `cfg/`，不再设置泛化的根 `config/`。固定工具入口保留原位置，第三方依赖不为统一外观而重排；旧历史归档已按后续清理要求删除。

## 当前归属

| 位置 | 文件与职责 | 消费入口 |
| --- | --- | --- |
| [firmware/cfg/](../../firmware/cfg/) | 固件/SSC 产品配置、配套 `dcu_compiler.h` 和 `device_config.h` 设备数量 | [固件 CMake](../../firmware/CMakeLists.txt) 注册包含路径；宿主协议测试使用同一路径 |
| [firmware/app/motor/cfg/](../../firmware/app/motor/cfg/) | `motor_drivers.hpp`；允许使用的型号配置与驱动种类 | 产品绑定显式选择，只注册当前真实 ENCOS 实现 |
| [firmware/bsp/dcu_hpm5e31/cfg/](../../firmware/bsp/dcu_hpm5e31/cfg/) | `tool_config.hpmpc`；HPM 配置工具工程 | 人工打开新路径；普通构建不运行该工具 |
| [scripts/cfg/](../../scripts/cfg/) | `board.example.json`、私有 `board.local.json`、`60-dcu-jlink.rules`；探针参数、核对模板与 USB 规则源文件 | [dcu.py](../../scripts/dcu.py)、[USB 向导](../../scripts/setup-usb.sh) |
| [debug/cfg/](../../debug/cfg/) | `openocd.cfg`；J-Link、复位时序、Flash 和服务配置 | `dcu.py` 的受保护目标操作 |
| [tools/cfg/](../../tools/cfg/) | `toolchain.lock.json`；工具版本、下载地址和 SHA-256 | [bootstrap.py](../../scripts/bootstrap.py) |
| [cmake/cfg/](../../cmake/cfg/) | `CMakePresets.json`；实际 configure/build/test 预设 | 根 [CMakePresets.json](../../CMakePresets.json) 的 `include` |

`cfg/` 跟随维护归属，不是每一层目录都创建一个空目录。后续电机或 IMU 确有独立配置文件时，再在对应模块下建立 `cfg/`；跨模块公共固件配置仍维护于 `firmware/cfg/`，不复制多份同名头。

已有 C/C++ 接口头、时钟/引脚实现、生成的对象字典、ESI/SII 交付物不是仅凭扩展名就应搬入 `cfg/` 的文件。`dcu_compiler.h` 当前随共享配置头保留，用于 C/C++ 布局断言，不以本轮目录调整另造公共库。

## 固定入口与例外

| 保留位置 | 原因与边界 |
| --- | --- |
| 各级 `CMakeLists.txt` | 构建脚本入口，继续与所注册源码所属模块相邻，不是可任意重命名的参数文件 |
| 根 `CMakePresets.json` | CMake 的固定发现入口；只含版本和 `include`，不再重复维护实际预设参数 |
| 根 `app.yaml` | 当前 SDK 默认从应用根目录查找，HPM Explorer 0.1.0 也在示例目录根识别该名称；保留默认约定，不额外覆盖 `APP_YAML_PATH` 改变工具行为 |
| `firmware/bsp/dcu_hpm5e31/dcu_hpm5e31.yaml` | SDK 以 `${BOARD_SEARCH_PATH}/${BOARD}/${BOARD}.yaml` 发现并读取板卡，不能只移动文件而不改变 SDK 接入方式 |
| `.vscode/launch.json`、`tasks.json`、`settings.json`、`c_cpp_properties.json`、`extensions.json` | VS Code/扩展的标准发现位置；没有为迁入 `.vscode/cfg/` 创建副本或不可移植的符号链接 |
| 根 `.gitignore`、可选 `CMakeUserPresets.json`、本机 `.env` | Git/CMake/环境工具的约定入口；私有配置继续忽略，不以归档要求发布到仓库 |
| `third_party/` 内配置 | 保留依赖内部约定，不修改第三方解析代码来满足目录形式；旧 `legacy/` 归档现已删除 |
| `build/`、`artifacts/`、`.tools/` 中配置与报告 | 工具生成或本机安装的运行产物，例如目标事务 `transaction.cfg` 和镜像报告 JSON，不是受维护的源配置；继续忽略 |

SDK 依据见 [application.cmake](../../third_party/hpm_sdk/cmake/application.cmake)；Presets 的根入口及相对 `include` 规则已核对本机 `cmake --help-manual cmake-presets.7`。HPM Explorer 的应用根目录识别已核对本机安装包 `src/catalog.js`，这不等于已经完成该扩展的 GUI 验收。

不为目录一致性引入额外板卡生成层、重复配置或修改冻结 SDK。固定入口以外的新增项目配置按表中规则归档。

## 私有参数与操作方式

原 `config/board.local.json` 已原字节移动至 `scripts/cfg/board.local.json`，不是从示例重建。当前机器的确认状态没有改变，也不代表获得新的上板授权。

新机器仍应从未确认的模板开始，在核实实物与接线后填写本地文件：

```bash
cp -n scripts/cfg/board.example.json scripts/cfg/board.local.json
```

[忽略规则](../../.gitignore) 同时忽略新私有路径和退役的旧私有路径，防止遗留文件误提交；旧路径不再被运行入口读取，也不作为兼容回退。共享模板、USB 规则和工具锁文件不被忽略。

命令入口、Debug/Release 预设名及输出目录不变：

```bash
python3 scripts/dcu.py build --preset hpm-debug
python3 scripts/dcu.py build --preset hpm-release
python3 scripts/dcu.py test
ctest --preset hpm-debug
```

显式使用 `--board` 的个人命令需改为新路径；自行维护的绝对路径、外部脚本和旧终端历史不会自动更新。USB 规则的源文件归入 `scripts/cfg/`，系统安装目的地仍是 `/etc/udev/rules.d/60-dcu-jlink.rules`，本轮没有执行 sudo 或重新安装规则。

HPM 配置工具工程改为手动打开 `firmware/bsp/dcu_hpm5e31/cfg/tool_config.hpmpc`。尚未验收迁移后的重新生成行为；先输出到临时目录，审阅 `board`、`clock`、`pinmux` 差异后再回填 BSP，不能把 `cfg/` 当成 C/H 源码生成目录直接覆盖。
