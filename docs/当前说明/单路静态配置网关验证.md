# 单路静态配置网关验证

对应[《单片机代码治理表》](../设计资料/单片机代码治理表.md)第一阶段。新增 `hpm-gateway-profile`，只在独立内部回环镜像中启用，不修改 BSP、生产对象字典、SII/ESI、主站或 `motor` 运行路径。该预设仅允许配置、构建和离线镜像检查。未上板。

## 配置如何生效

[单路内部回环配置](../../firmware/app/gateway/cfg/单路内部回环配置.yaml)是唯一配置源。[构建期生成器](../../tools/protocol/generate_static_profile.py)校验 YAML 并生成头文件，放在预设的构建目录；MCU 不解析 YAML，也不写 Flash 保存配置。

| YAML 字段 | 消费位置与约束 |
| --- | --- |
| `channels[0].bus` | BSP 的硬件映射不变；诊断适配只取所选 MCAN 及其 IRQ，初始化这一路的时钟、Message RAM、FIFO 和内部回环。范围 0–3，未启用通道不初始化，不配置 CAN 引脚或收发器。 |
| `channels[0].devices[0]` | 只允许一个 `internal_echo_v1` 测试设备。网关静态路由用通道、帧序号和连续的标准 CAN ID 路由发送及核对接收。错通道、越界帧和不匹配的回包不形成有效结果。 |
| `pdo.rx`、`pdo.tx` | YAML 选择两个 PDO 的映射对象和数据对象索引。Rx 按连续 32 位条目；每两项构成一帧 8 字节。Tx 前段回显同长数据，尾部追加四个小端状态字。SII、CoE 映射对象、SSC 大小和缓冲区均用同一份生成描述。 |
| `nominal_bitrate_kbps`、`frame_timeout_ms` | 首轮限定经典 CAN、速率 1000；单帧超时范围 1–20。数值不带单位，单位写在字段后缀。 |

默认 Profile 为 MCAN0、`probe0`、CAN ID `0x600..0x603` 和 32/48 字节 RxPDO/TxPDO。诊断产品码为 `0x7fff0004`，不能用 `0x7fff0003` 的主站配置作验收。该路径在 [网关静态配置模块](../../firmware/app/gateway/static_profile.c) 消费通道与路由，不链接 motor；原生产路径还使用旧配置，不宣称生产迁移已经完成。

这是内部回环专用配置，不替代[面向物理回显的最小 Profile](../../tools/protocol/cfg/最小回环配置.yaml)。就绪与一次确认另见[独立会话预设](单路配置网关就绪与确认验证.md)；当前预设仍不启用该门控。实际设备、外部 CAN、动态配置未在这两份镜像中验收。

## 离线验证

```bash
python3 scripts/dcu.py build --preset hpm-gateway-profile
python3 scripts/dcu.py check-image --preset hpm-gateway-profile
python3 -m unittest discover -s tests/host -p test_static_gateway_profile.py -v
```

[替代配置](../../tests/host/gateway/alternate_static_profile.yaml)用 MCAN2、`probe_alt`、CAN ID `0x650..0x651`、16/32 字节及不同对象索引。替身测试检查只初始化被选通道、帧 ID 与内容来自 Profile、离开 OP 不发布旧回包；独立解析 SII 并以真实 SSC 的对象读取函数核对全部映射和长度。可用 `cmake --preset hpm-gateway-profile -B <单独构建目录> -DDCU_STATIC_PROFILE_FILE=<绝对路径>` 构建替代版。验证结果不代表运行过实际 MCAN2 或线上 PDO。
