# 启动编号日志初始化与烧录保留

生产 Boot ID 只用于诊断。日志不可用时上报零，仍按 Profile 正常进行设备自检和 PDO 协商。首装日志不是生产运行前置条件；下载和升级仍必须保护 SII 与日志保留区。

## Flash 布局

以下为当前 HPM5E31 单路会话诊断预设的离线核对。地址范围左闭右开；Flash 基址为 `0x80000000`、容量 1 MiB。

| 区域或镜像 | 地址范围 | 说明 |
| --- | --- | --- |
| EtherCAT SII 保留区 | `[0x80080000, 0x80090000)` | 64 KiB，保持原布局 |
| 启动编号日志 | `[0x80090000, 0x80092000)` | 8 KiB，起于 SII 结束地址；两个 4 KiB 扇区，页大小 256 字节 |
| `hpm-debug` | `[0x80000000, 0x80061000)` | 当前 ELF 擦除跨度 |
| `hpm-release` | `[0x80000000, 0x8005a000)` | 当前 ELF 擦除跨度 |

[镜像检查](../../scripts/image_guard.py)按 ELF 加载地址、段间空洞和扇区对齐计算整个擦除跨度，碰到任一保留区即拒绝。表中跨度不是白名单，每次重编译或升级都重新计算。

## 首次初始化：只为确认从未发号的新日志准备

1. 将来获准上板时，先在目标暂停的情况下核对物理 Flash 几何，完整读出两个日志扇区并留档。仅在已确认该板**从未发号**且两扇区全部为 `0xFF` 时准备首装。仅凭全空不能区分新板与曾被整片擦除的旧板。
2. 用读回快照离线生成计划，输出目录必须不存在：

   ```bash
   python3 scripts/prepare_gateway_journal.py --blank-snapshot gateway-id-journal.bin --output-dir journal-first-install
   ```

   只生成 `epoch-zero.bin`（16 字节）和 `plan.json`，不连接目标，也不生成擦除或写入命令。清单记录目标地址、禁擦除、写前和写后完整 8 KiB 的 SHA-256；短文件、有任何非空字节或已有记录都拒绝。
3. 未来单独批准的首装只允许在写前重新确认全区与清单匹配后，向 `0x80090000` 写入这一条记录，禁止擦除。写后仍暂停并完整回读两扇区，核对写后摘要；不匹配就停止，不补擦、不重置编号。保留读回、清单和板卡对应记录。代号 0 仅作首装标记，首次正常启动从 1 发号。

## 后续升级：按原样保留，不导入旧备份

1. [受保护下载入口](../../scripts/dcu.py)冻结待烧录 ELF 并检查擦除跨度；写前完整备份 SII 和日志到事务目录的 `retained-eeprom.bin` 和 `gateway-id-journal.bin`，对照当前 Flash 校验。重大升级使用现有 `--backup-before-reset` 先暂停备份，复位暂停后校验备份未变化再写入。
2. 只在 ELF 覆盖范围内烧录。校验固件，再校验两个保留区与备份一致；失败不报告成功、也不写回旧日志。正常完成仍保持暂停。
3. 不把日志打包进固件，不整片擦除，不把旧日志备份当作恢复镜像。不确定板卡是否已发过号、日志已有内容或异常全空时，不执行首装；隔离该板，单独处理。升级不触发初始化。

## 离线验收结果与边界

历史主机回归用文件模拟整片 Flash，并用 Tcl 替身执行生成的下载事务。覆盖普通和复位前备份两种路径：首次发号后，模拟升级，SII 与日志逐字节不变；再次启动拒绝旧 SDO 激活和旧 PDO，编号连续递增。另验证日志备份失败、复位后内容变化和擦除越界时事务失败，不自动恢复旧日志。

当前未初始化实板、未烧录，未确认真实 NOR 擦写、断电或实际出厂状态；原离线预设 `hpm-gateway-session` 已退役。BSP、生产镜像和 EtherCAT 接口未变。
