# 按启动配置生成周期布局

生产固件按 CAN Profile 中的全部控制单元启动。RK 可在 PREOP 从同一份 Profile 选择本次使用的通道和设备，重新生成 `MotorWithRaw` 的 SM2（主站输出）和 SM3（主站输入），不重启 HPM。物理掉线、单轴失能或修改 RAM 策略不触发重映射。增加未登记型号、路由、位速率或扩大安全限值仍需新的启动 Profile，不属于在线选择。

| Profile 中的单元 | SM2 | SM3 |
| --- | ---: | ---: |
| 板头 | 32 B | 32 B |
| 每条已配置的 CAN 通道 | 8 B | 8 B |
| 每台 ENCOS，或启用中性 MIT 的北京创新电机 | 24 B | 32 B |
| 每台仅查询状态的北京创新电机 | 0 B | 32 B |
| 已登记双向 PDO、运动参数待确认的轴 | 24 B | 32 B |
| 仅登记在 `passthrough_devices` 的设备 | 0 B | 0 B |
| MotorWithRaw：配置 `cyclic_sideband` 的头手单槽 | 12 B | 12 B |
| MotorWithRaw：无头手排程的原诊断旁带 | 48 B | 48 B |

未绑定的 IMU 不占循环空间。各块按板头、通道、轴、旁带排序；通道按 BSP 编号升序，同路轴按 Profile 的声明顺序。被省去的块不留洞，也不重编物理轴掩码或 CoE 对象索引。主站通过对象查生成的偏移，不用轴号乘固定步长。只读轴不能通过启用掩码申请命令。

下表是完整启动目录的 **SM2 / SM3 字节数**，不是每次在线选择后的长度。使用同次生产构建的契约。

| 生产布局 | `hpm-release`（rev 11） |
| --- | ---: |
| Motor（不带旁带） | 376 / 480 B |
| MotorWithRaw（上电默认） | 388 / 492 B |
| Raw（32 B 板头 + 每条已配置通道 128 B） | 544 / 544 B |
| SingleFd（一个完整透传帧） | 88 / 88 B |

生产配置：can0 是表情头与双手共用的 1 Mbit/s 经典 CAN。can1 腰部 ID 1/2/3 分别为 ENCOS 7220/7216/7216；can2 左臂和 can3 右臂各五台，ID 1/2/4 为 BJCX HRA55H-100，ID 3/5 为 HRA40H-101。13 台都在 `devices` 中，各占一对独立命令/反馈 PDO，不使用调试透传。腰与臂的接口名只描述已知的总线与 ID，不假设它们对应的机构方向。

`motion_parameters: pending` 表示双向映射已就位，但没有获确认的运动参数：HPM 只走本机协议驱动的只读查询，真实反馈按字段标记有效；不会依据任意 PDO 命令发送运动帧，也不会退回透传。这不是全零 MIT 模式。型号性能和机构输出限位不能冒充电机编码量程或安装后的电机侧限位。HRA V2.6 产品手册 §1.3 列出 HRA40H 的 101 档，HRA55H 列 51/81/101 档；§3.1 将通信细节指向独立协议文件，不能据此把现有 55H-100 铭牌改为 101 或判定 MIT 比例。

RK 的生产回环测试不依赖旁带。每个命令在下一拍按板头 `AcceptedCycleSeq` 和各轴的模式、运行状态、新反馈位、有效字段、年龄、故障位核对。CSV 的 `n1_fresh` 表示该轴的生产 PDO 是否满足这些条件，不是 CAN 抓包。释放周期主站并回到 PREOP 后，用同一 boot ID 和拓扑代数下的逐轴 `TxCompleteCount` 差值核对实际发送总数，不把已发 PDO 当作电机 TX。

## 表情头与双手旁带

生产 rev 11 默认混合档的 SM2（`0x1640 → 0x7300`）与 SM3（`0x1A41 → 0x6400`）尾部各有一个 12 B 槽。相对槽起点：`+0 CanId`（小端 U16，标准 11 位 ID）、`+2 Dlc`（U8，0…8）、`+3 Valid`（U8，0 为空、1 为有效）、`+4 Data[8]`（CAN 原字节序）。总线固定由 Profile 绑定，不传通道、标志或批号。全目录的两个起始偏移分别为 376、480 B；在线选择后按映射定位。未选 can0 时仍保留单槽，不收发，不改作诊断页。

下行随板头 `CycleSeq` 每拍最多发送一帧。上行每拍最多从 can0 接收队列取一帧，不是发送回显；其余帧留在有界队列，溢出计入丢弃。RK 按同一会话的板头 `PublishSeq` 去重：只有新的发布且 `Valid=1` 才消费，不能靠 CAN ID 或数据是否变化判断新帧。

RK 按 2 ms 拍发送。十拍顺序为：`0x601 / 左手 / 0x602 / 右手 / 0x603 / 空 / 0x604 / 空 / 0x605 / 空`。由 RK 在第一拍锁存一份新姿态；没有新目标、会话失效或手的 ID 尚未绑定时不重发旧目标。左右手分别在 Profile 的 `cyclic_sideband.frames` 增加 `left_hand`、`right_hand` 的 ID 和 DLC 后才能用，不以 ID 0 代替。变更绑定需要重新生成并核对契约。

主站适配头 `dcu_sideband.hpp` 的 `write_sideband_slot` 接收映射得到的 12 B SM2 尾块、从零开始的相位和本拍 payload；无命令传空指针和零长度。对正确大小的尾块，未绑定或长度错误的命令返回失败并清空槽，不产生 CAN 请求。HPM 不自行造帧或补发：仅在生产 OP 会话授权且 can0 已使能时发送 Profile 中的标准数据帧，校验 ID 与 DLC。按需维护帧不在周期表内，须由主站显式提交；ID/DLC 过滤不等于维护操作授权。切换纯透传档不继承该专线的混合档发送配额。

该十拍契约描述 **主站发送能力**，不代表四块头板已通过 50 Hz 吞吐验收。动力隔离后先被动收帧，再做[板 4 只读往返](../设计资料/表情头通讯协议.md)；持续姿态下发还须验证头板队列与丢弃计数，以及原电机 N+1 契约。

RK 的 `DriverModule` 用显式的 `face_command_topic` 订阅 `my_ros2_proto/msg/FaceControl`；不配置时不订阅。消息是一份完整的执行器目标，`id` 是头部逻辑通道，`value` 为度，不是 CAN 字节或 blendshape 权重。设备适配器编码五份载荷；PDO 周期按 Profile 选取当前拍的载荷。发布方时钟必须与 RK 对齐；重复、过期、缺项及非法目标不成为新姿态。此接口不改变电机 PREOP 路由核验，不应借用电机台架的配置进 OP。

### 头板故障怎么读

HPM 在选中 can0、生产混合档进入有效 OP 会话后开始被动监测，不等 RK 读取原始帧。can0 的 `ChannelStatus` 位 5、6、7 分别表示有头板心跳离线、有反馈组超时、本会话收到过设备错误。它们不占原始帧槽，不等同于 CAN bus-off，也不触发其他总线电机停机。手的 ID 与协议未定，不参与监测。

从只读 CoE 对象 `0x2104` 定位原因：

| 子索引 | 含义 |
| --- | --- |
| 01 | 1 正在监测；0 未启用或已停止。退 OP 后冻结上次结果以便排错，新会话重新计时。 |
| 02 / 03 | 已见有效心跳 / 当前心跳超时，bit 0…3 对应板 1…4。计数须变化，ID、DLC、板号和签名字节须匹配。自开始监测或最后一次有效心跳起满 9 s 判离线。 |
| 04 / 05 | 已见有效反馈 / 当前超时反馈组。位 0…15 依次为十六进制 ID：`781 785 791 / 782 786 792 7A3 7A7 / 789 78D 794 / 78A 78E 795 798 79F`。每个 ID 独立按 DLC 验证；连续 3 个名义周期未更新即超时（360 或 600 ms）。恢复只清对应项。 |
| 06 | 本会话明确报过错的板掩码。一次操作失败不等于该板离线；后续成功不抹去会话故障证据。 |
| 07…0A | 板 1…4 各自最近一次明确错误，格式 `(CAN ID << 16) \| (失败阶段 << 8) \| 状态码`。`0x621` 使用响应 Byte0，`0x627/628` 使用 Byte6（Flash 状态）和 Byte7（阶段）。例如板 4 的 `0x06280000` 加阶段和状态。 |

未见首包且未到阈值时是等待，不是“在线”。心跳不能代替反馈刷新，舵机软件输出不能证明机械到位。设备诊断不修改头板工作状态，也不自动重发失败的命令。

## 构建与核对

用 `-DDCU_CAN_PROFILE_FILE:FILEPATH=<配置的绝对路径>` 选择配置，省略时使用[生产 CAN 配置](../../firmware/app/profile/cfg/生产CAN配置.yaml)。构建目录的 `firmware/profile-contract/protocol/ethercat/` 包含本次配置的 ESI、SII、`周期布局.json`、`dcu_profile_pdo.hpp` 和 IgH 适配头 `dcu_igh_layout.hpp`。仓库同名生成物只代表默认 Profile，不可拿来配其他镜像。

- HPM 启动时核对装入的 Profile、各档实际映射、SSC 默认 assignment 和布局摘要。不匹配则不启动生产周期。
- RK 使用同一构建的导出目录作为头文件搜索路径。进入周期前用 `dcu_profile_pdo::verify` 核对只读 `0x2102:01` 的 32 字节布局摘要、在线 `1C12/1C13` 与 IgH 扫描所得每个映射字段，再用 `register_image` 注册域偏移。即使长度相同，字段或路由不一致也不得激活控制。布局摘要不等于 `0x2100/0x2101` 使用的策略摘要。
- 线协议版本为 `0x00010003`。固定的 `0x2102:01` 描述启动目录，不是热选择后的身份；热布局还必须核对所选掩码、实际 assignment、每个映射字段，以及 boot ID 和拓扑代数。仅核对长度或目录摘要不够。

## 在线选择

先停车并结束旧周期，释放旧 domain，确认 PREOP。热切换不主动向电机发零力矩或使能。源码 [IgH 适配头](../../protocol/ethercat/dcu_igh_selection.hpp) 复用现有切换状态机，步骤如下：

1. 读 `0x2103:05`（8 B boot ID）、`0x2100:05`（策略版本）和 `0x2103:02`（当前拓扑代数）。`0x2103:01` 一次写入 88 B 小端记录：boot ID、策略版本、旧代数、通道掩码、物理轴掩码、32 B 布局目录摘要、32 B 启动 Profile 摘要。除 boot ID 和摘要外每项均为 4 B。
2. HPM 撤销旧命令和 owner，暂停业务与探测，等待所有在途 CAN TX 退休并清理 RX。等待 `0x2101:03=1` 后在 `0x2101:02` 写入 1。故障只能在 PREOP 显式复位再重新请求；未提交不能进入 SAFEOP。未按时完成 drain 或 60 秒内未完成映射均闭锁。
3. RK 按候选布局写 `1C12/1C13`（先清各自的子索引 0，逐项写，再恢复数量），回读双方方向上每个映射字段；向 `0x2103:06` 写入旧代数加一。HPM 对两套 assignment 同时逐项比较，通过才更换驱动、调度、SDO 投影和 PDO 偏移。未选轴不会再被轮询；设备的单次中性 MIT 预算不会因此重置。
4. 回读 `0x2103:02/03/04/05` 的新代数、通道、轴和原 boot ID。RK 在新 domain 内显式登记这些块并检查偏移。需要进入 OP 的控制进程还须等待新反馈和新的无使能基线；不得复用旧输出缓冲。重启恢复启动 Profile 的全体设备，拓扑代数回到 0；在线选择不写 Flash 或 SII。

生产使用 `hpm-release`。RK 管理入口 [apply_cyclic_selection.cpp](../../tools/protocol/apply_cyclic_selection.cpp) 使用同次构建导出的头和目标机的 IgH 库。它不会启动周期，只校验在线映射和登记的新 domain：

```sh
c++ -std=c++17 -O2 -I"$DCU_CONTRACT" -I/opt/etherlab/include apply_cyclic_selection.cpp \
    -L/opt/etherlab/lib -Wl,-rpath,/opt/etherlab/lib -lethercat -o select
./select --inspect
./select --apply all
```

选择子拓扑时，以同次生产构建的 `生产CAN配置.yaml` 作为 `--catalogue`，在目标 YAML 中仅删除不使用的通道或设备，保留其他定义和顺序。先运行 `apply_cyclic_profile.py` 的只读核对，再按维护流程提交；`all` 恢复当次启动目录。登记成功不代表运动或 N+1 验收通过。
