# DCU 混合语言开发规范

更新日期：2026-11-13。采用“电机、IMU 和项目自有抽象层用 C++，其他固件用 C”的边界。现有电机实现已迁入 C++ 编译链，固件/BSP/依赖/生成物目录也已分离；布局及遗留事项见[目录规划与实施状态](../设计资料/单片机工程目录重构规划.md)。

## 1. 语言归属

| 范围 | 语言 | 当前落点 |
| --- | --- | --- |
| 电机控制、状态、租约、查询和调度 | C++17 | [motor_control.cpp](../../firmware/app/motor/motor_control.cpp) |
| ENCOS 电机协议编解码与参数转换 | C++17 | [encos_motor.cpp](../../firmware/protocols/encos/encos_motor.cpp) |
| IMU 设备实现、解析、校准和状态管理 | C++17 | 当前没有实际驱动；只有 `mc_imu_t`、对象 `0x6300` 和 PDO 映射，仍保持无有效样本 |
| 后续项目自有设备、总线访问及业务抽象 | C++17 | 按实际变化点引入，不提前创建空基类和逐函数转发层 |
| `main`、初始化编排、SSC 应用回调 | C | `firmware/app/main.c`、`firmware/comm/ethercat/digital_io.c` |
| MCAN/GPIO/中断、ESC/PHY/EEPROM 适配 | C | `firmware/comm/` 与 `firmware/bsp/dcu_hpm5e31/` |
| HPM SDK、SSC 栈核心和生成对象存储 | C，启动文件仍为汇编 | 不更改第三方语言；`encos_storage.c` 单独包含原生成存储 |
| C/C++ 共享类型和跨语言函数声明 | 双语言兼容 `.h` | 固定宽度数据、原有 packed 布局、静态断言和 C 链接约定 |

`ethercat_canfd_gateway.c` 虽然叫“网关”，实际直接操作 MCAN、GPIO 和 IRQ，因此保留 C。将来拆出的高层抽象采用 C++，不把底层寄存器实现也整体改成 C++。

这是固件的语言归属，不要求把主机构建保护脚本或协议生成工具改写成 C。改成 `.cpp` 也不代表已经完成面向对象设计：电机控制仍与 SSC 状态、对象字典和关中断操作耦合，本轮不重写其控制状态机或时序。

## 2. 构建规则

[根 CMake](../../CMakeLists.txt)明确设置 `CMAKE_CXX_STANDARD=17`、`CMAKE_CXX_STANDARD_REQUIRED=ON`、`CMAKE_CXX_EXTENSIONS=OFF`。C++ 源码使用交叉 `g++`，原 `.c` 仍使用交叉 `gcc`；最终 ELF 由 `g++` 链接，产物路径和镜像检查入口不变。

只对 C++ 编译添加 `-fno-exceptions` 和 `-fno-rtti`，不把这些选项施加到 C 文件，也不通过将所有源码强制设为 C++ 来实现混合构建。新增实际模块时由上级 CMake 加入该目录，在模块的局部 CMake 显式注册，例如未来的 IMU 目录中：

```cmake
sdk_inc(.)
sdk_src(imu_driver.cpp)
```

上例不是已存在的 IMU 文件。新模块必须先有真实设备型号、协议、接线与运行需求，再注册源码，不添加空文件占位。

**从旧 C 版本或旧目录布局首次切换，或以后删除/改名静态库源码时，要先清理对应配置的构建产物。** 当前 SDK 的归档命令使用 `ar crD`，增量归档可能保留旧对象。仅 `cmake --fresh` 清理缓存不够，可能在 `--whole-archive` 链接时重复定义。移动前先保留旧 ELF 并执行旧配置的 `clean`；新布局就绪后重新配置和构建：

```bash
cmake --build --preset hpm-debug --target clean
cmake --fresh --preset hpm-debug
cmake --build --preset hpm-debug
cmake --build --preset hpm-debug --target check-image
cmake --build --preset hpm-release --target clean
cmake --fresh --preset hpm-release
cmake --build --preset hpm-release
cmake --build --preset hpm-release --target check-image
```

首次配置、尚无构建目录时跳过 `clean`。若旧布局已经消失导致旧缓存无法执行 `clean`，不要为迁就缓存复制回旧源码；保留所需旧产物后，将对应旧构建目录移出并重新配置。日常不涉及源码删除/改名时继续使用 `python3 scripts/dcu.py build --preset hpm-debug`，不要求每次清理。

## 3. 接口与实时约束

- C 调用 C++ 时，公共 `.h` 在 `__cplusplus` 条件下以 `extern "C"` 包围函数声明。现有 `motor_control_*`、`MC_*`、`mc_object` 和 `encos_*` 符号保持 C 链接；SSC 回调名称不变。
- C++ 调用 C 时，优先使用已有兼容头；未提供 C 链接保护的 SSC 头在 C++ 使用处统一包入 `extern "C"`，不为此修改第三方栈。
- C 接口不暴露类、引用、模板、STL 容器或依赖 C++ 生命周期的对象。纯 C++ 内部类型可用 `.hpp`，不与线上 PDO/SDO 数据布局混用。
- 共享布局断言通过 [dcu_compiler.h](../../firmware/cfg/dcu_compiler.h) 的 `DCU_STATIC_ASSERT` 在 C 下使用 `_Static_assert`，在 C++ 下使用 `static_assert`。不删除或关闭布局检查。
- `encos_storage.inc` 保持原字节，由 [encos_storage.c](../../firmware/comm/ethercat/encos_storage.c) 按 C 编译；不让生成的 C 指定初始化依赖 C++ 扩展。原文件头仍记录旧包含者，实际构建关系以 C 包装文件为准。
- 不在控制周期、ISR 或长时间关中断区内引入堆分配、阻塞调用或隐含锁。关闭异常不等于禁止 `new`，是否使用动态内存必须另行评审。
- 设备访问不依赖全局对象动态构造的先后顺序；在板级初始化完成后显式初始化。现有 SDK 有静态构造调用机制，但本轮没有在板上验证 C++ 构造函数。
- 不为使用 C++ 强行把所有函数装进类；先保留现有保护行为，再在协议测试和真实依赖的基础上收敛模块接口。

共享生成头 `encos_interface.h` 仅增加断言兼容和 C 链接声明，字段、位定义、接口版本及默认存储不变。生成链仍不可用，未运行再生成；恢复生成器时须把兼容规则纳入输出，详见[生成文件与来源清单](生成文件与来源清单.md)。

## 4. 开发与验证

VS Code 的 C/C++ 配置使用现有 CMake 提供器和 `compile_commands.json`，已移除该配置中的 ROS2 包含路径、宿主 x86 编译器及个人绝对路径。其他扩展的 ROS2/Python 辅助设置仍可被编辑器回写，不参与固件 CMake 构建。固件编译和调试仍使用原锁定的 HPM 工具链及受保护入口。厂商 GDB 没有 Python 支持，不能据此承诺 STL pretty-printer 可用。

离线测试入口不变：

```bash
python3 scripts/dcu.py test
ctest --preset hpm-debug
```

新增主机端协议测试通过宿主 `cc` 编译 C 存储与调用者，再通过宿主 `c++` 编译、链接并执行 C++ 协议实现。完整测试套件因此需要宿主 C/C++ 编译器，Ubuntu 可由 `build-essential` 提供；这不替代 MCU 交叉工具链，详见[环境准备](环境依赖与外部资源准备.md)。缺少编译器会明确报错，不静默跳过业务测试。

目录迁移时套件为 47 项；后续配置归档新增 8 项，当前共 55 项：原 35 项保护/工具测试、8 项协议/互操作测试、4 项布局/命名测试和 8 项配置归档测试。具体源码集合、BSP 生效位置、ELF 差异和验收命令见[目录迁移验证记录](../验证记录/2026-11-13-混合语言目录迁移验证记录.md)，最新配置路径与验证见[配置文件归档规范](配置文件归档规范.md)。

以下保留先前语言迁移阶段、尚未移动主目录时的验证结果，不是当前映像的体积表：

- Debug/Release 清理后完整编译、C++ 链接及 EEPROM 保留区检查通过。
- 当时 43 项离线测试通过，其中 8 项为新增协议与语言互操作测试，覆盖 C 调用 C++、C++ 访问 C 存储、共享布局、对象字段边界、五种控制模式固定字节样例、非法命令、反馈、参数查询与浮点输入。
- 同一组 8 项测试也通过了改动前 `c5ede57` 中 C 协议实现的主机编译与执行，作为迁移回归基线；这不等于覆盖了所有输入或证明实物协议已经验收。
- 离线 GDB 能解析新 Debug ELF 的 `main`、电机 C++ 源码行和 `axis_t` 类型，关键 C 接口符号保持原名；Release 保持原优化且无源码行调试信息。没有进行目标连接或 GUI 联调。
- 相对本轮改动前的 C 版本，`size` 的 Debug `text` 从 `295272` 到 `295456` 字节，Release 从 `276944` 到 `277104` 字节；两种配置各自的 `data/bss` 未变。这不是最坏执行时间或运行时堆栈占用测量。
- 本轮未访问 J-Link、未复位或烧录目标，也未验证 IMU、实际电机、EtherCAT 周期及停机效果。先前 C 固件的硬件实测不自动覆盖新的 C++ 映像。
