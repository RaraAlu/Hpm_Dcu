## 实际构建与包含关系

根 CMake 显式注册以下本工程 C 源码；SDK 还会按配置加入其驱动和组件，并非只编译此清单。

| 区域 | 默认注册源码 |
| --- | --- |
| 根目录 | `ecat.c` |
| `application/` | `digital_io.c`、`motor_control.c`、`encos_motor.c`、`ethercat_canfd_gateway.c` |
| `SSC/Src/` | `coeappl.c`、`ecatappl.c`、`ecatcoe.c`、`ecatslv.c`、`mailbox.c`、`objdef.c`、`sdoserv.c` |
| `port/` | `hpm_ecat_hw.c`、`hpm_ecat_phy.c`、`hpm_ecat_e2p_emulation.c`，最后一项由 EEPROM 仿真配置控制 |

关键头文件通过包含关系生效，不能因未出现在 `sdk_src()` 中就认定为废弃文件：

```text
application/digital_io.c
  -> SSC/Src/digital_io.h
     -> SSC/Src/digital_ioObjects.h
        -> SSC/Src/gatewayObjects.h
application/motor_control.c
  -> application/encos_storage.inc
SSC/Src/ecatappl.c
  -> SSC/Src/eeprom.h
```

当前配置不注册 `port/hpm_ecat_foe.c`、`port/lwip/` 和 `port/modbus_tcp/`。这些是保留的可选适配，不代表已经启用，也不因此直接删除。

## SDK 与开发工具

SDK 的 `boards/hpm5e00evk/` 包含 `board.c/.h`、`clock.c/.h`、`pinmux.c/.h` 和 `tool_config.hpmpc`。目录仍使用 SDK 板名，但已经包含自研板修改。`soc/`、`arch/` 提供芯片定义、启动和链接配置；`drivers/` 提供外设驱动；`components/` 提供 EEPROM、调试控制台等。随 SDK 导入的预编译依赖不是本工程新产生的构建缓存，不能按扩展名统一清除。

| 入口 | 用途 |
| --- | --- |
| [scripts/dcu.py](../../scripts/dcu.py) | `doctor`、`configure`、`build`、`test`、`check-image` 和受保护的硬件命令 |
| [scripts/bootstrap.py](../../scripts/bootstrap.py) | 按锁文件安装本地工具 |
| [scripts/image_guard.py](../../scripts/image_guard.py) | 检查 ELF 加载和擦除范围是否侵入保留区 |
| [scripts/openocd.sh](../../scripts/openocd.sh)、[scripts/gdb.sh](../../scripts/gdb.sh) | 本地调试工具启动包装 |
| [scripts/setup-usb.sh](../../scripts/setup-usb.sh) | USB 权限配置向导，不执行 JTAG 操作 |
| [tools/toolchain.lock.json](../../tools/toolchain.lock.json) | 工具安装包来源、固定版本及摘要 |

`build/hpm-debug/` 和 `build/hpm-release/` 各自保存 `output/dcu.elf`、BIN、MAP、编译数据库和中间文件。不要将构建输出反向当作源码维护。

已安装 VS Code 扩展的分类、命令及配置接管风险见[HPM 开发扩展使用指南](开发扩展分类与使用指南.md)。扩展安装目录不属于本工程源码，也不意味着当前构建或硬件调试已经切换到该扩展。

## 后续改动原则

- 业务调整优先在 `application/`；硬件适配优先检查 `port/` 和 SDK 的 `boards/`。
- 协议布局变更须联动[生成文件清单](生成文件与来源清单.md)、固件、ESI/SII 和上位机；不能只改一份 XML。
- 目录移动应单独提交，同步修改 CMake、脚本、编辑器和文档引用，不夹带控制逻辑改动。
- 恢复生成链和补充测试前，不拆分 `motor_control.c`、批量改名或清理旧 SSC 工程。
