# DCU 目录层级与维护职责

核对日期：2026-11-16。以下是已经落地的目录，不是待建示意。电机采用 C++17，其他已存在固件保持 C；RTOS 复用 SDK 启动和移植，本页不承诺板上业务、实时性或停机效果。

## 当前目录

```text

|-- CMakeLists.txt
|-- CMakePresets.json              # 固定入口，仅包含 cmake/cfg 中的实际预设

|-- firmware/
|   |-- CMakeLists.txt
|   |-- app/
```

设备目录现在包含可测试的实际代码，不是空骨架。IMU 公共模型和未接入实现已准备，但没有具体芯片、总线或主循环采集接入，旧 PDO 仍无有效 IMU 样本。`app/cycle/` 是已接入默认构建的实际运行代码，不是预建空目录。具体契约见[设备驱动扩展与接入规范](设备驱动扩展与接入规范.md)和[同步规划](../设计资料/分布式时钟同步与实时系统接入规划.md)。

## 固件位置

| 位置 | 职责 | 维护约束 |
| --- | --- | --- |
| [main.c](../../firmware/app/main.c) | 板卡、CAN、EtherCAT、电机初始化和 RTOS 启动 | 保留 C 入口和 `main` 符号 |
| [周期运行目录](../../firmware/app/cycle/) | 纯 PDO 三缓冲、快 IRQ 交接、唯一业务任务、截止和 TX 故障门控 | C；纯核心不依赖 SDK，运行适配依赖 SSC/FreeRTOS/HPM |
| [motor_control.cpp](../../firmware/app/motor/motor_control.cpp)、[公共接口](../../firmware/app/motor/motor_control.h) | 控制权、两阶段启动、租约、反馈、调度和 CoE 访问 | C++ 实现，C 接口；业务任务唯一所有者，不允许从 ISR 直接修改 |
| [ENCOS 协议目录](../../firmware/protocols/encos/) | 电机帧编解码、单位换算、范围与参数检查 | C++ 实现；不以目录移动改变线上字节 |
| [电机设备目录](../../firmware/devices/motor/) | 公共命令、能力、驱动注入及 ENCOS 实现 | 公共 Interface 不包含 SDK、SSC 或生成类型；只有一个生产驱动 |
| [产品绑定](../../firmware/app/motor/motor_driver_binding.cpp)及[注册配置](../../firmware/app/motor/cfg/motor_drivers.hpp) | 型号选择、每轴实例和旧 PDO 兼容转换 | `cfg/` 只注册既有 `0x8000`；不自动猜测型号或回退协议 |
| [IMU 设备目录](../../firmware/devices/imu/) | 公共样本、有效性、非阻塞驱动契约和过期处理 | 未连接具体 IMU；不将公共浮点模型直接复制为旧 packed 过程映像 |
| [公共 CAN 帧](../../firmware/ports/can_frame.h) | 中立的 C/C++ 帧类型和载荷约束 | `encos_frame_t` 是兼容别名；仍仅支持 8 字节 |
| [CAN 适配](../../firmware/comm/canfd/) | 四路 MCAN、中断队列、发送进度和 LED | C；仍是产品专用实现，不是已经解耦的通用驱动 |
| [EtherCAT 适配](../../firmware/comm/ethercat/) | 当前 `digital_io.c/.h`、生成存储的 C 编译入口及硬件 port | 这是唯一活动应用实现，旧数字量示例已删除 |
| [自研 BSP](../../firmware/bsp/dcu_hpm5e31/) | 原自研板 `board`、`clock`、`pinmux`、板卡 YAML 和 `cfg/` 工具配置 | 硬件 C/H 原字节迁移；板卡标识为 `dcu_hpm5e31` |
| [固件配置](../../firmware/cfg/) | SSC 产品配置、FreeRTOS、周期参数、双语言断言和设备数量 | 与 `scripts/cfg/` 的主机配置分开维护 |
| [生成文件](../../firmware/generated/) | ENCOS 类型/存储、SSC 对象字典和 EEPROM 数组 | 保留唯一副本及现有语言兼容补丁，不运行损坏生成器覆盖 |
| [ESI/SII](../../protocol/ethercat/) | 供主站和 SII 工具使用的产品描述与二进制 | 不是普通构建缓存，不按 `.bin` 扩展名忽略 |

`firmware/protocols/` 是协议执行代码，根 `protocol/` 是对外协议交付物；`firmware/cfg/` 是板上固件配置，`scripts/cfg/` 是主机和探针配置。可迁移配置放在所属模块的 `cfg/`，不再保留根 `config/` 或 `firmware/config/`；固定工具入口和第三方目录的例外见[配置文件归档规范](配置文件归档规范.md)。

BSP 通过根 CMake 设置的 `BOARD_SEARCH_PATH=firmware/bsp` 由 SDK 注册一次。不要再在 `firmware/CMakeLists.txt` 中重复 `add_subdirectory(bsp/...)`。SDK 内原 `boards/hpm5e00evk/` 已移出，不保留第二份活动板级实现。`board.h` 中的历史日志名称仍为 `hpm5e00evk`，不代表构建选错板卡。

不使用递归通配注册固件，旧 `legacy/` 目录已删除。目录迁移时默认为 70 个编译单元，设备抽象后为 74 个；本轮加入 10 个内核/移植单元及 2 个周期单元，当前共 86 个，其中 6 个 C++，其余为 C/ASM。根 `app.yaml` 保留 SDK 要求的元数据入口，当前资源代价见[同步验证记录](../验证记录/2026-11-16-同步流水线与实时系统离线验证记录.md)。

关键包含关系为：

```text
firmware/comm/ethercat/digital_io.c
  -> firmware/comm/ethercat/digital_io.h
     -> firmware/generated/ethercat/digital_ioObjects.h
        -> firmware/generated/ethercat/gatewayObjects.h
firmware/comm/ethercat/encos_storage.c
  -> firmware/generated/encos/encos_storage.inc
third_party/beckhoff_ssc/Src/ecatappl.c
  -> firmware/generated/ethercat/eeprom.h
```

项目配置、应用头和生成头已从 SSC 源文件目录移出，避免引号包含优先命中旧副本。头文件没有单独出现在 `sdk_src()` 中不代表它未参与编译。

## 工具与资料

- `scripts/dcu.py` 的 SDK 定位已更新为 `third_party/hpm_sdk`，构建与目标保护入口不变；OpenOCD 仍使用该 SDK 的 `boards/openocd` 资源。
- 工具锁文件在 `tools/cfg/`，OpenOCD 在 `debug/cfg/`，板级主机参数和 USB 规则在 `scripts/cfg/`；脚本已同步引用。`.tools/` 安装位置、输出目录和两个受保护调试启动项不变，`.vscode/` 保留固定入口并通过 CMake 提供器和编译数据库获得源码路径。
- Python 测试入口现位于 `tests/host/`，CLI 和 CTest 同步发现。`tests/host/motor/` 是原生 C/C++ 测试源码，不是板上固件。
- 当前 `tools/protocol/generate_sii.ps1` 已更新输入输出路径，但 PowerShell/Beckhoff 再生成环境未验收。不可解析的旧 JS/JSON 已删除，协议生成链仍须单独恢复与验收。
- 旧 SSC 工程、数字量示例、FoE/lwIP/Modbus 适配、构建备份及过期 RST/图片已清理，不再保留 `legacy/` 或 `docs/历史资料/` 副本。当前 `FOE_SUPPORTED`、`EOE_SUPPORTED` 均为 0；将来启用这些能力需重新提供并验证适配。清理范围见[验证记录](../验证记录/2026-11-13-遗留清理验证记录.md)。

目录决定维护归属，不等于控制实现已经解耦。后续调整先检查[目录规划与实施状态](../设计资料/单片机工程目录重构规划.md)、[生成文件清单](生成文件与来源清单.md)和[迁移验证记录](../验证记录/2026-11-13-混合语言目录迁移验证记录.md)。
