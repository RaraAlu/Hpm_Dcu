# DCU 目录层级与维护职责

核对日期：2026-11-17。以下是已经落地的目录，不是待建示意。电机和产品 PDO/CoE 适配采用 C++17，SSC 栈、RTOS 编排和硬件适配保持 C；RTOS 复用 SDK 启动和移植，本页不承诺板上业务、实时性或停机效果。

`firmware/protocols/` 是协议执行代码，根 `protocol/` 是对外协议交付物；`firmware/cfg/` 是板上固件配置，`scripts/cfg/` 是主机和探针配置。可迁移配置放在所属模块的 `cfg/`，不再保留根 `config/` 或 `firmware/config/`；固定工具入口和第三方目录的例外见[配置文件归档规范](配置文件归档规范.md)。

BSP 通过根 CMake 设置的 `BOARD_SEARCH_PATH=firmware/bsp` 由 SDK 注册一次。不要再在 `firmware/CMakeLists.txt` 中重复 `add_subdirectory(bsp/...)`。SDK 内原 `boards/hpm5e00evk/` 已移出，不保留第二份活动板级实现。`board.h` 中的历史日志名称仍为 `hpm5e00evk`，不代表构建选错板卡。

## 文件命名

- 使用小写 `snake_case`，以实际对象和职责命名，如 `ethercat_cycle`、`ethercat_can_task`、`can_bus_scheduler`；不再将实现笼统命名为 `app_runtime` 或 `cycle_hardware`。
- 同一实现的接口使用相同词干。`gateway_application.cpp/.hpp` 是 C++ 原生业务实现及契约，不是底层电流环控制器。字典和 PDO 相关的 C 入口统一归 `motor_ethercat.h`，由通信适配层实现。
- 配置名说明范围：`gateway_schedule_policy.hpp` 是网关的总线时序与预算，`ethercat_can_task_config.h` 是任务资源，`cycle_timer_map.h` 是板级定时器映射。固定线格式保留 `*_pdo_layout`，不与工程配置混用。
- `encos_parameter_transactions` 明确保留厂商参数兼容范围，留在 ENCOS 驱动目录，不命名成通用参数框架；已有清晰名称不为统一前缀而重命名。
- `digital_io.h` 是 SSC 三个核心源文件直接包含的接入头，保留该固定名称；实际应用回调实现为 `ethercat_callbacks.c`。第三方文件、生成物、设备标识和 C 函数符号不因文件改名改变。
- 测试文件跟随受测模块命名；文档文件名继续使用中文。重命名同步修改引用、CMake 与文档链接，删除旧副本，并清理旧归档后重建。

## 工具与资料

- `scripts/dcu.py` 的 SDK 定位已更新为 `third_party/hpm_sdk`，构建与目标保护入口不变；OpenOCD 仍使用该 SDK 的 `boards/openocd` 资源。
- 工具锁文件在 `tools/cfg/`，OpenOCD 在 `debug/cfg/`，板级主机参数和 USB 规则在 `scripts/cfg/`；脚本已同步引用。`.tools/` 安装位置、输出目录和两个受保护调试启动项不变，`.vscode/` 保留固定入口并通过 CMake 提供器和编译数据库获得源码路径。
- Python 测试入口现位于 `tests/host/`，CLI 和 CTest 同步发现。`tests/host/motor/` 是原生 C/C++ 测试源码，不是板上固件。
- 调度测试独立编译生产 `can_bus_scheduler.cpp`，不依赖 SDK；电机集成测试同时编译实际 CoE/PDO/事务模块，并可启用 ASan/UBSan。
- `tests/host/freertos/` 编译生产内核和上下文，配合可选 Unicorn 执行；`tests/host/canfd/` 编译生产发送适配并注入故障交错，均不访问目标板。
- `tools/protocol/generate.py` 已取代旧 JS/PowerShell 入口，从可读定义统一生成 C 类型/存储、SSC 字典、ESI 和 SII；只读一致性检查、无旧输出再生成、布局及 EEPROM 身份迁移均纳入宿主测试。
- 旧 SSC 工程、数字量示例、FoE/lwIP/Modbus 适配、构建备份及过期 RST/图片已清理，不再保留 `legacy/` 或 `docs/历史资料/` 副本。当前 `FOE_SUPPORTED`、`EOE_SUPPORTED` 均为 0；将来启用这些能力需重新提供并验证适配。清理范围见[验证记录](../验证记录/2026-11-13-遗留清理验证记录.md)。

目录决定维护归属，不等于控制实现已经解耦。后续调整先检查[项目总计划](../设计资料/项目总计划.md)、[生成文件清单](生成文件与来源清单.md)和[迁移验证记录](../验证记录/2026-11-13-混合语言目录迁移验证记录.md)。
