# 设备驱动扩展与接入规范

更新日期：2026-11-25。生产 Profile 按 `protocol` 和 `type` 选电机型号。初始化先对照代码型号表核对配置，配置不符时拒绝绑定；这不是通过 CAN 自动识别实物型号。

## 已实现范围

| 模块 | 职责 | 当前限制 |
| --- | --- | --- |
| [MotorDriver / MotorDevice](../../firmware/devices/motor/motor_driver.hpp) | 通用命令、反馈、能力描述、驱动注入与错误结果；失败不提交输出 | 当前是 CAN 电机的周期编解码 Interface，不是完整的通用运动控制器 |
| [EncosMotorDriver](../../firmware/devices/motor/drivers/encos/encos_driver.hpp) | 验证原生路由、量程与帧格式，直接将通用命令/反馈交给 ENCOS 编解码 | 不依赖生成 DTO |
| [BjcxMotorDriver](../../firmware/devices/motor/drivers/bjcx/bjcx_driver.hpp) | 普通状态轮询与反馈解码，或 Profile 显式选择的限额全零 MIT | 这两种模式互斥；不提供一般使能、非零 MIT 或物理停机能力 |
| [ENCOS 运动编解码](../../firmware/protocols/encos/encos_motor.hpp) | `Command` 编码为 CAN 帧、CAN 周期反馈解码为 `Feedback` | 纯 C++ 契约，无旧运动 C API 或兼容包装；使用已验证的路由与量程 |
| [产品驱动绑定](../../firmware/devices/motor/motor_driver_binding.cpp) | 按 `protocol` 和 `type` 选择静态驱动实例，校验原生轴配置 | 不转换 PDO/SDO；线格式适配归 `comm/ethercat/motor_axis_codec.hpp` |
| [ENCOS 型号表](../../firmware/devices/motor/drivers/encos/cfg/encos_models.h) | 记录 4315、7216、7220、9025 的产品规格及已核实的协议量程 | CoE `ModelProfileId=0x8000` 仍是编码标识，不是商品型号 |
| [bjcx 型号表](../../firmware/devices/motor/drivers/bjcx/cfg/bjcx_models.h) | 记录 HRA40H-101、HRA55H-100 的减速比、转速和输出扭矩规格 | 产品数据不作为 CiH408 协议换算或台架限值；CoE `ModelProfileId` 仍读回 0 |
| [公共 CAN 帧](../../firmware/ports/can_frame.h) | C/C++ 共用的厂商无关帧类型 | 经典 CAN 最多 8 B；FD 按 DLC 换算，最多 64 B。FullBus/旧旁带每槽最多 8 B，SingleFd 才有完整 64 B 载荷区 |
| [ImuDriver / ImuDevice](../../firmware/devices/imu/imu_device.hpp) | 可替换驱动、样本校验、初始化重试、有效性、接收时间与过期处理 | 没有具体芯片、采样总线或主循环采集接入 |
| `UnavailableImuDriver` | 明确返回未接入，不制造有效样本 | 用于未接入状态及宿主测试，不冒充传感器 |
| [USTC V2 表情头监测](../../firmware/devices/head/head_health.hpp) | 根据实际收到的标准帧区分四板心跳、16 个反馈组的时效及维护响应错误；只在选中对应 Profile 的混合档 OP 会话启用 | 被动监测，不解释姿态、不自动重发。RK 通过 [can0 状态和只读 CoE 明细](按启动配置生成周期布局.md#头板故障怎么读)定位问题；未知手协议不参与判定 |

公共设备 Interface 只依赖标准固定宽度类型和公共 CAN 帧。生产驱动按 Profile 绑定，不使用宿主夹具建立所有权；历史替身结果不作为本机型的验收。

## 电机调用与数据契约

生产电机 PDO 由 EtherCAT 适配层解码为 `Command`，[网关](../../firmware/app/gateway/gateway_application.cpp)检查许可，[MotorInstance](../../firmware/devices/motor/motor_instance.cpp)检查轴状态和限值，实际绑定的驱动提供编码。网关调度器再把有效帧交给 MCAN。SDO 运动对象保留拒绝语义，不是与 PDO 并行的运动命令入口。

头手单槽走独立的设备边界：[生产初始化](../../firmware/app/production_init.cpp)按 Profile 绑定[设备观察接口](../../firmware/ports/cyclic_can_observer.hpp)。网关只通知会话开始、收到 CAN 帧和会话结束，并合并设备返回的通道状态位；不识别头板 ID、心跳周期或错误码。这些判定和状态归属 [devices/head](../../firmware/devices/head/head_health.cpp)，CoE `0x2104` 读取同一份设备状态。

驱动只做有界的编解码，不执行 CAN I/O、等待应答、分配堆内存或改变 EtherCAT 状态。编码成功只代表生成了合法帧，不代表已经进入发送器、更不代表电机已经收到；入队、完成、取消和预算仍由现有 C 适配及调度管理。

通用命令保留明确的定点单位，避免原协议转换规则在重构时发生舍入变化：

| 字段 | 单位或语义 |
| --- | --- |
| `position_urad`、`velocity_urad_s` | 微弧度、微弧度每秒 |
| `torque_mNm`、`current_cA` | 毫牛米、百分之一安培 |
| `current_limit_dA` | 十分之一安培，与电流反馈单位不同 |
| `kp_centi`、`kd_milli` | 现有阻抗模式增益的百分之一、千分之一数值尺度；具体物理解释由协议实现负责 |
| `control_bits` | 应用层 ARM、STOP、复位故障和 StartMotion 意图，不等价于驱动器的使能/制动报文 |
| `reserved_flags` | 兼容校验保留字段，当前必须为 0 |
| 温度反馈 | 十分之一摄氏度 |

`capabilities()` 声明控制模式、反馈字段、力矩常数及主动停止命令能力。不支持的模式返回 `Unsupported`；未绑定返回 `NotConfigured`。公共帧检查拒绝非法 DLC、标识符、标志组合；解码拒绝未声明字段。编码或解码失败均不覆盖调用者旧输出。

目前 `active_stop_command=false`。原停止动作仍是取消待发送帧并禁止后续控制发送，不能由此推出零力矩、失能、制动或物理急停。初始启动、控制权、租约和反馈超时仍在现有状态机，未把这些职责伪装成已完成通用抽象。

每轴绑定静态驱动槽，驱动对象及其配置彼此独立，不使用运行时插件或自动设备探测。`MotorDevice` 不拥有驱动，驱动必须比设备活得更久；`bound()` 只表示存在绑定，不表示电机在线或已经使能。配置和绑定只在原有 PREOP/停止校验流程内更新。全局静态对象只保存数据/虚表，不执行硬件操作；SDK 启动过程具有 C++ 初始化机制，但新映像尚未上板验证。

## 参数与协议边界

生产 Profile 的 schema 3 要求电机和透传设备显式填写 `type`，支持完整铭牌型号或对应驱动内的短名。ENCOS 可以写 `type: 7216`，数字短名加引号也可；bjcx 可以写 `type: 55h_100`，保留减速比以区分型号。编译后的 Profile 统一保存完整铭牌型号。未知型号、同驱动内的别名冲突和协议混配都不能通过选型校验。已部署的 YAML 即使只把全名换成短名，摘要也会变化，仍需同步 RK 配置。

新增型号只需在对应驱动 `cfg/` 的 `models[]` 追加一个条目：填写唯一的短名、完整铭牌型号，以及带单位的具名字段，如 `rated_torque_Nm = 5.4`。ENCOS 的厂家规格写在 `datasheet`，只有实测核实过的协议编码量程才写入 `mit`。未核实则留空，不能用厂家性能表代填。Profile 仍负责应用限位、KP、KD、位置编码及超时，不重复填写型号表已有的协议参数。初始化再次核对型号、路由和控制配置。

当前正式 Profile 保持 `can2` 的 `EC-A7216-P2-22H` 仅作透传，`can3` 的 `HRA55H-100` 保持原有模式。初始化不向这两个电机发送新的型号探测帧，不以 ENCOS Kt、MIT 量程或 bjcx 固件版本冒充唯一型号证据，也不把型号表上的额定/峰值参数作为台架安全限位。

ENCOS 在 Profile 的 `devices` 中登记为控制轴后，通过正常生产 PDO 使用 MIT，不需要专用档位或全零模式配置。轴仍须通过就绪探测、静止门槛、ARM 和启动边沿。`KP=KD=前馈力矩=0` 的 MIT 首帧按原命令编码，不先发送位置保持帧；该次启动不允许随后在线增加增益或前馈力矩。需要施加力矩时，须停止并重新走普通启动保护。参数为零不代表物理失能。

时间戳 ENCOS 阻抗轴的周期批次按硬件 TX 帧尾续发；不等待上一台电机回包才发下一台。间隔以 [CAN 传输常量](../../firmware/comm/canfd/can_transport.h) 为准，当前为 50 µs，不把旧镜像的 100 µs 当作现行值。预编码何时可复用、首次启动替换与逐轴 N+1 判据见[周期契约](周期锁存与反馈发布契约.md)。

**普通 BJCX 状态轮询**分两步：[驱动](../../firmware/devices/motor/drivers/bjcx/bjcx_driver.cpp)的 `prepare_status_poll()` 只检查询问间隔并构造帧；[事务层](../../firmware/app/gateway/can/can_transactions.cpp)按请求和预计回包计算预算，即使没有活动控制轴也要检查余额。窗口不允许、预算不足或 `dcu_can_submit()` 返回 0 时，不扣款、不建立在途事务，也不重置轮询时间。拿到有效 TX ID 才扣款、调用 `status_poll_submitted()` 并登记事务；这不等于 TX 已完成或收到了应答。当前生产 BJCX 为 `motion_parameters: pending`；只允许状态轮询，不据其他配置的 MIT 实测认定本路径通过。

四档线上尺寸及不同 revision 的差异见[布局说明](按启动配置生成周期布局.md)。生产代码直接使用 `dcu_can_frame_t`，已删除 `encos_frame_t` 别名及 `encos_encode/encos_feedback`，不提供兼容包装；运动编解码使用 `encos_motor.hpp` 的 C++ 契约。`encos_motor.h` 定义原生量程/配置，`encos_service.h` 提供仍被使用的查询、参数与字节辅助 C 函数；SSC/C 应用边界继续保留 C 链接。

反馈方向为 `CAN -> encos::decode_feedback() -> Feedback -> 轴私有状态/快照 -> EtherCAT 适配 -> mc_axis_tx_t`。驱动与核心不经过线格式中间值；查询功率、新鲜度、故障和诊断由轴持有，通信层仅映射快照。通用 `MotorDevice` 的能力检查、帧合法性检查和失败不提交契约仍保留，没有为减少映射而绕过保护层。

ENCOS 查询、参数写入、读回校验及维护命令仍是厂商专用服务，不强行改造成所有电机通用的参数表。方言由注册信息明确识别；未知配置不能落入 ENCOS 事务。不要把诊断/旧夹具的 PREOP 参数权限套到生产 owner；生产接入条件见[重连与授权](生产网关一次确认接入.md)。

事务由 [encos_parameter_transactions.cpp](../../firmware/devices/motor/drivers/encos/encos_parameter_transactions.cpp) 私有管理，调用方提交原生请求、检查状态和同步消费观察结果；禁止公开可写的共享事务数组。编码失败必须先拒绝，再计算载荷长度或复制校验值。维护回复按实际发送的节点地址匹配，不能依赖尚未 Apply 的轴运行配置。字典解析和缓存更新由 `motor_services.cpp` 负责，事务不读写字典。查询 36 的组系数和 39 的编码器角度已覆盖，36 的模式位因手册图文冲突只保留原始回复，不推测更新校准模式。

早期迁移曾用固定报文和冻结参考算法（`680d62e`）作宿主差分核对；该回归已退役。新运动编解码函数先在临时值中完成转换，成功后才更新输出；生产设备入口原本已有失败不提交保护，此次没有放宽。旧底层 C 函数失败时的部分写入行为不予保留；不声称所有输入下的执行步骤或整个 ELF 完全相同。

公共反馈模型允许设备只声明部分字段，但当前轴状态机的周期就绪判定要求同一快照具有位置、速度、电流，轴会拒绝缺少这些字段的周期反馈。分帧反馈设备需要先实现带各字段新鲜度的聚合适配，不能把单个电流或温度包误当成启动握手完成。超出产品电流/故障码字段宽度的数值也拒绝发布，不能截断。

## IMU 契约

IMU 公共模型采用加速度 `m/s^2`、角速度 `rad/s`、`wxyz` 四元数和摄氏温度。实际驱动负责原始计数、方向及单位转换，只为真实可用字段设置有效位；没有姿态输出时不得填入单位四元数冒充有效姿态。

- `initialize()`、`read()` 必须有界且非阻塞；初始化返回 `NotReady` 时下次轮询重试，不在接口里休眠等硬件。
- `read()` 只有返回 `Ok` 且校验通过才发布新序号；`NoData` 不刷新接收时间，也不制造样本。
- 各有效向量/温度必须为有限值，姿态必须接近单位四元数，平方模误差不得超过 `0.01`。超出该契约的原始四元数应由具体驱动或姿态处理校验，不在这里默默归一化。
- 过期使用调用方传入的本地单调纳秒时间和接收时间，不使用传感器时钟计算年龄。样本另标记捕获时间所属域，不能把“纳秒数值”解释为已经与 EtherCAT DC 同步。
- 达到最大年龄即失效；I/O 错误、未接入、非法字段、非有限数值或时钟回退均不得继续报告有效数据。最大年龄必须非零，由真实产品采样需求确定，不猜测默认值。

`poll()` 和 `snapshot()` 由同一执行上下文串行调用；公共模型不提供锁或跨核快照机制。未来从中断或其他线程供数时，具体传输/发布适配必须明确缓冲区所有权与同步方式，不能并发写读这些普通成员。

当前没有为 IMU 实例编造总线、型号或采样周期，也没有把公共浮点模型直接复制到旧 packed `mc_imu_t`。对象 `0x6300` 和 PDO 仍使用原零有效位；接入真实驱动后，须单独确认旧线格式的比例、有效位和时钟语义，再实现发布适配。

## 新增设备步骤

1. 同协议不同电机型号优先复用实现，核实量程、限位、方向、控制模式及停止行为；产品可调配置放入所属模块 `cfg/`，不猜测实物参数。
2. 新 CAN 协议实现 `MotorDriver`，补充能力与错误结果，核对固定报文、设备资料以及超时、拒绝路径；在产品绑定中增加真实实例和显式注册，不引入默认回退。
3. 核对现有启动握手、查询新鲜度、地址范围、帧长度及事务是否适用；不适用时实现相应适配，不能只注册一个类就宣布可以运动。
4. 新 IMU 实现 `ImuDriver` 并满足上述时间/有效性契约，再接入实际周期与发布适配；型号、接口、坐标系、采样率和 DC 同步要求必须明确。
5. 需要 UART/SPI/I2C、电机裸机 FOC、现有映射容纳不下的帧或新反馈字段或新参数字典时，另行扩展相应 Interface/传输及版本化映射，不直接放大公共帧数组或改旧 PDO 字节布局。
6. Ubuntu 按受影响的生产预设编译并检查镜像，不运行宿主回归。上板前确认动力隔离及当次授权；按[调测要求](../../AGENTS.md)验收普通轮询或生产运动路径，各自保留提交、完成和反馈证据。

设备接口初次接入的资源代价见[设备抽象基础验证记录](../验证记录/2026-11-13-设备抽象基础验证记录.md)。后续已移除旧电机全局关中断区、CAN→电机定时反向调用及业务核心的字典/生成 DTO 依赖。历史结构评审见[固件评审及实施记录](../设计资料/固件目录与代码划分评审.md)。ENCOS 和 BJCX 的实测范围按镜像、设备与命令分别记录在[项目总计划](../设计资料/项目总计划.md)；IMU 仍未接入。
