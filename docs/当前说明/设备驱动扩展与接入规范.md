# 设备驱动扩展与接入规范

更新日期：2026-11-17。当前只有一种实际电机协议实现：ENCOS，使用既有自定义范围配置 `ModelProfileId=0x8000`，不推测具体安装型号。可替换的驱动 Interface 已接入现有周期命令和反馈路径；没有增加虚构的第二种固件驱动，没有连接目标板。

## 已实现范围

| 模块 | 职责 | 当前限制 |
| --- | --- | --- |
| [MotorDriver / MotorDevice](../../firmware/devices/motor/motor_driver.hpp) | 通用命令、反馈、能力描述、驱动注入与错误结果；失败不提交输出 | 当前是 CAN 电机的周期编解码 Interface，不是完整的通用运动控制器 |
| [EncosMotorDriver](../../firmware/devices/motor/drivers/encos/encos_driver.hpp) | 验证配置、节点地址与帧格式，直接将通用命令/反馈交给 ENCOS 编解码 | 不再构造 `mc_axis_rx_t/mc_axis_tx_t`；配置仍使用产品类型，只有这个生产实现 |
| [ENCOS 运动编解码](../../firmware/protocols/encos/encos_motor.hpp) | `Command` 编码为 CAN 帧、CAN 周期反馈解码为 `Feedback` | 纯 C++ 契约，无旧运动 C API 或兼容包装；使用已验证的路由与量程 |
| [产品驱动绑定](../../firmware/app/motor/motor_driver_binding.cpp) | `ModelProfileId` 选择、静态实例、PDO 数据与通用模型的一次转换、参数方言判断 | 产品适配依赖生成类型；通用设备 Interface 不依赖这些类型 |
| [驱动注册配置](../../firmware/app/motor/cfg/motor_drivers.hpp) | 声明允许使用的型号配置和驱动种类 | 只注册 `0x8000`；未知项拒绝，重复编号在编译期报错 |
| [公共 CAN 帧](../../firmware/ports/can_frame.h) | C/C++ 共用的厂商无关帧类型 | 当前仅支持 DLC 0..8；不因名称为 CAN FD 就宣称支持 64 字节载荷 |
| [ImuDriver / ImuDevice](../../firmware/devices/imu/imu_device.hpp) | 可替换驱动、样本校验、初始化重试、有效性、接收时间与过期处理 | 没有具体芯片、采样总线或主循环采集接入 |
| `UnavailableImuDriver` | 明确返回未接入，不制造有效样本 | 用于未接入状态及宿主测试，不冒充传感器 |

公共设备 Interface 只依赖标准固定宽度类型和公共 CAN 帧。生产驱动与宿主测试替身通过同一个 Interface 使用；替身不注册到固件，不作为第二种电机已适配的证据。

## 电机调用与数据契约

当前路径为：

```text
既有电机状态机及调度
  -> 产品绑定：PDO/SDO 命令转换为 Command
  -> MotorDevice
  -> MotorDriver Interface
  -> EncosMotorDriver
  -> encos::encode_motion(Command)：生成 CAN 帧
  -> 返回应用，由调度提交给 C CAN 传输
```

驱动只做有界的编解码，不执行 CAN I/O、等待应答、分配堆内存或改变 EtherCAT 状态。编码成功只代表生成了合法帧，不代表已经进入发送器、更不代表电机已经收到；入队、完成、取消和预算仍由现有 C 适配及调度管理。

通用命令保留明确的定点单位，避免原协议转换规则在重构时发生舍入变化：

| 字段 | 单位或语义 |
| --- | --- |
| `position_urad`、`velocity_urad_s` | 微弧度、微弧度每秒 |
| `torque_mNm`、`current_cA` | 毫牛米、百分之一安培 |
| `current_limit_dA` | 十分之一安培，与电流反馈单位不同 |
| `kp_centi`、`kd_milli` | 现有阻抗模式增益的百分之一、千分之一数值尺度；具体物理解释由协议实现负责 |
| `control_bits` | 应用层 ARM、STOP、复位故障和 StartMotion 意图，不等价于驱动器的使能/制动报文 |
| `reserved_flags` | 兼容校验保留字段，当前必须为 0 |
| 温度反馈 | 十分之一摄氏度 |

`capabilities()` 声明控制模式、反馈字段、力矩常数及主动停止命令能力。不支持的模式返回 `Unsupported`；未绑定返回 `NotConfigured`。公共帧检查拒绝非法 DLC、标识符、标志组合；解码拒绝未声明字段。编码或解码失败均不覆盖调用者旧输出。

目前 `active_stop_command=false`。原停止动作仍是取消待发送帧并禁止后续控制发送，不能由此推出零力矩、失能、制动或物理急停。初始启动、控制权、租约和反馈超时仍在现有状态机，未把这些职责伪装成已完成通用抽象。

每轴绑定静态驱动槽，驱动对象及其配置彼此独立，不使用运行时插件或自动设备探测。`MotorDevice` 不拥有驱动，驱动必须比设备活得更久；`bound()` 只表示存在绑定，不表示电机在线或已经使能。配置和绑定只在原有 PREOP/停止校验流程内更新。全局静态对象只保存数据/虚表，不执行硬件操作；SDK 启动过程具有 C++ 初始化机制，但新映像尚未上板验证。

## 参数与协议边界

现有三档 PDO、对象字典字段、接口版本、ESI/SII 和生成存储均未修改。`encos_frame_t` 仍是公共帧类型的 C 别名。已删除 `encos_encode/encos_feedback` 的声明与实现，不提供别名或兼容入口；运动编解码只使用 `encos_motor.hpp` 中的 C++ 契约。`encos_motor.h` 保留仍被使用的配置、查询、参数与字节辅助函数，SSC/C 应用边界也继续保留 C 链接。

反馈方向为 `CAN -> encos::decode_feedback() -> Feedback -> 产品绑定 -> mc_axis_tx_t`。绑定只更新周期反馈字段和有效位，保留功率有效位及状态、诊断、年龄等其他字段；驱动和协议核心不再经过线格式中间值。通用 `MotorDevice` 的能力检查、帧合法性检查和失败不提交契约仍保留，没有为减少映射而绕过保护层。

ENCOS 查询、参数写入、读回校验及维护命令仍是厂商专用兼容路径，不强行改造成所有电机通用的参数表。方言由注册信息明确识别；未知配置不能落入 ENCOS 事务。已知 ENCOS 的 PREOP 参数事务仍允许先于首次 Apply 配置，周期运动仍须完成原使能和配置条件。

事务现由 [encos_parameter_transactions.cpp](../../firmware/app/motor/encos_parameter_transactions.cpp) 私有管理，调用方只能提交操作、检查状态和消费观察结果；禁止公开可写的共享事务数组。编码失败必须先拒绝，再计算载荷长度或复制校验值。维护回复按实际发送的节点地址匹配，不能依赖尚未 Apply 的轴运行配置。此模块仍读写旧字典兼容存储，不是通用参数模型。

合法命令与反馈由固定报文和独立冻结参考算法作差分核对，参考来源为改动前 `680d62e`，只链接到宿主测试。新运动编解码函数先在临时值中完成转换，成功后才更新输出；生产设备入口原本已有失败不提交保护，此次没有放宽。旧底层 C 函数失败时的部分写入行为不予保留；不声称所有输入下的执行步骤或整个 ELF 完全相同。

公共反馈模型允许设备只声明部分字段，但当前产品状态机的周期就绪判定要求同一快照具有位置、速度、电流，产品绑定会拒绝缺少这些字段的周期反馈。分帧反馈设备需要先实现带各字段新鲜度的聚合适配，不能把单个电流或温度包误当成启动握手完成。超出旧电流/故障码字段宽度的数值也拒绝发布，不能截断。

## IMU 契约

IMU 公共模型采用加速度 `m/s^2`、角速度 `rad/s`、`wxyz` 四元数和摄氏温度。实际驱动负责原始计数、方向及单位转换，只为真实可用字段设置有效位；没有姿态输出时不得填入单位四元数冒充有效姿态。

- `initialize()`、`read()` 必须有界且非阻塞；初始化返回 `NotReady` 时下次轮询重试，不在接口里休眠等硬件。
- `read()` 只有返回 `Ok` 且校验通过才发布新序号；`NoData` 不刷新接收时间，也不制造样本。
- 各有效向量/温度必须为有限值，姿态必须接近单位四元数，平方模误差不得超过 `0.01`。超出该契约的原始四元数应由具体驱动或姿态处理校验，不在这里默默归一化。
- 过期使用调用方传入的本地单调纳秒时间和接收时间，不使用传感器时钟计算年龄。样本另标记捕获时间所属域，不能把“纳秒数值”解释为已经与 EtherCAT DC 同步。
- 达到最大年龄即失效；I/O 错误、未接入、非法字段、非有限数值或时钟回退均不得继续报告有效数据。最大年龄必须非零，由真实产品采样需求确定，不猜测默认值。

`poll()` 和 `snapshot()` 由同一执行上下文串行调用；公共模型不提供锁或跨核快照机制。未来从中断或其他线程供数时，具体传输/发布适配必须明确缓冲区所有权与同步方式，不能并发写读这些普通成员。

当前没有为 IMU 实例编造总线、型号或采样周期，也没有把公共浮点模型直接复制到旧 packed `mc_imu_t`。对象 `0x6300` 和 PDO 仍使用原零有效位；接入真实驱动后，须单独确认旧线格式的比例、有效位和时钟语义，再实现发布适配。

## 新增设备步骤

1. 同协议不同电机型号优先复用实现，核实量程、限位、方向、控制模式及停止行为；产品可调配置放入所属模块 `cfg/`，不猜测实物参数。
2. 新 CAN 协议实现 `MotorDriver`，补充能力与错误结果，并通过宿主替身、固定报文和设备资料验证；在产品绑定中增加真实实例和显式注册，不引入默认回退。
3. 核对现有启动握手、查询新鲜度、地址范围、帧长度及事务是否适用；不适用时实现相应适配，不能只注册一个类就宣布可以运动。
4. 新 IMU 实现 `ImuDriver` 并满足上述时间/有效性契约，再接入实际周期与发布适配；型号、接口、坐标系、采样率和 DC 同步要求必须明确。
5. 需要 UART/SPI/I2C、电机裸机 FOC、长 CAN FD 帧、新反馈字段或新参数字典时，另行扩展相应 Interface/传输及版本化映射，不直接放大公共帧数组或改旧 PDO 字节布局。
6. 分别验证 Debug/Release、协议样例、故障路径、内存和实时预算；上板重新确认动力隔离及当次操作授权。

设备接口初次接入的资源代价见[设备抽象基础验证记录](../验证记录/2026-11-13-设备抽象基础验证记录.md)。后续 RTOS 改造已移除旧电机全局关中断区和 CAN→电机定时反向调用，并分离协议适配、事务和调度。最新轴状态与运动编解码简化证据见[固件评审及实施记录](../设计资料/固件目录与代码划分评审.md)。控制状态机仍使用生成 DTO，应用与参数服务仍有字典依赖，完整的协议中立参数模型和真实设备验收尚未完成。
