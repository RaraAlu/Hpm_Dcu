# 透传布局切换

RK 决定何时让电机停住，以及何时申请 EtherCAT 状态迁移。DCU 不通过切档发零力矩或判定电机静止。电机档的看门狗、保护和生产就绪条件不变；纯透传档的就绪只代表本地配置和 CAN 状态，不代表电机就绪。

通道名称统一使用 BSP 的零起始编号：`can2` 对应 `channel: 2`，`can3` 对应 `channel: 3`。Profile 的 `bus` 也用同一编号。

## 邮箱接口

对象 `0x2101` 不映射进 PDO，不支持 Complete Access。请求和动作不是可回读的配置。

| 子索引 | 方向与长度 | 含义 |
| --- | --- | --- |
| 01 | 只写，41 字节 | 字节 0 为目标档位；1..4 为 Profile ID，5..8 为当前修订号（均为小端 U32），9..40 为 Profile 的 32 字节摘要原始值。只接受 OP 或 PREOP。 |
| 02 | 只写，U8 | 1：显式复位，仅 PREOP 且透传槽已退休；2：报告透传故障，例如 RK 观测到 WKC 不符。 |
| 03 | 只读，U8 | 0 Disabled、1 Requested、2 Armed、3 Active、4 Draining、5 Faulted。调试器也可查看网关实例的 `layout_.state`。 |
| 04 | 只读，U32 | 累计透传丢弃数，按无符号差值比较；含软件拒收、透传队列溢出以及透传通道的硬件 RX 丢弃。混用通道的硬件丢弃无法区分帧所有者。 |
| 05 | 读写，U32 | 纯透传配额，按小端字节顺序对应 can0..can3，每路 0..8 帧/2 ms。只在 PREOP、无活动电机且所有透传 TX 槽已退休时整组替换；禁用总线必须写 0。失败不改旧值，不撤销在途帧。 |
| 06 | 读写，U8 | 电机总线发送权掩码，bit 0..3 表示 can0..can3。仅在 PREOP、目标为档 3 且协商 Requested 时暂存；被授予的通道必须配置了电机、透传配额非零，发送槽已退休。映射提交才生效，退 OP 或故障时撤销；读回的是已生效掩码。 |
| 07 | 只读，U32 | 本次启动全板 CAN 控制器发送完成计数。包含电机档流量，验收须对比独占会话前后的差值，不能当作电机应答计数。 |
| 08 | 只读，U32 | 本次启动透传发送取消终态计数；取消不保证竞争窗口内帧未上总线。 |

当前 Profile ID、修订号可在 `0x2100:04/05` 核对；摘要来自匹配的 Profile。各档独立，由两侧的完整 assignment 决定，不按报文内容猜测。

| 档位 | 主站输出 SM2 / 主站输入 SM3 | 内容 |
| --- | --- | --- |
| 0 Motor | 依启动 Profile；默认 72 / 80 B | 板头、已配置的通道和有对应方向的轴 |
| 1 MotorWithRaw（上电默认） | 档 0 各加 48 B；默认 120 / 128 B | 电机区后紧接双槽旁带；物理轴掩码与对象索引不变 |
| 2 Raw | 每向 32 + 128 × 已配置通道数；默认 288 B | 板头与对应通道的 FullBus；不是 88 B 单帧档 |
| 3 SingleFd | 88 / 88 B | 起始字节即单个 `mc_raw_t`；没有板头、电机、通道块或 IMU |

同一生产镜像保留 can3 和它的电机。纯透传配额从 Profile 初始化（当前全零），只存在 RAM，退 OP 或换档不清空，重启恢复 Profile 默认。只在档 2/3 使用这组配额，0 禁止该路透传收发；档 0/1 始终用原始通道角色和原始旁带权限。配额不会启用未配置的 CAN 控制器，也不会改变帧格式、位率、TDC 或 Profile ID/修订号。档 2/3 不映射电机 PDO，HPM 不自产电机控制、参数请求或就绪探测；保留物理设备清单，回切后重新按原 Profile 建立就绪。

所有 CAN 通道的透传收发均不使用 CAN ID 白名单，通道启用、配额和帧格式校验仍有效。纯透传下，未配置运动轴的通道允许 `0x7FF`；已配置运动轴的通道默认禁止向电机 ID 发帧，仅档 3 已明确移交给 RK 时解除电机 ID 发送保护，而 `0x7FF` 仍禁止发送。RK 接管前负责停车，接管后负责设备协议及安全停机。

## 单帧档线协议

`0x1C12 = [0x1641]` 映射输出对象 `0x7301`，`0x1C13 = [0x1A42]` 映射输入对象 `0x6401`。双方布局相同，多字节量为小端；老的 `0x7300/0x6400` 仍是 48 B。

| 字段 | 子索引（十六进制） | 字节偏移 | 宽度（B） |
| --- | --- | ---: | ---: |
| BatchSeq | 01 | 0 | 4 |
| ValidMask | 02 | 4 | 1 |
| SlotCount | 03 | 5 | 1 |
| Flags（批标志，置零） | 04 | 6 | 2 |
| DropCount | 05 | 8 | 4 |
| Reserved | 06 | 12 | 4 |
| CanId | 07 | 16 | 4 |
| Channel（0..3） | 08 | 20 | 1 |
| FrameFlags（帧标志，不与批 Flags 同名） | 09 | 21 | 1 |
| Dlc | 0A | 22 | 1 |
| SlaveMatch | 0B | 23 | 1 |
| Data_0 至 Data_63 | 0C..4B | 24..87 | 各 1 |

SM2 的 DropCount、Reserved、SlaveMatch 置零。`ValidMask == SlotCount`，只接受 0（空批）或 1（一帧）。进 OP 且生产就绪后，先发序号非零的空批建基线；随后每周期递增 BatchSeq，即使无帧也发空批续租。重复序号不重发，不续租；超出已配置的命令租期会闭锁。Dlc 是 CAN 线码而非字节数：64 B 用 15，FD 标志为 0x08，BRS 为 0x10，扩展 ID 为 0x02。

SM3 每次发布最多从一个通道取一帧，轮询通道，不覆盖下一帧；无帧时有效位与计数均为零。DropCount 为网关累计透传丢弃数。SlaveMatch 只在有效帧上读取：它是本次 PREOP 映射时 ESC 配置站址（寄存器 `0x0010`）的低 8 位，不是物理位置、别名或 CAN ID。RK 按实际分配的站址核对；低字节冲突时不能单靠这个字段鉴别从站。Tx 的 BatchSeq 是发布序号，不是对下行命令的回显。

## 主站适配与时序

- RK 生产档 3 按匹配的 `schedule_file` 使用 **2 ms DC Sync0**，相位锁定后才允许发 CAN；不会在 DC 失败时退回 SM2。HPM 另兼容老主站显式选择的非 DC、SM2 事件模式。两者都不等外设应答才发布，主站未读的 SM3 映像不被覆盖，晚到帧留到后续窗口。详见[周期契约](周期锁存与反馈发布契约.md)。
- ESI/SII 的 SM2/SM3 DefaultSize 对应本次构建的档 1，见[启动配置与映射生成](按启动配置生成周期布局.md)。RK 应通过下述 PREOP 事务选择档 3，再配置实际 SM2/SM3 长度均为 88。不能只改拷贝长度，或从旧 SII 复制映射。
- RK 的 `DriverModule` 通过 `SingleFdTransport` 独立配置、校验和交换 88 B PDO，预期 WKC 为 3。不读轴反馈、板头 AcceptedCycleSeq 或 T1R2，也不按电机档偏移取旁带或解释第二槽。
- 正式 Profile 的 `passthrough_devices` 登记透传设备及型号，不分配运动 PDO、不参与就绪探测，也不充当过滤规则。can2 上登记的 ENCOS `EC-A7216-P2-22H` 原 ID 为 `0x01`，位率 1M/5M。该通道须协商纯透传配额，不申请电机总线所有权；可双向透传合法的标准或扩展 CAN ID，包括 ENCOS 使用的标准 ID `0x7FF`。can3 电机配置保持不变。
- SM2 从 `0x1100` 开始，SM3 从 `0x1A30` 开始。88 B 单缓冲最后地址分别为 `0x1157/0x1A87`；按实际三缓冲计，最后地址为 `0x1207/0x1B37`。两者不重叠，也未超过固件的 `0x2FFF` 地址界限，无需新增或移动 SM。
- RK 名义周期仍为 2 ms，保留命令租约和 EtherCAT 看门狗。100 Mbit/s 下，每方向 88 B 净载荷串行化为 7.04 µs。与档 1 的差值取决于启动 Profile，不是端到端节省量。该档跳过电机快照与打包，仅向 SM3 发布 88 B；实际发布耗时、最坏抖动和帧划分需实测。每方向最多 500 帧/秒（全通道合计），按满 FD 为 32,000 B/s；持续超额的 CAN 输入仍可能排队和丢弃。

## RK：生产 can3 切入 88 B

1. RK 先按自身安全策略停车并确认，再主动从 OP 经 SAFEOP 到 PREOP（冷启动已在 PREOP 则不必先进 OP）。这些 SDO 都不会自行把从站踢出 OP。实际退 OP 才结束电机会话；切档只做本地取消和清理，不发送零力矩。在 OP 写配额、复位、assignment 均拒绝；有电机时不要在 OP 请求档 2/3。
2. 在 PREOP 读 `0x2101:03`。如果为 5（Faulted，直接退 OP 后常见），先写 `0x2101:02 = 1`（U8）；未退休时等工作任务消费终态后重试。这个复位不会立刻改变 Faulted 状态。写 `0x2101:05 = 0x01000000`（U32，线上 `00 00 00 01`）并读回：只给 can3 每 2 ms 一帧。不写则生产默认拒绝全部透传。
3. 读 `0x2100:04/05`（Profile ID / 当前修订，均 U32）。写 `0x2101:01`（41 字节）为 `03 | ID_LE32 | 修订_LE32 | 摘要原始32字节`。当前仓库生产配置为 ID 1、初始修订 8，摘要为 `ddb79e78ed6daa4830f4b6a8227c887d9fb482d1d0a02868d34b79a0af4c7b72`（十六进制解码，不是 ASCII）。部署 rev 8 固件时，RK 透传配置须同步使用新修订和摘要；下文实板记录仍是 rev 7。不要为切档提交 `0x2100` 策略。轮询 `0x2101:03` 至 1（Requested，不是 4 Draining）。仅在 RK 明确接管 can3 电机协议和停机责任时，先写 `0x2101:06 = 0x08`（对应 RK 的 `motor_tx_owner: true`；默认关闭）。然后写 `0x2101:02 = 1`。
4. 仍在 PREOP，逐项写，禁用 Complete Access：`1C12:00=0, 1C13:00=0`（U8）；`1C12:01=0x1641, 1C13:01=0x1A42`（U16）；`1C12:00=1, 1C13:00=1`（U8）。RK 按各 88 B 重建 SM2/SM3、域偏移和预期 WKC，保留原 SM 起址，按匹配的调度文件配置 DC Sync0，避免 IgH 自动重配回默认 assignment。只有显式使用旧 SM2 事件模式的主站才禁用 DC Sync0。请求 SAFEOP，两侧完整匹配才提交，状态应为 2（Armed）。
5. 进 OP 后确认 `0x2101:03=3`（Active）及生产 RUNNING（`0x2002:03` 的低字节为 3）；若申请了电机总线发送权，确认 `0x2101:06` 的 can3 位已生效。用序号非零、其余为零的 88 B 空批建立基线；生产 DC 路径确认相位锁定前不发送有效 CAN 请求。等待 CAN 应答时仍每 2 ms 递增 BatchSeq 发送空批续租。SM3 只发布实际收到的 CAN 帧，**不是本地回显**。验收分别核对 EtherCAT WKC、CAN 控制器发送终态，以及对端设备协议规定的应答。

下列历史记录说明当时映射和设备往返，不代表新 DC 路径的时序验收。隔离台架曾用 RK 的 `driver_single_fd_board_test --motor-neutral` 验证：连续 2500 个空批后，can3 上的 HRA55H-100（ID `0x02`）对单笔 16 B 中性 MIT 请求返回了 `0x80`，模式 2、告警 0；发送完成计数增加 1、取消计数不变。任意 ID 的字节回显仍需专用应答端，不是这个电机台架的验收方式。

正式 Profile 1/rev 7 用 `driver_single_fd_board_test --encos-read-position` 验证 can2：只协商 can2 的配额（`0x2101:05 = 0x00010000`），不申请发送权移交；2500 个空批后单发 `E0 01`，收到了 `A0 01 C3 0B 6C 70`（位置 −139.4236°，电机错误码 0）。CAN 控制器完成计数增加 1、取消计数不变，未发使能或运动指令。

## RK：进程内切换透传通道

生产透传配置用 `switch_channels: [2, 3]` 限定可切换通道，`switch_namespace: dcu` 提供 ROS 2 服务 `/dcu/SwitchCanChannel`（`my_ros2_proto/srv/SwitchCanChannel`）。例如请求 `{channel: 2}` 切到 can2。切换只用于未申请电机总线接管的纯透传。

DriverModule 和 HPM 不重启，正式 Profile 的 ID、修订与摘要不变。DriverModule 停收下行、清掉旧会话待发帧，释放旧 EtherCAT 会话，经 PREOP 重新建立目标通道配额与 88 B PDO。切换期间有通信中断，不是保持 EtherCAT OP 热切。服务仅在新通道已进 OP、WKC 为 3 且空批基线成立后返回成功；客户端收到成功后再发送目标通道的帧。

正式 Profile 1/rev 7 的实板验收在同一 AimRT 进程内完成 can2 → can3 → can2，切换耗时分别为 1.481 s、1.536 s，HPM 启动编号始终为 288。两次 ENCOS 位置查询和一次 HRA55H-100 版本查询均从 ROS 2 透传话题返回；CAN 控制器成功发送增加 3、取消不变，未发使能或运动命令。

## RK：回到默认电机档

1. 停止提交有效透传帧。可在 OP 写 `0x2101:01` 请求目标 **1**（其余 40 B 同上），协商不改变当前 AL 状态；轮询至 Requested，再主动退到 PREOP。也可直接退到 PREOP，若 Faulted 则先复位、重新请求目标 1。每次都等到 Requested，在 PREOP 写 `0x2101:02=1`。建议同时写 `0x2101:05=0` 撤销下次纯透传授权。
2. 先将两侧 `:00` 写 0，随后从本机匹配的 `周期布局.json` 取档 1 的有序映射号。分别向 `1C12`（rx）和 `1C13`（tx）从 `:01` 起连续写 U16，最后各写回实际条数。不要把其他 Profile 的数组或容量上限写回。
3. RK 按对应布局重建域，核对长度、WKC 和字段后，再经 SAFEOP 进 OP。需要既有 READY、有效零使能基线、新的 ARM 和启动边沿，不自动续跑；若原有中性 MIT 运行已闭锁，切档也不解锁。需要无旁带的档 0 时，直接使用该 Profile 的档 0 映射。

配额写入、请求、显式复位、透传闭锁都不等于 AL 状态迁移。真正的本地 PDO 周期同步故障会按既有路径停输出并请求 SAFEOP + 同步错误；主站还应处理标准 EtherCAT 看门狗和状态错误。

## 故障和恢复

非预期退 OP、邮箱会话丢失、本地周期故障、主站报告、透传撤销等候超出既有反馈时限，或本次透传会话丢弃超过 8 帧，均可闭锁透传。闭锁清除透传有效标志及旧队列，不改电机命令。导致闭锁的底层故障若也是整机故障，其原有保护仍会触发。

在 Faulted，重新进 OP 或重新分配旧档都不会恢复透传。RK 应在 PREOP 写 `02 = 1`，再以当前 Profile 身份重发 `01`；只有重新映射并进 OP 才能恢复。复位本身不会发 CAN 帧。若需切到电机档，用相同流程请求档 0。

从站不能看到主站计算的聚合 WKC；RK 必须自行判错、废弃旧样本并在邮箱可用时报告。故障后本地镜像和后续发布无有效透传帧，不能撤回已送达主站的 PDO 或已上总线的 CAN 帧。TX 槽退休也不能证明外设已停机或不会再给出晚到回复。
