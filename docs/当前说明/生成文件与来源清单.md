## 来源判断

历史 SSC 升级说明曾将 `tools/generate_encos.js` 称为对象和 PDO 的唯一维护源。该说明原路径为 `docs/电机封装/HPM_ENCOS_SSC与EEPROM升级使用说明.md`，当前工作区已移除，此处仅保留首次核对时登记的线索。该脚本当前无法解析，尚不能核实其内部输入输出关系。因此 **不预先认定 `SSC/encos_interface.json` 是权威输入**，也不直接将历史可读 JSON 替换进去。

以下将文件自身声明、可读脚本中的引用和历史说明分别记录。没有执行再生成，不把同名文件视为已经证明一致。

## 恢复生成链的验收条件

1. 找到可解析的原生成脚本，确认真正的权威数据源与每个输出路径，不从损坏材料猜写协议。
2. 在隔离临时目录生成，与 Git 中现有生成物比较；差异必须逐项解释，不覆盖工作树再看能否编译。
3. 检查对象类型、索引、位宽、顺序、默认值、接口版本、ProductCode/Revision 和三档 PDO 映射。
4. 检查 C 布局、ESI、SII、映射实现和上位机的一致性；SII 还需核对容量、类别和 Alias/Serial 保留流程。
5. 固化离线编解码及映射校验后，再调整生成目录或输入格式。硬件运行与实时性另行验收。

当前映射实现接受的 RxPDO/TxPDO 字节数分别为 `736/1024`、`784/1072`、`544/544`。这些是本地源码事实，不是任意历史方案的验收结果。
