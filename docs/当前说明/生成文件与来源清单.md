# DCU 生成文件与来源清单

核对日期：2026-11-23。普通生产固件构建从选中的启动 Profile 在构建目录独立生成，不改工作树；Git 中保存默认 Profile 的交付物，宿主测试和 `check-protocol` 检查其一致性。

## 唯一维护入口

| 文件 | 职责 |
| --- | --- |
| [接口定义.json](../../tools/protocol/cfg/接口定义.json) | packed 类型、字段顺序/类型/访问权/默认值、对象展开规则、四档可选 PDO 映射目录、常量、SSC 模块信息与 SII 精简设置 |
| [生产 CAN 配置](../../firmware/app/profile/cfg/生产CAN配置.yaml) | 构建期默认的通道与设备；可由 `DCU_CAN_PROFILE_FILE` 显式替换 |
| [设备模板.xml](../../tools/protocol/cfg/设备模板.xml) | 设备标识、ESC/邮箱/SM/FMMU、物理端口、DC 模式、EEPROM 配置和图标；不含生成的 Dictionary/PDO |
| [generate.py](../../tools/protocol/generate.py) | 复用 CAN Profile 校验器，按方向选取实际映射，检查字段范围、SM 地址区间、SII 长度与容量 |

这是基于活动产物和实际调用契约重建的可读源定义，**不是声称找回或修好了原 JS**。旧 JS/JSON 在删除前不可解析，原因仍未确认；可从 Git `c5ede57` 追溯，但不再是活动输入。新来源以迁移前 `c8ea19f` 的 C token、ESI 结构及 SII 分类摘要为独立对照，不能凭同名历史输入覆盖。

## 输出与边界

| 输出 | 内容与使用者 |
| --- | --- |
| [encos_interface.h](../../firmware/generated/encos/encos_interface.h) | 产品线格式、逐字段偏移/尺寸断言、C/C++ 调用声明；沿用文件名，不限定为纯 ENCOS 编码模型 |
| [encos_storage.inc](../../firmware/generated/encos/encos_storage.inc) | 业务对象的初值、访问元数据与存储，含只读布局摘要；仅由 `comm/ethercat/encos_storage.c` 实例化 |
| [gatewayObjects.h](../../firmware/generated/ethercat/gatewayObjects.h) | SSC 对象描述、映射目录及该 Profile 的默认 SM 分配 |
| [digital_ioObjects.h](../../firmware/generated/ethercat/digital_ioObjects.h) | SSC 双遍包含/实例化接入、0xF000 和字典结束项；保留 Beckhoff 许可证提示 |
| [ESI](../../protocol/ethercat/HPM_ENCOS_4CAN_28AXIS_IMU.xml) | 完整产品字典、全部映射及设备描述，供主站使用 |
| [SII BIN](../../protocol/ethercat/HPM_ENCOS_4CAN_28AXIS_IMU.bin) | 16 KiB EEPROM 交付物，含所选 Profile 的默认混合档和实际 SM 大小 |
| [eeprom.h](../../firmware/generated/ethercat/eeprom.h) | 同一 BIN 的逐字节 C 数组，由 SSC 嵌入固件 |
| [布局清单](../../protocol/ethercat/周期布局.json) 与 [主站布局头](../../protocol/ethercat/dcu_profile_pdo.hpp) | 每档各方向的映射、字段与偏移以及布局摘要，供 RK 使用 |

生成器只支持本产品，不是通用 ESI 转 SII 工具。SII 不保存 PDO 名称及非默认 Raw 全量映射；完整名称和替代映射可从 ESI/在线 CoE 获取。四档大小及双端核对办法见[按启动配置生成周期布局](按启动配置生成周期布局.md)。

## 日常命令

```bash
# 只读检查；差异返回非零，不覆盖工作树
python3 tools/protocol/generate.py

# 隔离生成，先审查差异
python3 tools/protocol/generate.py --output-root /tmp/dcu-protocol-review

# 确认输入及差异后，显式更新活动生成物
python3 tools/protocol/generate.py --output-root .

python3 -m unittest discover -s tests/host -p test_protocol_generation.py -v
python3 -m unittest discover -s tests/host -p test_eeprom_migration.py -v
cmake --build --preset hpm-debug --target check-protocol
```

生成器不需要 Node、PowerShell、Beckhoff DLL、网络、SDK 或旧输出。原 `generate_sii.ps1` 已删除，不保留第二套活动入口。不要手改生成物；需要变更线上接口时，先更新定义及接口版本策略，再审查契约测试、主站、C/C++ 调用者和各档映射，不把更新测试摘要当成兼容性证明。

## 历史：2026-11-17 迁移差异

- 类型、索引、位宽、字段顺序、访问权、默认值、接口版本 `0x00010002`、Vendor `0x10000`、ProductCode `2`、Revision `2` 均保持不变。C 格式、注释和常量位置变化，不改变 C token 契约；XML 格式变化不改变字典/PDO 结构。
- 删除 `digital_ioObjects.h` 中不在活动字典、也没有调用者的旧数字量示例声明和实例。保留 SSC 所需文件名、双遍包含方式及 0xF000 契约，不留兼容别名。
- ESI 删除固件已拒绝的非 DC 模式，只声明 `DC Sync0 (1-5 ms)`、AssignActivate `0x300`、Sync0 Factor `1`，不声明 Sync1。
- SII 的 128 字节头及 General/FMMU/SM/默认 TxPDO/RxPDO 类别与迁移前逐字节一致。Strings 将旧 `SM-Synchron` 更新为上述 DC 名称。DC 类别使用 24 字节标准布局：AssignActivate 在偏移 14、Sync0 Factor 在偏移 16、名称/描述索引在偏移 18/19。旧文件的 `0x0300` 位于偏移 18，按该布局读到的是字符串索引而非激活值，不能照抄为正确配置。
- 新 SII 终止类别位于字节 `7322`、字地址 `3661`，小于 `4096`；镜像仍为 16384 字节，剩余填充为 `0xFF`。不扩大 EEPROM 保留区。

SII 配置头依据 [Beckhoff ESC 技术手册第 11 章](https://download.beckhoff.com/download/Document/io/ethercat-development-products/ethercat_esc_datasheet_sec1_technology_v2.5.pdf)；DC/General 字段布局另与 TI 官方的 [DCEntry](https://software-dl.ti.com/mcu-plus-sdk/esd/AM243X/08_02_00_31/exports/docs/industrial_protocol_docs/am243x/ethercat_slave/struct_e_c___a_p_i___s_l_v___e_e_p___s_cat___d_c_entry.html) 和 [General](https://software-dl.ti.com/mcu-plus-sdk/esd/AM243X/08_02_00_31/exports/docs/industrial_protocol_docs/am243x/ethercat_slave/struct_e_c___a_p_i___s_l_v___e_e_p___s_cat___general.html) 交叉核对。General 偏移 14 的次级组索引和固定标志沿用既有 SSC 产物；本次没有推测修改硬件能力。

评估过外部转换工具，但未将其实现或依赖引入工程：Synapticon siitool 的硬件使用许可不适用于本项目，另一个浏览器 EEPROM 生成器未覆盖完整 PDO/DC。当前实现按数据格式独立编写，不复制它们的实现。

## 验证与部署约束

`test_protocol_generation.py` 在无旧生成物的目录生成两次，校验可重复性、只读检查、历史映射目录、按设备方向选择的布局、等长度错配拒绝、SII 独立解析、DC 字段、边界拒绝、BIN/头一致性，并以 C11/C++17 编译链接隔离产物及 SSC 字典。

`test_eeprom_migration.py` 编译真实 EEPROM 适配实现，仅替换底层 Flash/E2P 存储，执行新镜像、更新、旧逐字记录迁移、写失败及运行态门控。覆盖 Alias/Serial 保留、CRC 重算、最后提交身份页、16 KiB 边界及延后写重试。不是实际 Flash 掉电测试。

日后首次运行含新 SII 的固件时，现有非 OP 初始化路径会因内容差异更新 EEPROM 仿真页，保留每板 Alias/Serial；不是仅靠 Revision 增加触发更新。本轮没有连接、复位或烧录目标板。主站重新导入 ESI、真实 EEPROM/Flash 更新、DC 配置进入 SAFEOP/OP、CAN 负载和实时性仍需按上板计划验收。

BSP 的 `pinmux.*`、`clock.*` 保持原工具标记和就地维护规则，不属于此产品协议生成链；没有据此宣称可从本生成器恢复整块板的所有代码。
