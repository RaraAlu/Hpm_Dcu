# 从站预就绪与主站一次确认启动计划

日期：2026-11-17。状态：**用户已确认启动目标，具体接口与实施方案待落地，尚未完成该流程的实板验收。**

本计划承接[上电前四步调试计划](上电前四步调试计划.md)，记录后续多设备发现、通信预准备及快速启动的目标。本次只更新文档，不修改固件、主站或协议交付物，不连接、复位、烧录或运行目标板，也不构成后续硬件操作授权。前四步已有证据仅适用于[首轮实测记录](../验证记录/2026-11-17-上电前四步首轮实板调试记录.md)中的冻结镜像，不能扩展为本计划已经通过。

后续补充方向见[任务状态机与动态配置架构草案](任务状态机与动态配置架构草案.md)：由 Profile 组织 CAN 设备拓扑，通用任务状态机负责自举、主从就绪协调及动态下发/修改。该草案待逐项核对；本计划保留一次激活的快速启动目标，不将动态重配耗时隐藏在快速路径内。

## 已确认目标

- 项目主线是设备数据的正确传输、处理和实时交换。Motor、灵巧手、表情头、IMU 是设备业务模块，通用启动、通信、路由和就绪管理不由 `motor` 统领。
- MCU 上电后按启动 Profile 的预期连接表自主核验设备、进行无动作自检，并提前准备设备模块、通信任务、队列、缓冲区和 PDO 数据通路，不等主站上线才逐设备初始化；不要求盲扫任意未知设备。
- 主站保留源配置文件，选择本次使用的设备和配置；未预置的受支持配置可通过动态事务下发并重新准备。MCU 提供实际核验清单、能力及准备结果，主站据此核对，不由设备响应这一事实自动授予业务运行权限。
- **从站已经准备完毕且配置匹配时，主站只需一次应用级确认，随后在协议条件满足时自动开始 PDO 周期交换，不再进行第二次业务确认。**
- 优化重点是“主站上线到首个有效 PDO”的延迟，以及“确认接受到首个有效 PDO”的延迟。把可前置的工作移出上线后的关键路径，不以绕过校验、伪造反馈或取消保护换取启动速度。

“一次确认”指一次应用级激活事务，包含请求和明确的接受或拒绝结果；不是整个 EtherCAT 建链只交换一个报文。正常设备识别、状态读取、邮箱传输、PDO/DC 配置及 PREOP、SAFEOP、OP 转换仍须完成。确认接受不等于已经进入 OP，也不等于执行器已经使能。[EtherCAT 状态依据](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1446518411.html)

## 职责与配置来源

| 所属 | 职责 |
| --- | --- |
| 板端基础描述 | 固化或预先提供可用接口、总线参数、已支持的设备协议、允许探测范围和资源上限，使 MCU 在主站缺席时仍能准备；不包含默认动作授权 |
| 通用网关模块 | 发现结果、就绪快照、路由与内存资源、通信任务、激活状态、诊断及公共故障处理 |
| 设备模块 | 各自的探测、自检、编解码、数据有效性和故障策略；不能强迫 IMU 使用电机命令模型 |
| 主站 | 读取能力与实际设备清单，选择已准备好的设备集合或 Profile，核对版本并发起一次激活；配置变更通过独立动态事务处理 |

主站“选择性加载”与 MCU “提前发现”分别负责选择和发现，不再把发现推迟到主站选定设备之后。快速启动只覆盖板端已准备且能承载的配置，不要求预先建立任意设备组合的所有副本；使用有上限的设备槽位和共享通信资源，并校验所选集合的总预算。

主站若要求新的波特率、协议、资源规模或 PDO 布局，应明确进入非快速配置流程，重新准备受影响部分；不能把逐字段下发配置、重新初始化和等待自检隐藏在“一次确认”内部。源配置文件保留在主站，MCU 可接收能力范围内的编码配置数据，不因此要求增加文件系统或运行代码生成器；动态下发与掉电保存分开设计，SII 保留区不自动成为业务配置存储区。

## 启动流程总表

| 阶段 | MCU 工作 | 主站工作与通过条件 | 输出约束 |
| --- | --- | --- | --- |
| 1. SDK 启动 | 进入应用入口，完成运行时基础初始化 | 可尚未上线；沿用前四步计划的检查范围 | 不执行设备业务 |
| 2. 板级初始化 | 时钟、引脚、时间基准和基础中断等 | 可尚未上线；基础资源检查通过 | 不执行设备业务 |
| 3. EtherCAT 硬件初始化 | ESC、PHY、SII/EEPROM 等 | 可尚未上线；未接网线不等于硬件初始化失败 | 不执行设备业务 |
| 4. CAN 控制器初始化 | 控制器、Message RAM、FIFO 和基础时序 | 可尚未上线；控制器成功不代表外接设备在线 | 不发送业务控制命令 |
| 5. 通用运行环境 | 启动 SSC、RTOS、通信接收、诊断和有界后台任务 | 若主站提前上线，可读取准备进度；不能因扫描阻塞邮箱响应 | 允许经审核的探测通信，禁止执行器动作 |
| 6. 设备核验与自检 | 按 Profile 的预期连接表核验，记录身份、能力、状态、失败原因和时间戳 | 无须主站逐设备触发；未支持或未验证的项目明确标记 | 不自动使能、试动作或写设备持久化参数 |
| 7. 数据通路预准备 | 绑定设备模块，建立队列和固定槽位，准备 PDO 快照、初始有效位和预定义布局，发布 `READY` 能力 | 主站可读取哪些配置或设备集合已经就绪 | 保持未激活；无反馈时不能伪造有效数据 |
| 8. 一次确认 | 对所选配置及当前就绪快照进行有限校验，接受后进入 `ARMED`，否则返回明确原因 | 主站核对实际清单和版本，提交一次应用级激活请求 | 接受确认不直接放行运动命令 |
| 9. 自动开始周期交换 | 在映射、同步、EtherCAT 状态和新会话有效 PDO 条件满足后进入 `RUNNING` | 主站完成标准协议步骤并发送本次会话的有效 PDO，不再做第二次业务确认 | 只有另行满足动作授权、命令新鲜度及设备保护条件时才允许执行器动作 |

候选应用状态流为 `BOOT_BASE -> PREPARING -> READY -> ARMED -> RUNNING`，它与 EtherCAT 状态机分别维护，不能用应用 `READY` 代替 SAFEOP/OP 或 DC 已生效。`ARMED` 只表示激活请求已接受，不表示电机已使能。运行中的掉线、失步、租约超时和硬件故障进入相应禁止输出及诊断路径，不能沿用旧会话自动恢复动作。

## 发现与就绪约束

- 后续将“扫描所有设备”收敛为按预置或已下发 Profile 的预期连接表核验；覆盖范围必须处于已支持协议、已知总线条件和允许地址范围内，不对任意未知协议盲发报文。核验必须有超时、重试上限和总线预算，不自动修改设备地址或轮换总线速率试探。
- 每种设备先确认其发现能力。CANopen LSS Fastscan 是依赖特定上层协议的发现方式，不能据此假定 ENCOS 或其他私有协议可通用枚举；不支持自动身份发现时，应使用板端预置范围进行受控探测，并报告识别能力限制。[CiA LSS 说明](https://www.can-cia.org/can-knowledge/cia-305-layer-setting-services-lss/)
- 区分“发现响应”“身份匹配”“通信自检通过”“数据有效”和“允许动作”。动力隔离、设备未供电或协议不支持某项检查时，结果为缺失、受限或未验证，不能伪填通过。
- `READY` 针对可供选择的配置或设备集合成立，并附带配置版本、相关设备发现代次和数据新鲜度。等待主站期间继续维护状态，不能扫描一次后永久沿用；读取快照与确认之间的相关设备变化须能被检测。
- 新设备插入、掉线或故障应更新清单；使受影响配置的就绪失效，不自动改变已约定 PDO 字段偏移。与当前所选配置无关的设备事件按既定策略诊断，不能无依据扩大为所有业务故障。
- 必选设备缺失时拒绝对应配置激活；可选设备缺失是否允许降级及其 PDO 有效位由配置契约明确。主站未选择的设备可以被发现和诊断，但不获得业务动作授权。

## 一次确认与快速路径

以下是激活契约需要表达的信息，具体对象索引、字段长度、分段传输及版本规则留待接口设计，不在本计划中冻结线上的二进制布局。

| 信息 | 目的 |
| --- | --- |
| 所选配置或 Profile 标识及设备集合 | 明确主站本次要使用什么，不将发现清单直接当作运行清单 |
| 协议/PDO 布局版本、配置摘要及相关就绪代次 | 确认主从对同一份数据布局和准备结果达成一致，拒绝过期快照 |
| 启动或会话标识与请求序号 | 防止跨复位、重连或旧报文重放；相同会话的重复请求应幂等 |
| 接受/拒绝结果、原因及已接受版本 | 区分“请求已经接受”“尚待协议条件满足”“已经运行”，不能以 SDO 写成功代替运行状态 |

快速路径要求：

1. 主站读取就绪状态后只提交一次业务激活，不再依次对每个设备做初始化、Apply 或二次业务确认。状态读取和必要的 EtherCAT 协议交换不伪装成额外业务确认，也不据此承诺仅一个物理报文。
2. 确认处理只核对已准备的配置、资源和有效就绪快照，并进行受控状态切换。不扫描、不重新初始化外设、不写 Flash、不动态分配内存、不阻塞等待设备应答。
3. PREOP 中可以返回“接受，等待协议条件满足”，不能阻塞邮箱应答等待主站进入 OP，否则会形成启动互等。随后满足条件即自动进入周期运行；不要求主站再次发送应用激活命令。
4. 若尚未就绪、配置不匹配或快照过期，返回明确状态，保持动作输出禁止；不静默降级成旧配置，也不先启用一部分设备再报告整组失败。主站选择等待就绪或显式进入非快速配置流程。
5. 激活和运行切换保留会话隔离，清除旧命令、旧待发业务请求及不属于本会话的暂存 PDO；首次运行只接受本会话新数据。重复请求不得反复初始化或重复触发设备动作。
6. PDO 初版采用固定槽位或预定义 Profile，主站、对象字典、ESI/SII 和编解码布局保持一致；不得按扫描顺序紧凑排列，也不在 OP 中调整偏移。新契约须版本化并通过现有生成链验证。
7. 保留现有 DC/Sync0、一拍反馈流水线、截止和超时保护。DC 周期及实际映射的最终检查不能前置伪造；协议等待不算重复设备初始化，其耗时必须单列。

PDO 交换与设备动作分开授权。允许为了诊断发布有效的在线状态或标记为无效的测量值，不允许为了“首帧更快”把未采样值标成有效、把 `AcceptedCycleSeq` 当作设备实际执行确认，或把软件 TX 禁止视为物理急停。

## 分阶段实施

| 阶段 | 工作与交付 | 状态 |
| --- | --- | --- |
| 契约与资源清点 | 确认首批设备、探测协议、板端基础描述、总线预算、所选配置及版本兼容策略 | 待实施 |
| 通用职责整理 | 将发现、预准备、就绪和激活编排与电机语义分开，保留有类型的设备接口和现有保护 | 待实施 |
| 从站自主预准备 | 实现有界发现、自检、设备清单、预分配数据通路、就绪代次及持续状态维护 | 待实施 |
| 一次激活接口 | 实现整组校验、明确应答、幂等、过期请求拒绝及 `ARMED` 到运行的自动切换 | 待实施 |
| 主站接入 | 读取能力和就绪清单，对照配置文件选用预准备结果，提交一次激活并完成标准 EtherCAT 启动 | 待实施 |
| 离线与实板验收 | 状态/协议/内存边界回归、双配置构建及资源检查后，单独授权分阶段上板测量 | 待实施 |

先通过可控设备模拟和离线测试证明行为，再实施真实总线试验。沿用[实时系统规划](分布式时钟同步与实时系统接入规划.md)的时序约束，不因启动优化改变原有一拍反馈或混淆 CAN 设备实际执行时间。任何前四步硬件配置变化都需要相应回归，不能直接继承原冻结镜像的实测结论。

## 验收与时间指标

| 场景 | 验收要求 |
| --- | --- |
| 主站缺席启动 | MCU 能自行发现、自检和预准备；管理任务持续响应，不产生执行器动作 |
| 从站已就绪后主站上线 | 对匹配配置只发生一次业务激活事务；确认后无重复发现/初始化，标准协议条件满足后自动进入有效 PDO 交换 |
| 主站提前上线 | 能读取进度或未就绪原因；不得因主站等待而阻塞从站准备，不误报快速启动已经成立 |
| 确认时设备变化、版本不匹配或资源超限 | 拒绝激活或使相关就绪失效，保留清晰原因，没有部分动作输出放行 |
| 重复确认、旧会话、断链和复位 | 幂等或明确拒绝，过期请求不激活，旧命令不重放，故障后不自动恢复动作 |
| 必选/可选设备缺失、协议不支持 | 按冻结策略拒绝或降级，保留真实有效位；未验证不记为通过 |
| 满配置及通信压力 | 扫描/自检不饿死 SSC、SDO 或周期任务，队列、内存和带宽有界；无需放宽既有同步保护才能启动 |

| 指标 | 定义与口径 |
| --- | --- |
| 从站准备耗时 | 同一 MCU 单调时钟中，启动标记到目标配置首次 `READY` 的耗时；若要测量物理上电起点，另用硬件标记并注明差别 |
| 主站上线到首个有效 PDO | 同一主站单调时钟中，约定的接入流程开始标记到收到本次会话首个有效 TxPDO；记录链路建立、状态转换及同步等待的分项 |
| 确认接受到首个有效 PDO | 同一 MCU 单调时钟中，激活接受到本次会话首个有效 TxPDO 发布；协议等待与本地处理分开统计，不直接相减未经对时的主从时间戳 |
| 首轮端到端数据往返 | 另测主站命令经 CAN 对端及反馈映射返回主站的耗时；只有对端支持序号关联或使用可控测试对端时才称为因果往返，不以 PDO 发布或命令接受计数替代 |

首个有效 PDO 必须符合本次会话、约定布局、同步和数据有效性规则。可报告合法状态信息，但不能把空白初始镜像算作设备反馈已经回环。分别报告 PDO 通信启动和 CAN 端到端结果，不将二者混成一个通过项。

冻结测试条件后记录周期、所选设备、总线速率、数据大小、负载、固件与主站版本、样本量、时间分辨率、最大值及分位数。将“从站已就绪后上线”与双方同时冷启动分组，不用平均值或 READY 状态提前宣布整体最优。具体延迟上限及重复次数待确定，不在无实测依据时承诺毫秒数；性能验收须待这些门槛冻结后进行。

实板扫描、查询报文、OP 切换和周期运行均超出原前四步的批准范围，执行前必须重新确认接线、供电、动力隔离、独立安全措施及操作范围；本计划不启动这些操作。
