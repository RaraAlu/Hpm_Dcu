# DCU 项目总计划

更新：2026-11-22 · 本仓库唯一执行计划 · 当前阶段：1（500 Hz 单设备 60 秒通过；单路 7 台待验）

**目标**：证明主站第 N 帧下发的命令，下一帧能读到**对应设备的新反馈**。先在固定布局上成立，再开放布局变更。

**阶段 1 最低容量**：按单路 CAN 7 台 HRA55H-100、每台 500 Hz 设计和验收。每拍下发 7 台的全零 MIT，第 N+1 帧必须一次读齐 7 台的对应新反馈；分路、降频或轮流回包不替代该验收。此为通信验证，不授权使能或非零输出。

**回环**：指数据往返，不是电机闭环性能，也不是物理停机验收。

**配置源**：活动 Profile 是设备拓扑、路由和限值的唯一来源；RK `DriverModule` 使用协商后的布局，不维护第二份可独立修改的映射，也不在不匹配时静默回退。布局标识在阶段 2 加入 Profile。

**生产与测试**：实板一律跑生产固件与生产 Profile；host 回归、诊断镜像、探针和夹具属于测试侧，独立构建，不进入生产 ELF，生产代码不为测试留旁路。单设备与多设备走同一条 Profile→绑定→适配→槽位路径，不为单电机做特例。

**冻结单（T0）**

- [生产 Profile](../../firmware/app/profile/cfg/生产CAN配置.yaml) 当前第 7 版保留 can3 的配置，并增加只透传的 can2。第 6 版为硬件重发实板基线，第 5 版为不重发基线。can3（`bus: 3`）节点 `0x02`，FD+BRS 1/5 Mbit/s；连续全零 MIT 仅在 500 Hz DC Sync0 工作，当前 30,000 帧封顶。can1 首轮使用第 4 版。先前独立对照确认 `0x02` 版本为 `37.03.1E.06`，绕过生产网关仍复现 `0x17` 无回包。
- 首台设备由现场确认为北京创新 HRA55H-100（CiH408）。Profile 用 `type: HRA55H-100` 标识型号，由 `protocol: bjcx` 绑定驱动，不分配数字型号 ID；当前 can3 首设备映射到全局槽下标 21（从 0 起），早期 can1 的记录用槽 7。厂家表列额定扭矩系数 `5.97 N·m/A`，未给该行额定电流，不能据此推算台架限流。
- 生产命令是 MIT `0x11`（16 B），反馈是同 ID 的 `0x80`（16 B）；`0x17` 状态查询不算命令应答。独立 RAM 探针和生产构建均已收到带有效 RX EOF 的 `0x80`；其中生产构建的 500 Hz 配置验证了单笔 N+1。
- 冻结双端版本、镜像、活动配置、帧格式与关联方式。
- 冻结设备故障的作用范围（单设备停发还是整组停发），以及必选/可选设备缺失时的降级与有效位规则。
- 冻结 MIT 的承载：复用现有轴槽的 Kp/Kd、目标位置/速度和前馈字段；CAN MIT 帧没有电流限幅字段，PDO 限幅不能当成电机端限流，须冻结本地保护与设备限流的职责。滚动计数与会话前提另行定义；若 784/1072 槽位承载不了，阶段 1 暂停并重新排期，不借 Raw PDO 绕过。
- 冻结单笔因果证据：`0x80` 不带请求序号。生产单发查询已按 TX 令牌和同一 MCAN 的 TSU EOF 严格先后筛选，缺失时间戳、陈旧回复和超时不更新状态。EOF 先后本身不能区分同 ID 的主动上报与应答；生产 MIT 还需单在途、隔离同 ID 的查询或上报，并实现会话计数。
- 冻结指标口径（`1 µs` 指 Sync0 到锁存的峰峰抖动、正负偏差还是最大延迟，三者不混算）、样本量和长测时长。
- 安全前提：全零 MIT 不是失能或停机；首笔不自动使能、不切反馈格式、不重试；模式与使能条件按实机手册确认。

**通过条件**

阶段完成 = T0 冻结单确认、T1–T10 通过，并满足：

- 每台设备：本拍命令能在下一帧读到新反馈；旧反馈、跨拍补发不计。硬件重发只在同一事务内恢复且仍满足 N+1 时计该事务一次，单独保留错误证据。
- 按 `(CAN 通道, 节点 ID)` 关联，通道间不串路；单设备、跨通道、同通道多节点三组都留下可复现记录。
- 覆盖无主站准备、主站早到/晚到、普通重连、首笔真实往返四类场景。
- 记录 WKC/OP、未执行/漏拍/错配/超期、最大偏差与最小余量；只在同一时钟或已对齐的时轴上相减。
- 实板数据只来自生产构建与生产 Profile；诊断镜像、探针和夹具只作对照，不计入阶段通过。
- 单路 7 台 bjcx 的 MIT `0x11` 在 `784/1072 B`、`500 Hz`、DC Sync0 下，下一帧读齐各自 ID 的 `0x80`；`0x17` 查询和 32/48 B 诊断镜像不计。

**时序与故障压力（T9）**

- RK 分开测唤醒、IgH 接收、域处理；HPM 区分 Sync0 硬件边沿、槽发布/锁存、ESC 写完。
- 复验 DC 支持范围 1–5 ms、最短周期、多节点及 SDO 并发；记录任务栈水位、执行时间、CAN 预算、队列溢出。
- 按 T0 冻结的口径与样本量报告超限次数与尾部，不用均值替代最坏观测。
- 失步、缺帧、总线故障、任务停滞时禁发；重连不恢复旧命令；软件取消不等于在途帧撤回，也不等于电机物理停机。

## 阶段 2 · 两套预定义布局的双端切换

**责任**：RK 与 HPM 共同负责 · **状态**：未开始 · **前置**：阶段 1 通过

**做法**

- 两套布局指总字节数相同、同宽字段换序的两份定义；现有三档功能档位不是这两套布局。
- 先离线验证 HPM 状态机与 RK 重建过程域，再在无动作条件下联测。
- 保持活动配置与候选隔离，有界处理缺片、重复、冲突及资源超限。
- 覆盖两套布局互切、旧主站、切换中断链、复位及超时。
- 同时核对 OD、ESI/SII、主站导入描述与双方**实际注册**的映射，成功和拒绝两条路径都要测。

**通过条件**

- 即使 WKC 正常，布局不匹配也必须拒绝输出。
- 同长度换序、旧主站、重启/断链均不能误放行。
- 新布局分别重跑单帧、截止和真实反馈；不继承旧布局的时序结论。

## 阶段 3 · Profile 生成布局

**责任**：RK 与 HPM 共同负责 · **状态**：未开始 · **前置**：阶段 2 通过，且双方已按下文“双端事务”完成过切换

**做法**

- 允许 Profile 在双方支持的字段语义及资源上限内定义 PDO 长度、映射索引和字段定义。
- 支持有明确用途的自定义 SDO。
- 布局变化后重跑单帧 LRW、同步窗口和下一帧反馈截止，不沿用固定布局的时序结论。

**通过条件**

- 按“PDO 生成”规则出包，核对 SM2/SM3 实际映射长度与线上数据长度。
- 至少比较单电机和多电机布局；移除电机后，其字段不再占用线上字节。

## 布局规则与双端事务

### 什么算“启用”

- “启用”指 Profile 将设备纳入周期数据交换，不等于电机已使能或在线。
- 运行中失能、掉线、反馈超时只改变状态与有效位，不改变布局。
- 固定布局下启用或停用设备只改 Profile 与有效位；重新冻结 Profile 属于构建期重部署，下一轮仍从零使能帧起步。
- 只有字段定义、长度、映射顺序或索引变化，才走双端事务；即使新旧长度相同，也必须重新核对布局。

### PDO 生成（阶段 3 完成后生效）

- 按当前 Profile 启用的设备集合生成，不按最大电机容量固定发包。
- RxPDO、TxPDO 分别由公共字段、已启用设备的映射字段及必要对齐组成；按约定顺序紧凑排列，不给未启用的电机留空槽。
- 板内可按容量上限预分配缓冲区，但不把空余容量映射到线上。
- `784/1072 B` 与每路 7 槽是首轮固定布局的基线，不是动态布局的生产默认长度。

### 双端事务（改变线格式时）

改变线格式走独立事务，不占用配置未变时的快速启动路径。

1. RK 停止控制，HPM 撤销动作授权并封锁业务输出；退出 `OP`，在 `PREOP` 停用旧过程域，隔离旧会话的命令和待发队列。
2. HPM 暂存候选布局，校验索引与映射、字段类型、偏移和容量，发布带版本与摘要的布局描述；RK 根据描述重新注册 PDO 映射并重建 IgH 过程域。双端核对实际使用的方向、索引及子索引、位宽与位偏移、类型和字段语义，不只核对总长度或 WKC。
3. 双方确认同一布局及本次会话后，重新完成标准状态转换，恢复 PDO 周期交换；先验证本会话的中性帧，再显式使能。任何一步失败、超时或失去连接都保持禁输出，不自动恢复旧命令或动作授权。

**管理对象**

- 用于发现布局、提交候选及确认版本的 SDO 保持固定索引、子索引和类型，确保 RK 不知道新布局也能发现和核对。
- 其他自定义 SDO 可由 Profile 声明索引、类型、长度及访问权限，但不得覆盖固定管理对象。
- 具体对象编号、编码及持久化另行设计。

## 网关架构（已实现，已离线验证）

以下三项已完成固件构建和宿主回归，不包含本次改动后的实板验收。

1. **先分开生产启动与诊断激活**
   - [生产入口](../../firmware/app/main.c)保留启动编号及无有效日志时拒绝启动；生产启动不再要求显式会话号分配回调。
   - 显式激活留给独立诊断，同源就绪逻辑不复制。
   - 验收：生产首帧零使能、旧命令拒绝、退出 OP 撤销、诊断会话原有行为；Flash 日志格式和两处保留区不变。
2. **应用层绑定 Profile，EtherCAT 投影槽位**
   - 应用层按活动 Profile 绑定通道、设备和限值；[EtherCAT 适配层](../../firmware/comm/ethercat/motor_adapter.cpp)负责设备到 PDO 槽位及对象字典的投影，不另设可写映射。
   - [原生网关回归](../../tests/host/motor/application_core_test.cpp)不链接 EtherCAT 即可验证设备绑定；[适配回归](../../tests/host/motor/motor_application_test.cpp)覆盖同总线多节点、跨总线重复 ID 和空设备列表。原有 PDO/SDO 布局不变。
3. **保留单任务周期编排**
   - [网关周期](../../firmware/app/gateway/gateway_application.cpp)负责整机命令许可、事务仲裁和反馈发布；电机保护归设备，线格式归通信适配。
   - 私有 `process_bus()` 保持 TX 完成、RX、控制与查询的顺序；所有总线处理后才检查撤销、处理 Raw。已有回归覆盖中间总线故障不跳过后续总线的查询，且该查询先于同周期的 Raw 帧。
   - 台架专用代码归测试侧，不进入生产构建；诊断能力不能因此删除，也不能据此宣称提速。

## 进入硬件前的门槛

- **授权**：每轮单独确认板卡、镜像与测试范围、接线/端接、逻辑供电、执行器动力隔离及独立安全措施；外部 CAN、上 OP、复位、下载和运动试验均不因本计划获得授权。
- **启动复验**：改过启动路径时按 [SDK → BSP → ESC → MCAN 检查点](../验证记录/2026-11-17-上电前四步首轮实板调试记录.md)复验（观测项和通过结论以该记录的逐步表为准，源码地址按当次 ELF 重解析），另测脱离调试器的冷启动。
- **构建**：固件改动先跑受影响的宿主回归、Debug/Release 构建与镜像检查；调整声明归属另跑头文件归属检查。实板只用生产构建与生产 Profile，测试夹具、探针单独构建并记录摘要，不用诊断镜像替代生产路径。
- **部署**：冻结镜像、Profile 和主站配置，按[受保护下载流程](../当前说明/启动编号日志初始化与烧录保留.md)保留 SII 与启动日志。
- **记录**：区分实测、离线替身和未执行；物理停机时延和真实负载另行验收，软件观测、控制器内部回环和临时替身均不计实物通过。
