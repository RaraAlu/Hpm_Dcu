## CAN 收发与配置治理计划

**配置只认当前 Profile。** CAN 通道、收发和 ENCOS 设备绑定不保留固定四路、旧配置读写入口、默认回退或双配置来源。PDO/SDO 数据布局不改；旧配置字段仅留布局占位。BSP、启动编号日志及 SII 保留区不动。

| 顺序 | 实施内容 | 离线验收 |
| --- | --- | --- |
| 1. 配置与初始化一并切换 | YAML 的 `channels` 列表决定启用哪路，保留物理通道编号；每路明确 `bus`、`mode`、`nominal_bitrate_kbps`，FD 另填 `data_bitrate_kbps`。构建时生成 MCU 描述，网关在启动时将已校验参数交给 MCAN。删除无参固定四路初始化、旧位率常量和旧写路径，不先保留过渡回退。MCAN 只管板级资源和 FIFO。 | 单路选 `bus: 2` 时只初始化 MCAN2；其余通道不启用时钟、收发器或 IRQ，收发和状态查询不访问未启用的控制器。缺失、重复、越界或不支持的配置明确拒绝；任一路初始化失败都不允许业务发送、不进入 READY。 |
| 2. 收发与电机轴号解耦 | MCAN 按通道收发，发送归属使用通用事务标识；区分提交、硬件完成、取消与有效回复。轴号、节点匹配和驱动协议留在网关及设备适配器。保留发送门、时间戳和 64 字节 FD 能力；旧 PDO 不因内部帧长改变。 | 验证相同标识在不同通道互不串扰，取消后迟到事件不误记完成，提交成功不等于已完成。重跑 DLC 0～15、发送门以及 PDO 8 字节边界的回归。 |
| 3. ENCOS 设备迁移 | 只按 `Profile.devices` 建立路由和设备保护，取消旧配置读写、默认补齐和 Apply；保留线上的 PDO 槽位与诊断对象。 | 不写旧 SDO 即可绑定并查询指定节点；未配置设备和空设备列表不发业务帧；配置后的设备拒绝越限 PDO。只离线验证。 |

第 1 行已完成主机回归、Debug/Release 构建和[生产镜像单路初始化实板验收](../验证记录/2026-11-18-生产CAN配置单路实板验证.md)。第 2 行已完成离线回归：跨通道 ID 不串、取消后迟到事件不误计，ENCOS 参数事务只有在同通道同 ID 的发送完成后才等待并校验回复。取消表示软件撤销，不能保证已在总线上发送的帧可撤回。

生产 ENCOS 的设备、CAN ID、型号、编码范围及控制限值只从 `Profile.devices` 读取。运行时设备编号取自 Profile 顺序，没有轴号。EtherCAT 适配层由物理通道与该通道内的设备顺序推导固定 PDO 槽：每通道预留 7 槽，CAN2 的首个设备是槽 14（从 0 起）。PDO/SDO 索引、字段布局和 SII 不变；旧轴配置对象仅留布局占位，旧读写和 Apply 均不再支持。原 `0x2002` 的只读布局用于公布就绪与会话。已有只读反馈可取，主动探测由网关任务调度。

[生产 CAN 配置](../../firmware/app/gateway/cfg/生产CAN配置.yaml) 目前明确为 `devices: []`，没有已确认的实机节点与标定值，不猜测也不回退。[单路 ENCOS 离线配置](../../tests/host/motor/cfg/单路ENCOS验证配置.yaml) 只用于主机验证，不用于上板。[ENCOS 与 CiH408 混挂配置](../../tests/host/motor/cfg/混挂电机验证配置.yaml) 同样只用于离线验证。

## CiH408 接入与后续职责调整

- 参考双板项目的电机实现为 ENCOS。轮式项目的北京创新资料记录了 HRA40H-101、HRA55H-101；其 CiH408 V1.6 厂家协议与 `application/motor/protocol/protocol.c` 一致：标准 CAN FD+BRS、1000/5000 kbit/s，只读请求 `0x17`，默认状态回复 `0x80`、16 字节（DLC 10）。
- Profile 以 `protocol: cih408`、`model` 和 `bus + can_id` 绑定驱动。同总线禁止重复 ID；不同总线可重复。只接受本总线、本设备且 TX 完成后的有效回复；原 Raw PDO 仍不接收长帧。只读驱动不发送使能、反馈模式切换、运动或主动停机报文；12 位电机告警超出旧 8 位字段时报告 `255`，不因截断报告为零。
- **生产网关职责已迁移并统一命名。** 会话、CAN 调度、事务仲裁和原生反馈编排归入 `app/gateway`；旧 `app/motor` 不再有源码。电机驱动和保护仍在 `devices/motor`，PDO/SDO 布局与槽位映射仍在 `comm/ethercat`。生产使用 READY 和普通 PDO 自动恢复；Profile 变更仍计划走独立候选事务。

## 首轮实施约束

1. **先锁范围：**沿用现有 BSP、SSC、时间基准和独立镜像。只选一路 CAN、一个测试节点、一份静态 Profile；先确定路由、映射及谁拥有各阶段状态。现网 OD/SII/ESI 和主站兼容性未核对前，不在原生产路径替换 ABI。
2. **再迁职责：**先让 Profile 驱动通道和路由，再接入任务就绪态与一次激活；同时把通用队列、配置、周期编排从 motor 脱开。用离线替身核对提前确认、版本不符、离开 OP、超时和旧数据拒绝，不用替身结果宣称设备发现已通过。
3. **最后验收：**保留独立内部回环作为对照；物理 CAN 需可控对端。实板分别记录本地就绪、已匹配配置只确认一次、标准协议切到 OP、首个来自 CAN 的有效反馈，不把配置下载或普通读状态混为激活次数。
