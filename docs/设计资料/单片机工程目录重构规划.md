# DCU 单片机工程目录重构规划

更新日期：2026-11-13。状态：**目录迁移、BSP 提取、混合语言构建、配置归档与遗留清理已实施；设备周期编解码抽象已接入，完整业务解耦、生成链恢复和硬件验收未完成。** 初次实施以先前 C++ 工作区为基线，保留已有改动；后续清理及提交范围见[遗留清理记录](../验证记录/2026-11-13-遗留清理验证记录.md)。整个整理过程没有连接目标板。

当前工程源自本地化 HPM SDK 示例，不是违反某个统一的单片机目录标准。本次按维护归属调整布局，不照搬其他芯片厂商的 `Core/Inc`、`Core/Src`，也不把移动文件当作架构解耦已经完成。

## 1. 已落地的布局

```text
Dcu_dev/
|-- firmware/
|   |-- app/main.c                 # C 入口与应用编排
|   |-- app/motor/                 # C++ 电机控制及产品绑定，注册放 cfg/
|   |-- bsp/dcu_hpm5e31/            # C 自研板支持
|   |-- comm/canfd/                # C MCAN 产品适配
|   |-- comm/ethercat/             # C SSC 回调与活动 port
|   |-- devices/motor/             # C++ 电机 Interface 与 drivers/encos 实现
|   |-- devices/imu/               # C++ 样本与有效性模型，尚无具体芯片驱动
|   |-- ports/                     # C/C++ 共用 CAN 帧，不执行 I/O
|   |-- protocols/encos/           # C++ 电机协议
|   |-- generated/encos/           # 原协议类型与存储
|   |-- generated/ethercat/        # 原对象字典与 SII 数组
|   `-- cfg/                       # 固件及 SSC 产品配置
|-- third_party/hpm_sdk/           # 本地化 SDK 核心
|-- third_party/beckhoff_ssc/       # SSC 栈核心及已有本地补丁
|-- protocol/ethercat/              # ENCOS ESI/SII 交付物
|-- tools/protocol/                # 可读 SII 工具
|-- tools/cfg/                     # 工具下载地址、版本和摘要锁定
|-- scripts/                       # 主机工具与受保护目标操作
|   `-- cfg/                       # 探针参数、确认模板与 USB 规则
|-- cmake/                         # 镜像检查与 CTest
|   `-- cfg/                       # 实际 CMake 预设
|-- debug/cfg/                     # OpenOCD 配置
|-- tests/host/                    # 离线工具、协议及布局测试
|-- tests/target/can_led/           # 显式启用的板上诊断
`-- docs/                          # 中文资料
```

根目录保留 `CMakeLists.txt`、`CMakePresets.json`、`app.yaml` 和工程说明；根 Presets 只转发到 `cmake/cfg/CMakePresets.json`。BSP 的工具工程位于自身 `cfg/`，板卡 YAML 和 VS Code 文件保留工具要求的入口；详细例外见[配置归档规范](../当前说明/配置文件归档规范.md)。`.tools/`、`build/`、`artifacts/` 仍是被忽略的本机产物。完整职责见[当前目录说明](../当前说明/目录层级与维护职责.md)。

## 2. 语言与模块原则

- 电机、真实 IMU 实现及后续项目自有抽象采用 C++17。现有入口、板级访问、通信适配、SDK、SSC 栈和生成存储保留 C，启动汇编不改。
- 当前 `firmware/devices/imu/` 已有可测试的样本、初始化、错误及过期模型和未接入实现；没有具体芯片驱动、主循环采集或虚假有效样本。
- C/H、CPP/HPP 与所属模块相邻；跨 C/C++ 公开接口继续用兼容 C 的 `.h` 和 C 链接，纯 C++ 内部类型可以用 `.hpp`。
- 电机控制在 `app/motor/`，因为它仍承担产品调度与 SSC 接入；周期命令和反馈已通过 `devices/motor/` 的 Interface，ENCOS 实现复用 `protocols/encos/` 编解码，不把厂商参数事务冒充通用协议。
- `comm/canfd/` 仍直接访问 MCAN/GPIO/IRQ，保留 C；将来确有替换需求的高层抽象采用 C++，不为每个 SDK 函数套转发层。

具体编译选项、实时约束和接口约定以[混合语言开发规范](../当前说明/混合语言开发规范.md)为准。

## 4. 构建与调试衔接

1. 根 CMake 只负责 SDK/外部板卡接入、语言规则和顶层注册，各模块用少量局部 CMake 显式列出源码，不用递归通配。
2. `BOARD=dcu_hpm5e31`、`BOARD_SEARCH_PATH=firmware/bsp` 由根工程设置，SDK 使用该外部 BSP 一次；原 SDK 同名板级目录已移出，时钟、引脚和 Flash 参数原字节保留。
3. 启动汇编、芯片定义和链接脚本继续由 `third_party/hpm_sdk` 提供唯一来源，不复制到 BSP 凑目录。
4. SSC 配置、应用头、生成头已与栈核心分开；先检查唯一所有者，再以编译依赖确认实际使用路径，避免引号包含遮蔽。
5. `scripts/dcu.py` 的 SDK 定位、CLI/CTest 测试发现、宿主测试包含路径及可读 SII 工具输入输出路径同步更新。
6. `APP_NAME=dcu`、Debug/Release Presets、ELF/BIN/MAP 输出路径和现有两个受保护调试入口不变。离线 GDB 检查新 `main.c` 和电机源码路径，不用旧硬编码地址。
7. 保留镜像检查、显式目标确认、镜像冻结、EEPROM 备份/校验、最终暂停和 `DCU_DEBUG_READY`，目录整理不精简下载保护。

入口仅将 CAN LED 测试头改为按开关包含。原 CMake 只按开关加入诊断源码、未定义固件宏；现在在独立测试清单内显式定义 `CONFIG_CAN_LED_TEST=1`，让人工启用时真正生效。默认仍为 OFF，默认控制行为不改。启用后是阻塞式板上诊断，编译检查不等于可以带电运行。

## 6. 验收与后续顺序

已执行的离线验证及二进制差异见[混合语言目录迁移验证记录](../验证记录/2026-11-13-混合语言目录迁移验证记录.md)。目录改动可能改变调试路径、对象链接顺序、地址和填充，不能只比较整个 ELF 哈希就判定等价，也不能把实际加载段差异都解释为调试信息。

后续设备抽象范围以[设备驱动接入规范](../当前说明/设备驱动扩展与接入规范.md)为准，资源增量与协议差分测试见[设备抽象验证记录](../验证记录/2026-11-13-设备抽象基础验证记录.md)。只有一种生产电机实现，不把宿主测试替身算作第二种设备支持。

后续涉及路径删除/改名时，先保存待比较的 ELF，再清理对应构建产物和 CMake 缓存。当前 SDK 的 `ar crD` 可能保留旧对象，仅 `cmake --fresh` 不够。无构建目录时跳过 `clean`。

```bash
python3 scripts/dcu.py test
cmake --build --preset hpm-debug --target clean
cmake --fresh --preset hpm-debug
cmake --build --preset hpm-debug
cmake --build --preset hpm-debug --target check-image
cmake --build --preset hpm-release --target clean
cmake --fresh --preset hpm-release
cmake --build --preset hpm-release
cmake --build --preset hpm-release --target check-image
ctest --preset hpm-debug
```

后续先补控制状态、租约、事务和调度测试，再决定如何将 SSC 接入和周期编排从电机实现拆开；不能按函数数量机械拆文件或修改 ISR 上下文。IMU 接入先明确型号、接口、协议和有效性/超时策略，不从 ESI 中存在 IMU 字段推导驱动已经实现。

生成链恢复、业务解耦与真实设备联调分别实施。连接目标前仍需重新确认动力隔离、接线和当次操作范围；历史授权不自动覆盖新布局或新 C++ 映像。
