# DCU 分布式时钟同步与实时系统接入规划

更新日期：2026-11-16。状态：**已采纳一拍流水线与 RTOS 路线，首批从站软件已实施并进入离线回归；未上板验收，需求继续补充。**

目标是由 IgH 主站配置 EtherCAT 分布式时钟和 Sync0 周期，使 DCU 在 Sync0 边界锁存 PDO，并加入 RTOS 管理后续业务。实施顺序为先完成从站，主站后续共同调整。本轮只读取主站代码作为接口参考，不修改、构建或启动主站。离线证据见[本轮验证记录](../验证记录/2026-11-16-同步流水线与实时系统离线验证记录.md)；软件实现不等同于 1 us 抖动或一拍反馈已经实测通过。

## 已确认需求

| 编号 | 需求 | 边界 |
| --- | --- | --- |
| 需求一 | 启用 EtherCAT DC，并基于 Sync0 同步 | 编译宏开启不等于运行时同步已经验收 |
| 需求二 | 主站使用 IgH | 用户指定 `x2_deploy/src/module/driver_module/` 为参考，主站后续再改 |
| 需求三 | Sync0 暂定 200–1000 Hz，由主站配置 | 周期 1–5 ms；首版停机重配，不支持 OP 中热切换 |
| 需求四 | 同步目标为 DCU 锁存 PDO，抖动要求为 1 us | PDO 方向、抖动统计口径和最大锁存延迟要求待确认 |
| 需求五 | 加入 RTOS | 工程首版选用 SDK 配套 FreeRTOS，单一业务任务拥有电机状态和 SDO |
| 需求六 | 采用一拍反馈流水线并开始实施 | 本拍锁存命令及收集反馈，在下一拍读取窗口前发布完整快照；不等待全部电机 |

200–1000 Hz 是从站配置接收范围，不是任意轴数、CAN 帧格式下的电机闭环带宽保证。

当前不将“四路 CAN 同时发送”或“全部电机实际执行同步到 1 us”列为验收目标。CAN 带宽仍限制命令消费速度，但不能据此直接判断 PDO 锁存抖动能否达标。

## 锁存语义与时间指标

### 锁存对象

已采用 RxPDO，即 IgH 向 DCU 下发的命令过程映像为快路径对象。锁存表示“选定一份完整且不可被覆盖的快照，作为当前 Sync0 周期的有效命令”，不是在 Sync0 到来后才开始复制整个过程映像。

TxPDO 使用独立完整快照并采用一拍流水线，不要求整个反馈映像与 RxPDO 同时在 Sync0 边界复制。固定的是反馈发布窗口，不是 CAN 电机的实际采样或执行时刻。

### 一拍流水线契约

```text
本拍 Sync0 前     PDI 完成 RxPDO 复制，发布完整待用快照
Sync0[n]          快路径锁存本拍命令；不解析命令、不发送 CAN、不调用 RTOS
本拍运行窗口       业务任务消费命令，按 CAN 独立节拍推进并解码收到的反馈
T - A - B 附近    开始构建 TxPDO，冻结已经解码的最新反馈
T - A 之前        完成整个 TxPDO 写入 ESC，供下一次读取
Sync0[n+1]        下一拍，不补跑、不自动把超期反馈顺延成正常两拍
```

`T` 来自主站；首版 `A=250 us` 为反馈发布提前量，`B=100 us` 为构建和 ESC 写入预算。配置位于 [cycle_config.h](../../firmware/cfg/cycle_config.h)。它们是可调整的工程初值，不是已经测得的耗时或已匹配任意主站相位的保证；任务按 50 us 定时器唤醒，实际构建起点可能在预算窗口内偏移。

- 发布快照包含截止构建时已解码的 CAN 状态。队列中尚未处理、截止后才收到或本拍未更新的反馈只能进入后续快照。
- `AcceptedCycleSeq` 仍表示 DCU 接受了命令，不表示所有 CAN 请求已完成发送，更不表示电机已执行。当前电机反馈没有逐命令序号回显，不能据此建立严格因果配对。
- `PublishSeq` 每次构建快照递增；每轴 `StatusWord` 的新反馈标记、`ValidFlags`、`FeedbackAgeMs` 继续有效，不伪造新鲜度。未收到新反馈的轴保留旧值及其真实年龄。
- 超过发布截止、跨拍完成、已收到周期帧后再次缺帧、未消费快照被覆盖或失步均锁存故障。定时器先禁止新 CAN TX 并取消排队请求，业务任务随后停止会话并请求 `SAFEOP + SYNCERROR`。
- 启动时尚未收到首份 OP 命令允许空快照，不复用上次会话命令；SSC 原有状态和看门狗检查仍保留。

### 指标定义

候选测量定义如下，最终验收口径需确认后固定：

```text
t_sync[n]  = 第 n 次 Sync0 硬件事件的时刻
t_latch[n] = 本周期完整 PDO 快照生效的时刻
L[n]       = t_latch[n] - t_sync[n]
J_pp       = max(L[n]) - min(L[n])
L_max      = max(L[n])
```

- 用户已提出“抖动 1 us”；候选解释为峰峰抖动 `J_pp <= 1000 ns`，尚未确认是否指正负偏差或其他口径。
- 最大锁存延迟 `L_max` 单独记录，是否也必须不超过 1 us 待确认。固定延迟和抖动不能混为一个指标。
- 参考点采用 ESC 的真实 Sync0 事件或经验证的硬件路由，不能仅用 ISR 内读取时间作为事件发生时刻。
- 锁存时间检查必须同时验证数据序号、完整性和所属周期；不能只凭 GPIO 翻转及时就判定 PDO 锁存正确。
- 平均值、P99 和有限时长内没有超限都不能单独证明最坏情况上界；需要同时分析中断屏蔽、嵌套和存储访问的阻塞上界。

1 us 当前是设计目标，不是可直接承诺的现有能力。若快速中断路径仍不能满足要求，应在进入完整业务迁移前评估硬件触发方案及其成本。

## 主站配置与周期变更

### 周期来源

周期由 IgH 配置，DCU 在状态转换时读取 ESC 的 Sync0 周期寄存器 `0x09A0`，单位为 ns，校验后作为运行配置。现有 SSC 已读取该寄存器并据此检查 DC 配置和设置同步参数，接入时复用这条路径，不另外猜测周期。

首版采用主站 PDO 周期与 Sync0 一比一，不支持超采样、分频、Sync1 联合模式或非 DC 生产运行。固件接收闭区间 `1000000..5000000 ns`，拒绝范围外配置；非整微秒周期在本地截止计算中向下取整，形成不足 1 us 的保守提前量。主站参考解析器当前只接受整微秒周期。

固件在 SSC 初始化后将 `0x1C32/0x1C33` 的支持位收敛为 Sync0；旧 ESI/SII 本轮不再生成，ESI 中残留非 DC 条目不代表新固件允许该生产模式。使用非 DC 配置将被拒绝进入 SAFEOP，不能当作兼容回退。

IgH 的 `ecrt_slave_config_dc()` 用于配置 AssignActivate、Sync0 周期和相位，应在 `ecrt_master_activate()` 之前调用。实际周期应以 ns 数值配置，不能假定 IgH 会替应用自动解释 ESI 的 Factor。[IgH 官方应用接口](https://docs.etherlab.org/ethercat/1.6/doxygen/group__ApplicationInterface.html)

运行时还需由主站按确定的 DC 策略周期性提供应用时间并执行时钟同步，核对 `ecrt_master_application_time()`、参考时钟和从站时钟同步调用；应用时间调用点应固定在实时周期中的同一相位。[IgH 应用时间与同步接口](https://docs.etherlab.org/ethercat/1.6/doxygen/group__ApplicationInterface.html)

### 变更方式

“周期由主站决定”与“OP 中可以无缝连续变周期”是两个不同要求。第一版只支持停止运行后的重新配置；OP 中检测到周期、激活位或同步模式变化将报错退出，不自动热适应。

建议的变更流程为：

1. 停止电机使能，清理当前会话的待执行命令，退出 OP 并进入适合重新配置的状态。
2. 在 IgH 主站停用和重新激活流程中配置新的 DC 周期与相位。
3. DCU 重新校验配置、重置周期序号和旧事件，按新周期更新同步监视参数。
4. 同步状态稳定、PDO 准备条件满足后再进入 OP，重新执行使能流程。

如需 OP 内热切换，须另行设计生效边界、过渡周期、看门狗重算、命令处理和失败回退，不能直接改寄存器后继续使用旧状态。

## 已采纳架构

### 数据路径

```text
IgH 发送本周期 PDO
    |
    v
SM2/PDI 复制完整过程映像到可写缓冲区
    |
    v
校验完整性并发布待用快照
    |
    v
Sync0 快路径选定本周期快照和序号
    |
    v
独立 50 us 定时器通知 RTOS 任务
    |
    v
电机任务消费已锁存命令，按独立 CAN 节拍推进业务
```

IgH 应让 PDO 在 Sync0 前完成准备，并留出保护窗口。该窗口由主站发帧相位、链路和 PDI 处理耗时确定，不能直接套用任意固定提前量。晚到帧、边界附近发布和缺帧必须有明确的周期归属，不得把不同周期的数据混为一份快照。

### 缓冲区所有权

已实现三缓冲的 `FREE/WRITING/READY/LATCHED/READING` 所有权状态，见 [pdo_pipeline.c](../../firmware/app/cycle/pdo_pipeline.c)。写入者为 PDI，锁存者为 Sync0，消费者为唯一业务任务；32 位原子操作需编译期证明无锁。约束如下：

- 写入完成后才能发布，Sync0 只能选取已完成的快照。
- 快路径只切换少量元数据，不复制整块 PDO，不等待生产者或消费者。
- 任务持有快照期间，PDI 不得覆盖该缓冲区。
- 使用经验证的原子操作和必要的内存屏障，不能仅依赖 `volatile` 保证并发正确性。
- 同一边界前多次收到完整映像，选择最新完整映像；复制未完成的映像归下一拍。
- 迟到帧不能挽回已经因本拍缺帧而锁存的故障，恢复须重新建立会话。
- 无空闲缓冲区或旧锁存快照尚未消费就到新一拍，锁存故障；收到首帧以后缺帧即故障，不继续重放旧命令。

### 执行职责

| 执行单元 | 首版职责 | 约束 |
| --- | --- | --- |
| Sync0 锁存快路径 | 固定完整快照、记录序号和测量标记 | 无日志、整块复制、协议解析、CAN 发送或 FreeRTOS API |
| PDI 中断 | 保留 SSC SM2 读取和同步统计，应用回调只暂存 RxPDO | 从 AL 事件中屏蔽 Sync 位，避免与独立 Sync IRQ 重复分派 SSC 处理 |
| 1 ms SSC 定时中断 | 更新时间和待处理计数 | 不直接执行 SSC 看门狗 |
| 唯一业务任务 `ecat-can` | `Sync0_Isr()`、`ECAT_CheckTimer()`、`MainLoop()`、SDO、电机状态、CAN 调度、TxPDO 构建与写入 | SSC Sync 与看门狗串行；SDO 与电机不跨任务共享可变业务对象 |
| 50 us 定时中断 | 唤醒任务；周期故障时设置 TX 禁止并取消硬件排队请求 | 不解析命令，不修改电机/SSC 对象；任务卡住时仍能禁止后续 TX |
| CAN 中断 | 接收队列、发送完成和 LED 活动 | 不直接修改电机状态；临界区只屏蔽相关 CAN IRQ |

首版没有拆成互相直接读写对象的 EtherCAT/电机双任务，也没有新增日志任务。这样避免为 RTOS 引入 SDO 与电机状态并发修改；将来拆分前须先建立受控请求接口。

当前 CAN 的 50 us 调度检查和 100 us 响应间隔不直接等同于 Sync0 周期。是否保留现有检查方式，或改用定时器与 CAN 完成事件推进，应在测量 CPU 占用和响应上界后决定；不为了加入 RTOS 强制每个 Sync0 发送一轮 CAN。

## 实时系统接入与中断约束

已补齐 SDK 1.12.1 配套 FreeRTOS V10.5.1 内核及 GCC HPM RISC-V 移植，不升级整个 SDK。固定提交为 `12bd92495abeed7f0a908c589e60974267c0506b`，38 个文件逐字节核对上游，仅两个文档改为中文文件名；本地摘要见 [freertos.lock.json](../../tools/cfg/freertos.lock.json)。摘要是本地校验记录，不是厂商签名。HPM 对应源码包含专用启动、中断和临界区处理，不能用通用移植文件直接替换。[HPM FreeRTOS 构建入口](https://raw.githubusercontent.com/hpmicro/hpm_sdk/v1.12.1/middleware/FreeRTOS/CMakeLists.txt)

当前静态分配一个 2048 字任务栈和内核 Idle 任务；RTOS Tick 为 1 ms，Tickless 和动态内核分配关闭。SSC 邮箱仍沿用原有 C 堆分配，不宣称整个固件无动态内存。内核临界区启用优先级屏蔽，边界为 3，Sync0 为 5、PDI 为 4，均禁止调用 RTOS API；CAN 为 2，50 us 唤醒定时器为 1。

| 资源 | 首版用途 |
| --- | --- |
| MCHTMR | FreeRTOS 1 ms Tick，24 MHz 配置 |
| GPTMR0 通道 0 | SSC 独立 1 ms 时间源，只累计事件 |
| GPTMR1 通道 0 | 1 MHz 自由运行本地时钟，32 位自然回绕，供截止和 CAN 调度使用 |
| GPTMR2 通道 0 | 50 us 业务唤醒及独立周期故障门控 |
| GPTMR3 通道 1 | 原板级 1 ms LED/毫秒计时回调，不再修改电机业务状态 |

GPTMR1 的板级通用 FreeRTOS 示例宏和 GPTMR2 的通用 BLDC 示例宏并未在本应用启用，后续不能直接复用。快速锁存、故障置位和时间读取位于 ILM，三缓冲位于 DLM；快路径固定使用 `-O2` 级别函数优化，包括 Debug 构建，便于避免 Debug 下整块业务单步的误解。本地 1 us 分辨率时钟用于截止，不足以单独验收 1 us 抖动。

后续持续验证约束如下：

- 优先静态分配任务、队列和缓冲区，初期关闭 Tickless，测量各任务及中断栈的占用。
- 完成浮点上下文、栈对齐、启动和中断嵌套检查；先建立任务与共享对象，再开放依赖它们的业务中断。
- 评估 HPM 的优先级屏蔽配置，使锁存快路径不被普通 RTOS 临界区屏蔽。高于系统调用优先级边界的中断不得调用 FreeRTOS API，通过较低优先级延后中断交接。[HPM 临界区与 ISR 约束](https://raw.githubusercontent.com/hpmicro/hpm_sdk/v1.12.1/middleware/FreeRTOS/Source/portable/GCC/RISC-V/portmacro.h)
- 清点并移除或严格限制长时间全局关中断；仅调整 PLIC 优先级无法绕过全局屏蔽。
- 审核 `DISABLE_ESC_INT()`、`ENABLE_ESC_INT()` 及 SSC 的 1 ms 看门狗并发关系，不能为了加快锁存破坏 SSC 状态一致性。
- 初期保留 SSC 独立 1 ms 时间源，不将 Sync0 当作 RTOS Tick 或所有超时的唯一时间源。
- 统一核对 GPTMR0、板级回调 GPTMR3、RTOS Tick 和潜在 CAN 子时隙定时器，避免资源及中断处理函数冲突。
- 根据测量结果确定快路径代码和数据的内存位置，检查 Flash XIP、缓存、总线竞争和 DMA 对最坏延迟的影响；运行期间禁止干扰实时路径的 Flash 擦写。

## 故障处理与兼容边界

- Sync0 丢失、PDO 不再更新、退出 OP、任务超期、CAN Bus-off 和反馈超时应分别检测，不能仅凭仍有 Sync0 脉冲认定主站在线。
- 独立本地时间源负责失步和命令新鲜度监视，避免 Sync0 停止后超时检查也停止。
- 当前采用严格缺帧策略：首个有效周期帧后再次缺帧即故障，不由原命令租约延长流水线；租约仍作为额外保护。
- 停止请求保持优先，不因序号重复、目标非法或队列过载而被普通命令覆盖；异常恢复后不得自动重放故障前的使能命令。
- 保留并重新回归现有租约、反馈超时、总线预算和停止逻辑；中止软件排队不代表已经上总线的帧被撤销，也不代表电机立即物理停止。
- 默认保持现有 PDO 字节布局和 C/C++ 接口兼容。若需要新增诊断对象或改变协议，单独明确版本与主站兼容策略。
- 周期故障复用现有 `BoardStatus` 的无效 PDO 位 `0x40`，详细原因保存在 `g_dcu_cycle_diagnostics`，本轮不新增 OD 对象或修改接口版本。仅供调试读取，不能在运行中修改诊断结构。
- SAFEOP/OP 拒绝 SII 写请求和 Flash 刷新；PREOP/INIT 恢复后处理之前延迟的脏页。初始化 Flash 操作仍发生在实时运行之前。
- 软件禁止 TX、取消排队、断言停机均不等于物理急停；已经上总线的帧和电机保持的目标不保证被撤销。任务定时器也受全局中断关闭和硬故障影响，独立硬件安全链仍须保留。
- 如调整 ESI 或 SII，须恢复所需生成与一致性校验，保留板卡 Alias、Serial 和 EEPROM 数据；不能只改 XML 就认为所有交付物已同步。
- 当前 SDO 维护模式和生产 PDO 控制模式的权限边界需要单独核对，不能以加入 RTOS 为由绕过已有安全约束。

### 主站参考留档

参考根为 `/home/zkbot/work/deploy/new/x2_deploy/src/module/driver_module/`。本轮只读核对：`cfg/driver_dcu_hpm.yaml` 当前为 `cycle_time_us=2000`、`control_period_ms=2`、`enable_dc=true`；`dcu/transport/igh_transport.cc` 配置 `0x0300` 和零 Sync0 Shift；`igh_cycle.hpp` 每周期依次提供应用时间、接收处理、同步参考/从站时钟并发送。解析器允许 1–10 ms，范围大于本从站首版允许的 1–5 ms。

`module/driver_execution.cc` 在周期开始接收上一交易，周期后段发送本交易，起点按当前时间建立，未显式对齐 DC 网格。后续区分“下一帧携带反馈”与“下一次主站控制计算已拿到反馈”；主站消费可能另有一拍，必须按实际收发窗口确认。主站反馈时间戳也需计入传输和消费等待，不能只扣从站发布时的 `FeedbackAgeMs`。这些是下一阶段接口工作，不作为本轮从站软件推进的阻塞条件。

板上测量同时观察 Sync0 硬件参考和锁存标记，校准标记本身带来的偏移，记录测试周期、PDO 大小、总线负载、任务负载、时钟、内存布局、样本量和测量分辨率。覆盖最短支持周期及四路 CAN 压力、邮箱访问和任务切换，不能只验收空载或平均耗时。
